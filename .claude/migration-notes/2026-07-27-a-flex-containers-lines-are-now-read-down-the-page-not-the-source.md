# A flex container's lines are now read down the page, not down the source order

**Landed:** 2026-07-27 (29cc6775) — Read a flex container down the page rather than down the source (#456)
**Doc section:** docs/html-css-support.md § [Page Breaks](../../docs/html-css-support.md#page-breaks)
**Verified against v0.9.6:** the note as originally written described a bug in the line-relocation pass added by the fragment-emission rewrite (`4fd44118`, 2026-07-26) — that pass, and the whole notion of a flex line being "moved" for pagination, did not exist yet at `v0.9.6`. Checked directly: `git show v0.9.6:src/PeachPDF/Html/Core/Dom/CssLayoutEngineFlex.cs` contains no `Page`/`Break` identifier anywhere except `SuppressWordPageBreaks` (used only to keep a page-break decision from sticking during an item's provisional measurement layout, not to move anything) — confirmed by `git grep -n "Page\|Break" v0.9.6:src/PeachPDF/Html/Core/Dom/CssLayoutEngineFlex.cs`. Empirically reproduced against a `v0.9.6` worktree: `break-before`/`break-after: page` declared on a flex item does not relocate its line at all — it instead leaks into the generic block-level forced-break check that every item's provisional measurement pass runs (`CssBox.PerformLayoutImp`'s `previousSiblingForBreak` handling), producing an incoherent side effect (a spurious extra blank page and an unrelated gap pushing later items down) rather than a line-level break of any kind, identically for both properties.

The pass that moves a flex line for pagination did not exist at all before this rewrite: a flex container's lines were positioned purely by the flex algorithm (`AssignLocations`), which has no concept of a page boundary, a line order down the page, or a break value between two lines — `flex-wrap: wrap-reverse`'s lines were simply never relocated, chained, or read in any page-relative order. The pass now reads the container's lines down the page rather than assuming source order ran down the page: under `flex-wrap: wrap-reverse` a relocated line no longer leaves the line physically below it behind or gets drawn over the top of it, and a break value between two lines is now paired with the line on the correct side of the boundary. In a wrapping `flex-direction: column` container, a `break-before`/`break-after` between two lines is inert, since two side-by-side lines share one range down the page with no page boundary between them for such a value to act on — see [the column-flex migration note](2026-07-30-column-flex-items-now-have-break-points-among-themselves.md) for the item-level break points that a column container's lines *do* have, and for how two side-by-side lines were made independent of each other. See [Forward compatibility](#forward-compatibility).
