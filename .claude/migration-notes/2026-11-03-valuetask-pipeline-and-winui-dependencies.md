# The load/layout/paint pipeline returns `ValueTask`, and `PeachBrackets.WinUI` no longer pulls in the whole Windows App SDK

**`Task` became `ValueTask` in the pipeline.** Before, `HtmlDocument.LoadAsync`, `CreateAsync`, `LayoutAsync`, `PaintPageAsync`, `PaintPageRegionAsync` and every update and edit method (`SetPointerStateAsync`, `ReplaceTextAsync`, ...), `StyleSheet.ParseAsync`/`AddAsync`, and on `PeachDrawing.Core.RenderContext` `AddFontFromBytes`, `AddFontFamilyFromUrl`, `AddLocalFontFamily` and the virtual `GetResourceStream` (plus the `AddFont` of the Win2D, Skia, PDF, raster and SVG contexts and the protected `AddFontFromStream`/`AddLocalFont` they override) returned `Task` / `Task<T>`. Now they return `ValueTask` / `ValueTask<T>`. `await` is unchanged; code that stores the result, passes it to `Task.WhenAll` or `Assert.ThrowsAsync`, or overrides `GetResourceStream` has to follow (`.AsTask()` for the first two). A render context that overrides `GetResourceStream` returns `ValueTask<RNetworkResponse?>`; one that answers from memory can return `default` or `new ValueTask<...>(result)` without allocating. `PdfGenerator` and `RNetworkLoader` (the public network-loader base class PeachPDF users derive from) are unchanged.

**New:** `HtmlDocumentOptions.SynchronousOnly` with `HtmlDocument.Load`, `Layout` and `PaintPage` (no waiting; `InvalidOperationException` naming the resource if the document tries to fetch something that is not already available), `HtmlDocument.GetContentHeight(pageIndex)`, `FontSet.Version`/`AddedFamilyNames` and the `fontSet` argument of `Win2dRenderContext` and `SkiaRenderContext`.

**`PeachBrackets.WinUI` dependencies.** Before, the package depended on `Microsoft.WindowsAppSDK` 2.5.1, so every app that referenced it received the AI, ML, Search and Widgets components (over 100 MB of ONNX Runtime and DirectML) whether or not it used them. Now it depends on `Microsoft.WindowsAppSDK.WinUI` 2.3.9, `.Foundation` 2.3.12, `.InteractiveExperiences` 2.1.9 and `.Base` 2.0.4 only. An app that relied on the package to supply the Windows App SDK runtime (`Microsoft.WindowsAppSDK.Runtime`, `.DWrite`, or the whole `Microsoft.WindowsAppSDK`) has to reference it itself.
