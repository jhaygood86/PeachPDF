# line-height as a length is inherited as a length

- **Before:** `<div style="line-height:1.5em">` (and `%`, `ex`, `ch`, `calc()`) was inherited as the text `1.5em` and re-resolved against every descendant's own font size, so an `<h2>` with a bigger font in it got a taller line than the 1.5em the div declared; `calc(1lh + 8px)` added its 8px again for each generation; a negative `line-height` was applied (lines of zero or negative height, paragraphs on top of each other); `<input>`, `<select>` and `<textarea>` took the line height of the container around them.
- **Now:** the length is worked out once, where it is declared, and descendants inherit that length (a number is still inherited as a number); a negative `line-height` is invalid and ignored; form controls use `line-height: normal`. A top-aligned `inline-block` holding text sits on the top of the line box instead of ~0.1pt above it.
- **Also new:** `line-height-step`, `block-step`, `text-box-trim`/`text-box-edge`/`text-box`, line room for `text-emphasis` marks (a line with an emphasis mark can be taller than before), emphasis marks in vertical text, `text-combine-upright` composition and the `text-decoration-skip` values. `text-combine-upright` is now inherited, as the specification says.
