# Default block margins follow the HTML Standard

**Before.** The user-agent style sheet carried the margins of the HTML 4 sample sheet: `p`, `blockquote`, `ul`, `ol`, `dl` and `menu` had `1.12em` above and below, `h2` to `h6` had `0.75em`, `0.83em`, `1.12em`, `1.5em` and `1.67em`, `h6` was `0.75em` tall text, `fieldset` and `form` had `1.12em` where a browser gives none, `pre` had `15px` above and nothing below, `figure` had none, and only an `ol`/`ul` nested in another `ol`/`ul` lost its block margin.

**Now.** The HTML Standard's rendering section (flow content, sections and headings, lists): `1em` for `p`, `blockquote`, `figure`, `pre`, `ul`, `ol`, `dl`, `menu`; `0.67em`, `0.83em`, `1em`, `1.33em`, `1.67em`, `2.33em` for `h1` to `h6` (the same `h6` text is now `0.67em`, as the standard has it); none for `fieldset` and `form`; `figure` has `40px` on each side; and any of `dir`, `dl`, `menu`, `ol`, `ul` inside another has no block margin. These are Chrome's figures to 0.1px at a 14px font size. A document that relies on the default margins gets different space between its blocks, and a different page count where that adds up; one that sets its own margins is unchanged. A `<pre>` keeps the sheet's own 10pt text.

**Checked.** `git show v0.9.26:src/engine/PeachBrackets/Html/Core/CssDefaults.cs` has `h4, p, blockquote, ul, fieldset, form, ol, dl, dir, menu { margin: 1.12em 0 }`, `h2 { margin: .75em 0 }`, `h3 { margin: .83em 0 }`, `h5 { margin: 1.5em 0 }`, `h6 { font-size: .75em; margin: 1.67em 0 }`, `pre { margin-top: 15px }` and the nesting rule for `ol`/`ul` only.
