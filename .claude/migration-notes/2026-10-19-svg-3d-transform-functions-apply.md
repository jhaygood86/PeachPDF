# 3D transform functions on an SVG element now apply

Before: `translate3d()`, `translateZ()`, `scale3d()`, `scaleZ()`, `rotate3d()`, `rotateX()`, `rotateY()`, `matrix3d()` and `perspective()` in the `transform` of an SVG element did nothing, and the other functions of the list still applied; `perspective`, `perspective-origin`, `transform-style` and `backface-visibility` were ignored on SVG elements.

Now: the element is carried through the 4x4 matrix (about `transform-origin`, whose third value is read as a z offset), seen through its container's `perspective`, hidden when turned away with `backface-visibility: hidden`, and the planes of a `transform-style: preserve-3d` container share one space. A document that relied on the old behaviour (a stray `rotateX()` that did nothing) now draws it turned. A list with a 3D function is ignored whole in `gradientTransform` and `patternTransform`, where before only the 3D function was skipped. In HTML, a `perspective` or `perspective()` distance under one CSS pixel is now one pixel, and a weak perspective, or a `preserve-3d` context of tilted planes that do not pierce each other, is vector artwork instead of a bitmap (selectable text, sharp at any zoom, and no longer rejected by PDF/A-1 for its bitmap).
