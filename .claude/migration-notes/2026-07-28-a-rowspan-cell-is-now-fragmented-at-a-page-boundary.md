# A `rowspan` cell is now fragmented at a page boundary instead of stretched across it

**Landed:** 2026-07-28 (f9d19a03) — Fragment a rowspan cell at the boundary instead of stretching it across (#523)
**Doc section:** docs/html-css-support.md § [Page Breaks](../../docs/html-css-support.md#page-breaks)
**Verified against v0.9.6:** the core claim holds, but the note originally described one defect that was never in a release. `git show v0.9.6:src/PeachPDF/Html/Core/Dom/CssLayoutEngineTable.cs`'s `LayoutBodyRow` is a single, non-resumable pass with no rowspan-aware page-break handling at all, so a spanning cell whose span crossed a page boundary was laid out as one uninterrupted box — reproduced directly against the `v0.9.6` tag (a `rowspan="2"` cell straddling a 200pt page boundary comes out as one `CssBox` running from `Location.Y=149` to `ActualBottom=281`, the boundary at 200 cutting straight through it). The "`vertical-align` applied twice" clause did not, though: v0.9.6's `LayoutBodyRow` calls `CssLayoutEngine.ApplyCellVerticalAlignment` on a spanning cell exactly once (there was no resumable multi-pass row loop to invoke it a second time) — that specific double-apply defect was introduced and fixed entirely within the unreleased rewrite between v0.9.6 and this commit ([f9d19a03](https://github.com/jhaygood86/PeachPDF/commit/f9d19a039ac5aa86defa07bf047394b0e49b2813)'s own message: "Also fixes a spanning cell being vertically aligned twice where a `CssSpacingBox` exists"), so it has been dropped from the before-paragraph below.

A row that ends a `rowspan` used to be left wherever it fell — v0.9.6 had no dedicated handling for it, so where a page boundary crossed the span, the row was laid out normally and the spanning cell was drawn as a single box cut through by the page edge. Such a row is now carried onto the next page like any other, and the spanning cell is split at the boundary rather than stretched across it — so a document with a `rowspan` at a page break gains a moved row, and possibly a page. On a split cell, the `vertical-align` now resolves against the fragment on the page the cell began on. See [Forward compatibility](#forward-compatibility).
