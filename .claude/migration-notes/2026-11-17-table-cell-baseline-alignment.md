# Table cell baseline alignment

**Before / now**, each a change a document author can see:

- **A table cell's `vertical-align: baseline`** used to be a no-op, aligned as if it were `top`. It
  now does what CSS 2.1 §17.5.3 / css-tables-3 §7.8 ask for: the cell's own baseline (its first
  in-flow line box's baseline, found through any nested blocks, plus its own top padding and
  border) lines up with the row's baseline - the largest such distance among the row's own
  `rowSpan == 1` baseline cells. A cell with no in-flow line box (an empty cell, or one holding only
  floated, absolutely positioned or otherwise out-of-flow content) is unaffected by this: it keeps
  its own natural position, since it has no content of its own to shift.
- **A row of cells with different top padding, font size, or an image beside text** can now be
  visibly taller than before: when the tallest cell's baseline sits far enough below the others',
  the row grows to give the shifted cells room, rather than clipping or overlapping them.
- **This also affects a cell whose `vertical-align` was never set at all.** `vertical-align`'s CSS
  initial value is `baseline`; a real `<td>`/`<th>` still defaults to `middle` (inherited from its
  `<tr>`/`<tfoot>` through the user-agent stylesheet), unchanged. But an *anonymous* table-cell box
  - one generated by the CSS table-model fixup rules, or a `display: table-cell` element that is
    not itself a `<td>`/`<th>` (so no UA rule gives it `middle`) - keeps the CSS initial value and so
    now baseline-aligns by default, where it previously (incorrectly) top-aligned.

See [Tables](../../docs/html-css-support.md#tables).
