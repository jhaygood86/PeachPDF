# A selector PeachPDF cannot match no longer drops its whole rule

**Landed:** 2026-07-27 (7a4efb1a) — Register the selectors PeachPDF cannot match instead of dropping their rules
**Doc section:** docs/html-css-support.md § [Recognized but unmatchable selectors](../../docs/html-css-support.md#recognized-but-unmatchable-selectors)
**Verified against v0.9.6:** this note was not present in the `v0.9.6` tag's docs. The original text overstated the scope of the change: `src/PeachPDF/CSS/Factories/PseudoClassSelectorFactory.cs` at v0.9.6 already built a dictionary of roughly two dozen recognized-but-unmatchable pseudo-class names (`:hover`, `:focus`, `:visited`, `:active`, `:checked`, `:disabled`, `:enabled`, `:valid`, `:invalid`, `:required`, `:read-only`, `:read-write`, `:in-range`, `:out-of-range`, `:optional`, `:target`, `:default`, `:indeterminate`, `:placeholder-shown`, `:focus-visible`, `:focus-within`, plus `:empty`/`:any-link`/`:scope` — see the sibling note on those three) that parsed without invalidating the selector list they appeared in — confirmed by commit `7a4efb1a`'s own new `UnmatchableSelectors.cs`, whose doc comment says the state-based set is one "PeachPDF has always accepted". Only a name **outside** that v0.9.6 dictionary hit `PseudoClassSelectorFactory.Create` returning `null`, which set `SelectorConstructor._valid = false` (`src/PeachPDF/CSS/Parser/SelectorConstructor.cs`, `OnPseudoClass`) and made `StylesheetParser.ParseSelector` return `null` for the *entire* selector text (`src/PeachPDF/CSS/Parser/StylesheetParser.cs`), dropping the whole rule — genuinely true at v0.9.6 only for the selectors 7a4efb1a actually added or fixed. Narrowed below.

Earlier versions already recognized (parsed, matched nothing, and left the rest of a comma-separated selector list intact) that core set of roughly two dozen state-based pseudo-classes — `:hover`, `:focus`, `:focus-visible`, `:focus-within`, `:visited`, `:active`, `:target`, `:enabled`, `:disabled`, `:default`, `:checked`, `:indeterminate`, `:placeholder-shown`, `:valid`, `:invalid`, `:required`, `:read-only`, `:read-write`, `:in-range`, `:out-of-range`, `:optional` — plus `:empty`, `:any-link` and `:scope` (see the sibling note, [`:empty`, `:any-link`, and `:scope` are now evaluated](2026-07-27-empty-any-link-and-scope-are-now-evaluated.md)). Everything *else* in the list above genuinely dropped its whole rule at v0.9.6: the Shadow DOM set (`:host`, `:host()`, `:host-context()`, `:defined`, `:state()`, `::part()`, `::slotted()`), every pseudo-element beyond `::before`/`::after`/`::marker`/`::first-letter`/`::first-line`, any vendor-prefixed name (there was no wildcard vendor-extension acceptance yet), the newer state pseudo-classes (`:open`, `:popover-open`, `:modal`, `:fullscreen`, `:picture-in-picture`, the media-playback set, `:user-invalid`, `:autofill`, `:target-within`, `:local-link`, `:current`, `:past`, `:future`), and even a differently-cased spelling of an already-recognized name (`:HOVER`, `::Before`) — the old lookup was case-sensitive. A rule that named any of *those* alongside a selector PeachPDF does match previously applied to nothing at all; it now applies to the matching half — so a document that (knowingly or not) depended on such a rule being discarded will render differently. See [Forward compatibility](#forward-compatibility).
