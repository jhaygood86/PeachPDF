# A table cell no longer moves its content down for trailing space

In a table cell that centres its content (the default) or aligns it to the bottom, a line that holds only a `<br/>`, the margin below the last block and the leading under the last line used to count as free room, so the content sat lower than in a browser: HTML e-mail that ends a cell's paragraph with `<br/>`, and any cell whose last block has a bottom margin (the default for `<p>`), had its text pushed down by half of that space. The content now ends where it ends, so a cell as tall as its content leaves it at the top, as in Chrome; in a row made taller by another cell the content is still centred, now including that trailing space. The row and table heights do not change, only where the content sits in the cell. A table that depended on the old offset (for example a header text that was nudged down by a trailing `<br/>`) moves up by that amount.
