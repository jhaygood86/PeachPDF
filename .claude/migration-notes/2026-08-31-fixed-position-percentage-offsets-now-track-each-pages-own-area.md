# `position: fixed` percentage offsets now track each page's own area (mixed page sizes)

**Landed:** 2026-08-31 — Resolve position:fixed percentage left/top per page (Layer E, mixed page orientation/size support)
**Doc section:** docs/html-css-support.md § Per-page margin variation ("Known boundaries of per-page margins")
**Verified against v0.9.15:** `git show v0.9.15:docs/html-css-support.md` confirms the prior wording verbatim ("the `position: fixed` containing block... resolves against the configured base page area" / "keep positioning against the base page box on margin-overridden pages") — confirmed genuine behavior change since 0.9.15, in scope for the next release notes.

A `position: fixed` box's percentage `left`/`top` previously always resolved against the document's single, globally-configured page area, computed once regardless of which page the box's repeated copy was being drawn on. It now resolves against each page's own area (CSS2.1 §10.1 / CSS Position 3) whenever the document mixes physical page sizes via a named or pseudo-selector `@page` rule's own `size` — a fixed banner positioned with `left: 50%` now sits at the horizontal center of *each* page's own width, rather than the base page's width repeated identically everywhere. An absolute-length offset (`left: 20pt`) is unaffected, since it never depended on the page's size to begin with. A document with no `@page size` overrides at all sees no change (the new per-page resolution only runs when the document actually mixes page sizes). A fixed box's own percentage *width*/*height* (as opposed to its position) is a separate, not-yet-landed piece.
