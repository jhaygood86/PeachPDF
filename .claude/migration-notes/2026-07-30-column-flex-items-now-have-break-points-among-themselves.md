# A column-direction flex container's items now have break points among themselves

**Landed:** 2026-07-30 (52a43f44) — Fix align-content:normal stretch and column flex break points between items (#565)
**Doc section:** docs/html-css-support.md § [Page Breaks](../../docs/html-css-support.md#page-breaks)
**Verified against v0.9.6:** the note as originally written implied a "every item of every line moves together" fallback existed at `v0.9.6` for `break-inside: avoid`/monolithic content on a column-direction item. No such mechanism existed at all. Empirically reproduced against a `v0.9.6` worktree: a `flex-direction: column; flex-wrap: wrap` container with two side-by-side lines, where the second item of the first line carries `break-inside: avoid` and is positioned to straddle a page boundary, renders with **every** item of **both** lines left exactly where the flex algorithm put them — none relocated, the `avoid` item included. This matches the row-direction finding in the [`break-avoid` migration note](2026-07-28-break-avoid-between-flex-lines-or-grid-rows-is-now-honored.md): `git grep -n "Page\|Break" v0.9.6:src/PeachPDF/Html/Core/Dom/CssLayoutEngineFlex.cs` shows no break-value handling exists in the flex engine for any `flex-direction`, so there was no "move everything together" behavior to fall back to — there was no line- or item-relocation behavior of any kind.

A column container's *items* previously had no break points among themselves at all, and nothing else stood in for that: a `break-before`/`break-after` between two items of the same line did nothing, and `break-inside: avoid`/monolithic content on one item did nothing either — the item was simply left straddling the boundary, and every other item in the container (same line or a different one) was completely unaffected by it, since none of them had any page-break awareness in the first place. Both break-before/break-after and break-inside/monolithic content are now honored at item granularity, and two side-by-side lines relocate independently of each other — an item's own break value in one line never displaces the other. A document that relied on the flex container simply ignoring these values inside a column-direction line now sees those items paginate for the first time.
