# Multi-column containers holding only text now columnize

**Before:** A container with `columns` or `column-count` whose content was only text, with no block-level child of its own, was laid out as one ordinary inline flow across the container's full width. The v0.9.22 support matrix documented this as a limitation. Text beside a float in such a container was not divided either: the float shortened its lines, and the columns were unaffected.

**Now:** Text placed directly in a multi-column container is divided into columns, like any other column content. Text beside a float is divided too, and the float sits in the column where it appears. Text under a vertical writing mode keeps its previous layout and stays in single-column flow. A multi-column scroll container (`overflow` other than `visible`, with a constrained height) that holds only text is laid out in its columns, and can break across a page boundary, as a multi-column scroll container with block-level children already could.

**Why:** The parser wraps an inline-only run in an anonymous block when its parent is multi-column. That gives the columns engine the block-level shape it fragments; widening the dispatch instead drops words. A float is kept out of the wrapped run, so the columns engine places it in its column and narrows the lines beside it. A multi-column box still dispatches to the columns engine, and the columns engine needs the page's fragmentainer, so such a box is not suppressed from breaking.
