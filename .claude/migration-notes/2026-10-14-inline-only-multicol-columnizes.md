# Multi-column containers holding only text now columnize

**Before:** A container with `columns` or `column-count` whose content was only text, with no block-level child of its own, was laid out as one ordinary inline flow across the container's full width. The v0.9.22 support matrix documented this as a limitation. Text beside a float in such a container was not divided either: the float shortened its lines, and the columns were unaffected. A scroll container (`overflow: hidden` or `scroll` with a constrained height) that established columns and held block-level children could also be split across a page boundary, because monolithic content was not suppressed when the box dispatched to the columns engine.

**Now:** Text placed directly in a multi-column container is divided into columns, like any other column content. Text beside a float is divided too: the float sits in its column and shortens the lines beside it. A monolithic multi-column scroll container with block-level children stays on one page, as an inline-only one already did. Text under a vertical writing mode keeps its previous layout and stays in single-column flow.

**Why:** The parser now wraps an inline-only run in an anonymous block when its parent is multi-column. That gives the columns engine the block-level shape it fragments; widening the dispatch instead drops words. A float is kept out of the wrapped run, so the columns engine lays it out in its own column. The monolithic check now asks only whether the box is monolithic, because laying out columns inside a box is internal to that box.
