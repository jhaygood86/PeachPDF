# A named/pseudo `@page` rule's `size` now produces a real, independent PDF page

**Landed:** 2026-08-31 — Read each page's own resolved sheet size in PdfGenerator.AddPdfPages (Layer G, mixed page orientation/size support)
**Doc section:** docs/html-css-support.md § `size` property
**Verified against v0.9.15:** `git show v0.9.15:docs/html-css-support.md` confirms the prior wording verbatim ("`size` is honored on the base `@page` rule only... every sheet in one document has the same physical dimensions") — confirmed genuine behavior change since 0.9.15, in scope for the next release notes.

Previously, `size` declared inside `@page :first`/`:left`/`:right` or a named `@page <name>` rule was silently ignored — every page in a document always shared the base rule's physical dimensions. `size` on these rules now takes effect: a page selected by such a rule gets its own genuinely independent physical PDF page (its own `/MediaBox`), letting one document mix portrait and landscape (or otherwise differently-sized) pages, e.g. via `@page landscape-table { size: A4 landscape; }` combined with `page: landscape-table` on an element. Vertical pagination already adapts to a differently-sized page's own content band. Horizontal content reflow to that page's own width is not yet implemented (tracked as part of the existing, broader #202 gap) — content on such a page still wraps at the document's base measure, so a wide table intended to benefit from the extra landscape width needs an explicit width (e.g. a percentage or fixed length) rather than relying on auto-reflow, until that follow-on work lands.
