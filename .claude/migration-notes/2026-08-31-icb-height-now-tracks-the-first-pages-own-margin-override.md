# The initial containing block's height now tracks the first page's own margin override

**Landed:** 2026-08-31 — Resolve per-page ICB/viewport-unit pinning rationale (Layer F, mixed page orientation/size support)
**Doc section:** docs/html-css-support.md § [Per-page margin variation](../../docs/html-css-support.md#per-page-margin-variation) ("Known boundaries of per-page margins")
**Verified against v0.9.15:** `git show v0.9.15:docs/html-css-support.md` confirms the prior wording verbatim ("The initial containing block uses the base page area... resolves against the configured base page area, not the first page's `:first`-overridden area") — confirmed genuine behavior change since 0.9.15, in scope for the next release notes.

The initial containing block's *height* (and therefore a `height: 100%` root-relative percentage, or any percentage chain that bottoms out at the true root rather than a sized ancestor) previously always resolved against the document's base configured page size, even when `@page :first` overrode the first page's own margins. It now resolves against the first page's own resolved content band, per css-page-3 §3 ("the edges of the page area on the first page establish the rectangle that is the initial containing block of the document"). A document with `@page :first { margin: 0 }` and root-relative percentage-height content will now see that content size to the full first-page sheet rather than the narrower base band. Only the height dimension changed — the ICB's *width*, viewport units, and the `position: fixed` containing block still resolve against the base page area (issue #201's remaining, still-open width scope; viewport units and `position: fixed` are unaffected by this note).
