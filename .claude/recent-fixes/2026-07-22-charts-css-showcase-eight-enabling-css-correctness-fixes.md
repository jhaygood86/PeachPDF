# Charts.css showcase + eight enabling CSS-correctness fixes

_Landed 2026-07-22._

**Charts.css showcase + eight enabling CSS-correctness fixes** (the capstone of the Charts.css work): a `charts_css` showcase (`src/PeachPDF.TestHarness/Program.cs`, category "Charts & Data Viz") embeds the **full official Charts.css v1.2.0 stylesheet verbatim** (MIT header intact, copied to `src/PeachPDF.TestHarness/charts.css` and read at runtime) and renders column, bar, area, line, pie, a multi-series column, and the documented customizations (extruded 3D bars via a stack of offset `box-shadow`s, a `skewY` tilt, and shadowed bars via a white panel with inset+outset `box-shadow`) — all verified in **both** PDFium and MuPDF. Embedding the *whole* sheet surfaced eight real, general engine gaps, each fixed (no charts-specific hacks):
1. **`@property` `<ratio>` syntax matcher** — `AspectRatioGrammar.TryParseRatio` (a pure `<ratio>`, no `auto`, sharing the ratio core with `TryParse`) + a `case "<ratio>"` in `RegisteredProperty.BaseTypeMatches`. Without it `@property --aspect-ratio { syntax:"<ratio>"; initial-value:auto }` was wrongly accepted (degrade-to-accept), registering the property with `auto`; now the invalid rule drops and `var(--aspect-ratio, 21/9)` falls back to `21/9` (browser behavior).
2. **flex × `aspect-ratio` definite cross size** (`CssLayoutEngineFlex.Layout`): `hasDefiniteHeight = hasExplicitHeight || CssLayoutEngine.TryGetAspectRatioHeight(_flexBox, out _)` (made `internal`), used for the pre-apply / `containerCrossSize` / `mainSizeIndefinite` / empty-flex / Phase-10 gates — so a row-flex `tbody` with `aspect-ratio` and `align-items: stretch` stretches its rows to the ratio height.
3. **`:nth-*(An + B)` whitespace-separated sign** (`SelectorConstructor.ChildFunctionState.OnOffset`): a standalone `+`/`-` `Delim` between `An` and `B` (as in `:nth-of-type(10n + 1)`, which charts.css uses 20×) now sets the offset sign instead of invalidating the selector. Fixes ALL per-series coloring. (Compact `10n+1` was already fine — the sign is part of a signed number token there.)
4. **CSS Color 4 space/slash-alpha `rgb()`/`rgba()`** (`CssValueParser.GetColorByRgb`/`GetColorByRgba` + new `ParseAlphaAtIndex`): `rgb(r g b / a)` / `rgba(r g b / a%)` and `%` alpha now parse (legacy comma form and 3-value space form were already fine). Fixes axis/gridline/legend colors.
5. **`calc()` in `clip-path: polygon()`** (`BasicShapeGrammar.IsLengthPercentage` accepts a calc-family `FunctionToken`; the resolver's per-coordinate `CssValueParser.ParseLength` already evaluates calc) — fixes area/line fills. See the #217 note above.
6. **`calc()` angle in `conic-gradient()`** (`CalcEvaluator` gained an `AngleCalcNode` case → radians; `CssValueParser.TryParseConicAngle` evaluates a single calc() stop-position item as an angle) — fixes pie slices whose every stop is `calc(1turn * <n>)`.
7. **Blockification of out-of-flow boxes** (`DomParser.BlockifyPositionedBox`, called at the end of `CascadeApplyStyles`): `position: absolute`/`fixed` coerces an inline-level computed `display` to its block-level equivalent (CSS 2.1 §9.7 / Display 3 §2.7), so a default-`inline` `::before` with `position:absolute` actually becomes out-of-flow. (Floats are also blockified per spec but left as-is — PeachPDF's float layout already treats them block-like.)
8. **Absolute-positioning layout + sizing** — (a) `CssBox.LayoutOutOfFlowChildren` lays out a flex/table container's out-of-flow children (the flex/table engines deliberately skip them, unlike the block-children loop, so they were never laid out at all); (b) `CssLayoutEngine.PercentageBase` resolves an absolute box's percentage width/height against its **nearest positioned ancestor** (CSS 2.1 §10.1), not `ContainingBlock`, when they differ (a `position:static` parent chain); (c) auto width/height with both insets set fills the containing block (§10.3.7 width, §10.6.4 height). Together these size a Charts.css `td { position:absolute; width:100%; height:100%; inset:0 }` fill (pie/area/line) and its `::before`.

All eight are regression-free (full net8.0 suite green). The area/line rows are authored with `--start`/`--end` so consecutive points connect into sloped fills/lines; the bar `tbody` is given `--aspect-ratio` (its charts.css default is `auto`) so its flex rows distribute a definite height. See `docs/html-css-support.md` (Positioning, clip-path, `@property`, gradient, color rows), and `AbsolutePositioningIntegrationTests`/`AspectRatioLayoutIntegrationTests`/`CalcEvaluatorTests`/`ConicGradientIntegrationTests` + the added cases in `BasicShapeGrammarTests`/`StructuralPseudoClassSelectorTests`/`AspectRatioGrammarTests`/`RegisteredPropertyTests`/`ShorthandResetAndColorParsingTests`. **Accepted gaps from this work** (from the post-change review): (a) the §10.3.7/§10.6.4 auto-size fill resolves percentage insets against the containing block's content-box measure while the separate placement code (`CssBox.PerformLayoutImp`) uses the ancestor's border-box (`ActualWidth`) — so a *percentage* inset (not `inset: 0` / length insets, and not unpadded ancestors — i.e. not the charts case) on a **padded** positioned ancestor can misplace the far edge ([issue #224](https://github.com/jhaygood86/PeachPDF/issues/224)); (b) `BlockifyPositionedBox` covers the inline-level outer displays but not the table-internal display values §9.7 also blockifies (`table-cell` etc.), and `LayoutOutOfFlowChildren`'s table branch is consequently unexercised for an absolute direct child of a `display: table` (anonymous-table wrapping moves it off the table box) ([issue #225](https://github.com/jhaygood86/PeachPDF/issues/225)). Over-constrained fills (insets wider than the CB) clamp to 0 per spec.
