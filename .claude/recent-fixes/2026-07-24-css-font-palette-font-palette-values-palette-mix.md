# CSS `font-palette` + `@font-palette-values` + `palette-mix()`

_Landed 2026-07-24._

**CSS `font-palette` + `@font-palette-values` + `palette-mix()`** ([CSS Fonts 4](https://www.w3.org/TR/css-fonts-4/#font-palette-values)): selecting which CPAL palette a COLR/CPAL color font paints with. Previously `ColorGlyphPainter.ResolveColor` hardcoded CPAL palette 0; now the resolved palette (index + per-entry overrides) threads down as a paint property alongside the text color. **Resolution is entirely CSS-side**, so the backend only looks up an index and applies overrides. Pieces:
1. **CPAL v1 flags** (`Fonts/OpenType/CpalTable.cs`): the reader now parses the v1 header extension's per-palette type flags and exposes `FirstLightPalette()`/`FirstDarkPalette()` (bit 0 = `USABLE_WITH_LIGHT_BACKGROUND`, bit 1 = dark). v0 fonts report none. `TryGetColor(paletteIndex, …)` already honored the index — only the caller's hardcoded `0` had to change.
2. **CPAL query surface on `RFont`** (`Html/Adapters/RFont.cs`, implemented in `FontAdapter` over `OpenTypeDescriptor.ColorPalette`): `PaletteCount`/`PaletteEntryCount`/`FirstLightPalette()`/`FirstDarkPalette()`/`TryGetPaletteColor(...)`, default-empty so a non-color `RFont` is a no-op. This lets the CSS layer read entry colors — needed for `palette-mix()` (blends per entry) and light/dark resolution.
3. **Threading**: a resolved `RFontPalette` (`Html/Adapters/Entities/`, a palette index + `RColor` overrides) is a new optional trailing param on the `RGraphics.DrawString` chain (mirroring how `color` travels), converted to a backend `XGlyphPalette` in `GraphicsAdapter.DrawString` and consumed by `ColorGlyphPainter` (overrides checked before the CPAL lookup; the COLR `0xFFFF` foreground sentinel still wins over overrides). `null` = default palette 0, so the legacy paint path is byte-identical. The font cache is untouched (palette is paint, not font identity). The ~10 test-only `RGraphics.DrawString` mocks each gained the ignored param.
4. **Layer A**: `font-palette` longhand (inherited, `FontPaletteValueConverter` validating `normal | light | dark | <dashed-ident> | palette-mix()`, authored text preserved for Layer B); the `@font-palette-values` at-rule (`FontPaletteValuesRule`/`IFontPaletteValuesRule` modeled on `@property`, descriptors `font-family`/`base-palette`/`override-colors` stored raw). One shared `PaletteMixGrammar` (`CSS/PaletteMixGrammar.cs`) validates `palette-mix()` for both layers, reusing `ColorInterpolationMethodGrammar` for the `in <space>` prelude (the "one grammar, one parser" rule).
5. **Layer B**: `CssBoxProperties.FontPalette` (the "four places") + a lazy `ActualFontPalette` that calls `FontPaletteResolver.Resolve` against the box's **used** font family (`FontFamily`, the cascade's first-existing family — spec-compliant, matched via `GetFontFaceFamilyName`) and `ActualFont`'s CPAL surface. `RegisteredFontPalette.BuildRegistry` (keyed `(name, family)`) collects the at-rules in `DomParser.GenerateCssTree`. `palette-mix()` resolution blends each CPAL entry via the shared `ColorFunctionExtensions.MixPaletteColors` (the same `Color.Mix` + percentage normalization `color-mix()` uses).
Verified end-to-end in **both** PDFium and MuPDF against a subset of Nabla (a real 7-palette COLR v1 font; `BundledFonts.Nabla`, generated by `assets/fonts/generate_nabla_subset.py`, which also upgrades CPAL to v1 and flags two palettes light/dark). Tests: `FontPaletteRenderingIntegrationTests` (normal/base-palette/light/dark/override-colors/palette-mix/inheritance/family-mismatch, asserting on emitted content-stream colors), `FontPaletteParsingTests`, `PaletteMixGrammarTests`, `RegisteredFontPaletteTests`, `ColrCpalTableTests.Cpal_V1_*`. Showcase: `font_palette`. Docs: `docs/html-css-support.md` (`font-palette` + `@font-palette-values` rows), `docs/license.md` (Nabla OFL). **Accepted gaps:** `font-palette` animation/interpolation (inherent — a static PDF has no timeline; [#292](https://github.com/jhaygood86/PeachPDF/issues/292)); nested `palette-mix()` (operands are limited to `normal | light | dark | <palette-identifier>`; [#291](https://github.com/jhaygood86/PeachPDF/issues/291)); `font-palette` only affects COLR/CPAL-over-`glyf` color fonts (consistent with the existing color-glyph format gap [#287](https://github.com/jhaygood86/PeachPDF/issues/287)).
