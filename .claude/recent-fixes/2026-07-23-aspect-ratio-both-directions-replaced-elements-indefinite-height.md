# `aspect-ratio` both directions + replaced elements + indefinite-% height + min/max clamping

_Landed 2026-07-23._

**`aspect-ratio` both directions + replaced elements + indefinite-% height + min/max clamping** (issue #219, the four deferred gaps from the entry above — all closed except the flex/grid transferred minimum): (1) `AspectRatioGrammar.TryParse` gained an overload exposing `hasAuto` (the 2-arg one delegates), so a replaced element can tell `auto <ratio>` from a bare `<ratio>`. (2) **Height→width** — new `CssLayoutEngine.TryGetAspectRatioWidth` (transpose of `TryGetAspectRatioHeight`; `width = boxSizingHeight * ratio`, a box-sizing-box width the caller adds `ActualBoxSizeIncludedWidth` to), gated on no explicit width + a definite height (new `HasDefiniteHeight` helper: a non-`%` length, or a `%` against a height-calculated CB). Hooked in `GetBoxWidth` **only** in the absolutely-positioned auto-width branch (the shrink-to-fit path), since a normal-flow block's auto inline size is stretch-fit, which wins over the ratio per CSS Box Sizing 4 §5.1 (browser behavior — deliberately NOT "fixed"). (3) **Replaced elements** — `MeasureIntrinsicSize` computes an `effectiveRatio` from the CSS `aspect-ratio` combined with the element's natural (intrinsic) ratio via `ResolveReplacedRatio` (bare `<ratio>` overrides natural; `auto <ratio>` prefers natural, falls back to specified; `auto`/none/zero-term uses natural), and the missing-axis + min/max-height rescale use it; the no-`aspect-ratio` path is byte-identical. (4) **Indefinite % height** — `GetBoxHeight`'s indefinite-`%` branch (a `%` against a non-height-calculated CB) now falls through to the ratio instead of returning null, and `ApplyHeight`'s `isRatioHeight` broadened from `!IsValidLength(box.Height)` to `!isDefiniteHeight` so the ratio-derived height is marked definite in that case too. The ratio-derived width/height is clamped by the existing `min-*`/`max-*` code. See `AspectRatioGrammarTests` (`hasAuto`), `AspectRatioLayoutIntegrationTests` (abspos height→width incl. border-box, normal-block-fills-not-ratio, indefinite-% sizing + descendant, min/max clamps), and `ReplacedElementIntrinsicSizeTests` (bare-ratio override both axes, `auto <ratio>` prefer-natural + fallback-when-no-natural, zero-term fallback, CSS-ratio min-height rescale). **Accepted gap** ([issue #219](https://github.com/jhaygood86/PeachPDF/issues/219), narrowed): the CSS Sizing §5.1 *transferred* automatic-minimum-size for flex/grid items (a `min-*: auto` item's min-content contribution taken through the ratio) is not modeled — a large, edge-case-heavy piece with little value for print; height→width on non-replaced **inline-block/float** boxes (whose width doesn't resolve through `GetBoxWidth`'s shrink-to-fit path) is also not covered.
