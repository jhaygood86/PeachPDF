# Fragment-aware box model: layout now produces an immutable fragment tree, and paint consumes it

_Landed 2026-07-24._

**Fragment-aware box model: layout now produces an immutable fragment tree, and paint consumes it** ([issue #298](https://github.com/jhaygood86/PeachPDF/issues/298), [CSS Fragmentation Level 3 §2](https://www.w3.org/TR/css-break-3/)). PeachPDF had no output data structure for layout at all — `CssBox` was simultaneously the DOM node, the computed-style store, the layout algorithm, the layout *output*, and the paint source, and pagination was emergent rather than produced (layout mutated boxes into one tall strip; `GetPaginationSlots` rediscovered pages geometrically afterwards; `PdfGenerator.AddPdfPages` re-walked the same mutable tree once per page, injecting per-page state by writing `ScrollOffset`/`PageClipOverride` onto the container and resetting a `_hasPainted` latch across the whole tree between pages). Delivered as three staged commits:
1. **Model + builder** (`Html/Core/Fragments/`). Immutable records: `FragmentTree` → `FragmentainerFragment` (one page: slot index, `PageBandGeometry`, `LocalOriginY`, root) → `BoxFragment` (`Lines`/`Words`/`Children`, `IsFirstFragment`/`IsLastFragment` for §6.2's decoration edges, `WholeBoxRect` for whole-box effects, `OriginY`, `IsFixed`) → `LineFragment`/`TextFragment`. A fragment owns geometry and keeps a `CssBox` back-pointer for style. Coordinates are **fragmentainer-local**, which is numerically what paint used to compute as `rect + ScrollOffset` — the arithmetic just moved into the builder. `FragmentTreeBuilder` walks the box tree twice (record each box's first/last fragmentainer, then allocate) sharing one emission rule, with band membership on the painter's own overlap epsilon. `CssProxyBox`'s nested `LayoutSnapshot` was promoted to `Html/Core/Fragments/BoxGeometrySnapshot.cs` — the pre-existing "one box, N positions" precedent — and the builder descends into a proxy's source subtree through it.
2. **Page materialization.** `AddPdfPages`/`HandleLinks` iterate `FragmentTree.Fragmentainers`. `HtmlContainerInt.GetPaginationSlots` and `DomUtils.CollectPrintableContentRanges`(`Into`) are **deleted**; CSS Paged Media 3 §3.2's content-empty-page rule now falls out of the build (a slot no printable fragment landed in never becomes a fragmentainer), with `DomUtils.HasOwnPrintableContent` surviving as the per-box predicate. **Resolving the canvas background moved from paint into layout** (`HtmlContainerInt.ResolveCanvasBackground`, replacing `PdfGenerator.ResolveCanvasBackground`): it is a pure CSS 2.1 §14.2 cascade question, and the page-materialization rule needs `SuppressOwnBackgroundPaint` already set — Acid2 grew 2→3 pages until this moved, because the promoted root background spans the root's whole auto height and made every slot look non-empty. It is also now idempotent across the repeated layout passes ShrinkToFit drives.
3. **Paint.** `PerformPaint(g, fragmentainer)`; `CssBox.Paint`/`PaintImp`/`PaintImpCore`/`PaintWords`/`PaintContentImage`/`PaintColumnRules` and every replaced-element override (`CssBoxImage`/`Object`/`Svg`/`Hr`/`Frame`/`Marker`/`SpacingBox`/`ProxyBox`) take a `BoxFragment`. `ScrollOffset` leaves the content paint path (and with it ~15 sites that had to remember to apply it). `_hasPainted`/`ResetPaint` become a painter-owned `HashSet<BoxFragment>` compared **by reference** (so a rowspan cell shown in each row it spans still paints in each); `CssSpacingBox.PaintImpCore` is deleted since the builder makes that cell a fragment child. `DomUtils.FlattenStackingContext`/`SearchForHoistableDescendants`/`StackingParticipant` walk fragment children (ordering rules untouched, still reading the boxes). Table `PageBreakBottoms` reads `fragment.FragmentainerIndex` instead of re-deriving the slot from an offset; `RenderUtils.ClipGraphicsByOverflow`/`PushAncestorOverflowClips` take `originY`.
**Verified rendering-identical**: all 60 TestHarness showcases rasterize **pixel-identically in both PDFium and MuPDF** against the pre-change build (the one MuPDF byte-level difference reproduces between two runs of the *same* code — it tracks the random font-subset tag). 55/60 PDFs are byte-identical after normalizing only creation date, document `/ID`, and subset tags; the 5 that differ are link-annotation UUIDs/mod dates (`svg`, `tagged_pdf`) and **removed no-op clip push/pop pairs** for boxes that used to be walked on pages they had no content on (`acid2`'s first content stream shrank 6159→2744 bytes, `transform`, `charts_css`). Full net8.0 suite green (5839). Tests: `FragmentTreeBuilderTests`, `FragmentPaintIntegrationTests`, plus `TestSupport/LayoutHarness.cs` + `TestSupport/FragmentPaintHarness.cs` (the shared harnesses the ~24 migrated paint-driving test files now use — they name the *page* to paint rather than the scroll offset that used to select it). Two `GhostTextOnPreviousPageIntegrationTests` fixtures gained a background on their filler: the page the ghost would have appeared on carried no printable content, so it is no longer materialized and there was nothing left to assert against. **Accepted gaps** (each filed): layout is still one continuous-flow pass fragmented afterwards rather than break-token-driven ([#321](https://github.com/jhaygood86/PeachPDF/issues/321)); multicol columns aren't modelled as fragmentainers ([#322](https://github.com/jhaygood86/PeachPDF/issues/322)); monolithic content isn't explicitly marked ([#323](https://github.com/jhaygood86/PeachPDF/issues/323)); paint is still `async` only because `CssBoxImage`/`CssBoxObject` load images inside it ([#324](https://github.com/jhaygood86/PeachPDF/issues/324)); and `CssProxyBox` still wrote its snapshot back to the live boxes before painting, because the `overflow` clip walk resolved ancestor client rectangles off the live box tree ([#325](https://github.com/jhaygood86/PeachPDF/issues/325), since fixed).
