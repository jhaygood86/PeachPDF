# Canvas audit: what is CPU-only or stranded in the scripting layer (Phase A)

Two goals (user): canvas drawing is hardware accelerated or capable on WinUI/Skia/CoreGraphics, and anything generally useful lives in `PeachDrawing.*` and is exposed upward, `OffscreenCanvas` and `ImageBitmap` included. This is the audit of what exists today against them, the work list for the phases of the html-canvas plan, and the safety net that lets each move prove it changed nothing.

**Safety net (built in this phase).** `CanvasParityTests` (`tests/PeachBrackets.Scripting.Tests`) paints 32 vector-only scenes (fills, alpha, linear/radial/conic gradients, dashes and caps, arcs and curves, evenodd clips, transforms with `roundRect`, shadow, multiply/lighter, all nine Porter-Duff modes and one with a clip, partial and full `clearRect`, patterns, canvas-to-canvas draws, `putImageData`, smoothing off, save/restore, miter limit) and pins the SHA-256 of each page's pixels in `Baselines/CanvasParity.txt`; a second test pins what scripts read back (`getImageData`, `isPointInPath`, `isPointInStroke`, a checksum, `toDataURL` length, an erase). Regenerate with `PEACH_UPDATE_BASELINE=1` and review the diff; a changed hash is a behavior change to explain. The 32 hashes are all distinct, so no scene is blank. The raster backend is deterministic and the scenes draw no text, so the hashes do not depend on fonts or machine.

Locations are in `src/engine/PeachBrackets.Scripting/Internal/Canvas/` unless noted. "Target" is where the logic belongs; "GPU path" is what each screen backend should do instead.

## Bugs the audit found by running things

- `putImageData(data, dx, dy, dirtyX, dirtyY, dirtyW, dirtyH)` always threw "The dirty rectangle is not finite": the finite check counted argument 0 (the `ImageData`, which is not a number). Fixed in `ScriptRuntime.CanvasPixels.cs`; `PutImageDataWithADirtyRectangle_DrawsOnlyThatPart` covers it. It was untested because the only existing `putImageData` tests used the three-argument form.
- `drawImage(canvas)` onto itself overflowed the stack (fixed in the previous change).

## Rules for the phases that move this code

- A move is done when the scripting-layer copy is deleted. No parallel implementations.
- Each move keeps `CanvasParityTests` green with unchanged hashes, or regenerates the changed scenes with the visual and behavioral reason written in the PR.
- GPU backends cannot be hashed on CI the way the raster backend can: their pixel tests (`PeachDrawing.Skia.Tests`, `PeachDrawing.Win2D.Tests`, `PeachDrawing.CoreGraphics.Tests`) compare against the raster reference within a tolerance.
- Phase 1 comes first because items 1, 2, 3, 4, 6, 7, 8 and 11 all depend on the compositing primitives and the offscreen surface it adds.
