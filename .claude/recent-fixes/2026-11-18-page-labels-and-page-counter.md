# Page labels (composer, declarative, HTML) and the page counter

- **Writer**: `PdfPageLabelRange`/`PdfPageLabelStyle`/`PdfComposer.AddPageLabels`; `PdfCatalog.SetPageLabels` writes a flat `/Nums` tree on each save (rebuilt, so saving twice is right). A range at page 0 is added as plain decimal when none was given (the format requires it). `PdfOperation` carries labels by resolving each output page's (style, prefix, number) and opening a range only where it does not follow on.
- **Declarative**: `IPageDescriptor.PageLabel` records a range per section; `RenderPagesCore` moves it to the section's first page (a `ConditionalWeakTable<HtmlDocument, ...>` keyed by the laid-out document). `IDocumentBuilder.PageLabels` takes absolute ranges and is applied after every section is in.
- **Page counter** (`HtmlContainerInt.BuildPageCounterValues`): built after pagination in `LayoutMarginBoxes`. A page that resets shows the reset value (the idiom `counter-reset: page 1` restarts at 1; the implicit +1 is not also applied). `:left`/`:right` stay physical: the earlier plan said they should follow the counter, but css-page-3 section 4.2.1 classifies by page progression, so they do not. `:first` is document-level here, so a named-page restart needs a rule that matches one page (a plain `@page body` matches every page of that name and resets on each).
- **`-peachpdf-pdf-page-label`** (+ hidden `-prince-pdf-page-label`): CSS-OM-only descriptor like `bleed`/`marks`; read as `StyleDeclaration.PdfPageLabel` (needs a setter, or `StyleDeclarationTests.EveryNamedProperty_RoundTripsInheritKeyword` fails). `PageLabelResolver` maps `["prefix"] counter(page, style)` to a PDF style and anything else to a text-only label; letters past Z are text because PDF repeats the letter and CSS counts. Ranges travel on `DocumentAnnotations.PageLabels` like bookmarks.
- **Traps**: the text reader of the importer skips operators outside `TextOnlyOperators` (not relevant here but cost an hour in the layers work); harness runs of all 263 showcases crashed once with an `AccessViolationException` in `DerivedStyle.get_ActualDisplay` (Release) and passed on rerun - unreproduced, not caused by this change as far as we could tell.
- Not done: `target-counter(..., page)` ignores the counter rules (accepted gap file), `counters()` for page.
