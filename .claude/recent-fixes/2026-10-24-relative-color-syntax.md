# Relative colour syntax (#1772)

`rgb(from red r g b)` and the same in `hsl()`, `hwb()`, `lab()`, `lch()`, `oklab()`, `oklch()` and `color()` are read (`ColorFunctionExtensions.Relative.cs`, a partial of the colour resolver).

- **Shape:** `from <origin> <3 components> [/ alpha]` (4 with the space for `color()`). The origin is any colour (a nested relative one too: it shares `color-mix()`'s `MaxColorMixDepth`), converted to the function's space; its components are bound to channel keywords (`r g b` scaled to 0-255 for `rgb()`, `h s l`, `h w b`, `l a b`, `l c h`, `x y z` or `r g b` per space for `color()`, plus `alpha`). An omitted alpha is the origin's, not 1.
- **calc() over keywords:** not a second calc grammar. `CalcParser.Parse` takes an optional `variables` dictionary and an `Ident` bound in it parses as a `NumberCalcNode`; a small evaluator in the same file (`Relative.Calc`) folds the tree to a number, percentage or angle, with the type rules of `CalcTypeChecker` (`calc(r + 10px)` and `calc(r + 10deg)` are rejected; a hue takes a number or an angle, `h` itself is a number).
- **Unclipped origin:** a plain sRGB origin converts from its own 8-bit value, so `rgb(from red r g b)` is exactly red; one that can leave the gamut (`lab()`, `oklch()`, `color()`, `color-mix()`) converts from the Oklab coordinates it was written with (`ToSpaceFromOklab`, which gained the three new `color()` spaces), so `color(from color(display-p3 1 0 0) display-p3 r g b)` is the same colour back, and the result of a wide-gamut function feeds a mix unclipped too.
- **Traps:** `CssValueParser.TryGetColor`'s string fast path for `rgb(` read `from` as a malformed number and returned false, so a text containing `from` (like one containing `none`) skips it for the token reader. `WrittenComponents` returns null for a relative colour (its `from` would otherwise be read as a component and give a wrong missing-mask).
  Argument count is checked strictly (`rgb(from red r g b / 1 2)` is invalid), as `Extract` alone ignores trailing values after a slash.
- **Animation:** nothing new in `CssValueInterpolator`: `TakesAMixIntoOklab` already named `from`, and those branches were dead code until now. A relative colour is mixed in Oklab, like `color()`.
- **Not done:** `none` in a relative colour's result is 0, not a missing component of the mix; `hsl()`/`lch()` origin hues are not made powerless for a gray (the conversion's hue is used).
