# The hosts use the tree diff

Both hosts keep the tree they last told the platform about and compare it with the new one (`AccessibilityTreeDiff`, from the engine) in `RefreshAccessibility`, instead of announcing "the whole structure changed" after every restyle.

- **Empty diff, no event.** A focus change, a caret move or a repaint that rebuilds the tree but changes nothing a reader hears used to raise a structure change (and on WinUI a full peer rebuild). Both now return early; WinUI does not even invalidate its peers.
- **WinUI.** A structure change when anything differs, `ToggleStateProperty` for a check box that was toggled (the old and new `ToggleState`), and `RaiseNotificationEvent` per announcement with the region's id as the activity id; an assertive region is `ImportantMostRecent` (interrupts), polite and others `MostRecent`. `LastAccessibilityDiff` is kept for the window test, because a test cannot register a UI Automation client to see events.
- **Android.** `AccessibilityMapping.ContentChangeTypes` turns the kinds of change into the event's content-change bits (subtree, text, state description) and a live region sends its own window-content-changed event with `CONTENT_CHANGE_TYPE_TEXT`, because TalkBack reads a live region from the event's source node and its `LiveRegion` mode, which was already set on the node. The first tree of a document is announced as a subtree as before.
- **Not done / not verified:** no live region can change in the running host yet, because the engine has no way to change text in place that the hosts expose; the announcement path is tested in the engine (`AccessibilityTreeDiffTests`) and its mapping here, but nothing on a device has produced one. `RaisePropertyChangedEvent` covers only the toggle state; expanded, value and name changes arrive as structure changes.
