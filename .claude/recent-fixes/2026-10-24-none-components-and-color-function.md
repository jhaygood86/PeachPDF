# `none` is a missing component, and `color()` is read

Part of #1774 and #1772 (relative colour syntax is the remaining half of #1772).

- **Representation:** `ColorSpaceMath.WrittenCoords` gained a `Missing` bit mask (bits 0-2 the components in the written space's order, `AlphaMissing` the alpha). A colour's static value is unchanged by it (`none` is 0, an alpha of `none` is transparent, as Chrome draws it); only a mix reads it.
  `Color.MixComponents` copies the other operand's value into a missing slot after mapping the slot to the mix space's analogous one (`ColorSpaceMath.AnalogousSlot`, CSS Color 4 §12.4: lightness to lightness, hue to hue, a/b to a/b, r/g/b to r/g/b or x/y/z; hsl saturation is chroma-like; hwb's whiteness and blackness have none), and a missing alpha takes the other's alpha before premultiplying.
- **Trap, cross-family:** `lab(none 40 20)` in an `oklab` mix is *not* the same as `lab(80 40 20)`: the colour is converted with the missing component as 0 and only the analogous slot (L) is then replaced, so a and b come from `lab(0 40 20)`. Tests compare same-family operands (oklab/oklch) for exact equality for that reason.
- **Trap, second parser:** `CssValueParser.TryGetColor` has a string fast path for `rgb(`/`rgba(` that reads numbers only; it silently mis-read `rgb(none 0 0)`. A text containing `none` now skips it for the token reader (`ColorFunctionExtensions`). `none` is rejected in the legacy comma syntax, as in a browser.
- **`color()`:** every predefined space (`srgb`, `srgb-linear`, `display-p3`, `a98-rgb`, `prophoto-rgb`, `rec2020`, `xyz`, `xyz-d50`, `xyz-d65`); `a98-rgb`, `prophoto-rgb` and `rec2020` are new `ColorSpaceMath.Space` members whose inverse matrices are computed once (`Invert3`) from the published forward ones. It needed a `FunctionNames.ColorFunction` converter in `Converters.ColorConverter`, or `background-color: color(...)` was dropped at the CSS-OM before the render layer saw it. Wide-gamut values are clipped to sRGB like `lab()`/`oklch()`, and mix from their unclipped Oklab coordinates.
- **Animation:** `CssValueInterpolator`'s colour token carries `OklabMissing`, filled by `CssValueParser.TryGetMixOperand` for every Oklab-mixed colour; `rgb()`/`hsl()`/`hwb()` containing `none` now take the Oklab mix (`TakesAMixIntoOklab`), as Chrome does. `#f00` to `color(display-p3 0 0 1)` half way is Chrome's `oklab(0.547 0.096 -0.098)` (pinned).
- **Evidence:** Engine/PeachPDF/PDF suites green in Release; white is white in all nine `color()` spaces and grays stay gray; the showcase page rasterizes identically in MuPDF and PDFium.
