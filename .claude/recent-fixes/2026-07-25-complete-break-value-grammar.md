# Complete `break-*` value grammar

_Landed 2026-07-25._

**Complete `break-*` value grammar** ([issue #299](https://github.com/jhaygood86/PeachPDF/issues/299), [CSS Fragmentation 3 §3.1/§3.2/§3.3](https://www.w3.org/TR/css-break-3/)): the six break properties now accept exactly the spec's value sets, and every accepted value round-trips into `CssBox` storage. Parsing/plumbing only — the *layout* behavior of the newly-accepted values stays out of scope and is tracked by the issues this unblocks (#302 directional forced breaks, #304 avoid-* distinction, #312/#313 multicol, #314 table rows, #315 flex/grid, #319 region no-op). Pieces:
1. **All four value sets now live in `Map.cs`**, one dictionary per spec production, each doc-commented with its section. `BreakModes` (§3.1) gained `recto`/`verso`/`region`/`avoid-region` and **lost `always`**; `BreakInsideModes` (§3.2) and `PageBreakModes` (§3.3) were already right; a new `PageBreakInsideModes` (§3.3) replaces the hand-rolled converter `PageBreakInsideProperty` was the only sibling to carry, so all six property classes are now uniform map-backed converters. New `BreakMode.Recto`/`Verso`/`Region` + `Keywords.Recto`/`Verso`/`Region`. (`all` was never in a break map — nothing to remove.)
2. **`always` is legacy-only now, and `page` is the single forced-break token.** `break-before: always` is invalid CSS and dropped at parse time — **a user-visible behavior change** (it used to force a break), documented in `docs/html-css-support.md`; `page-break-*: always` is unaffected and still normalizes to `page` at the `CssUtils` seam. **Careful with the rationale**: `always`/`all` were never *in* §3.1 to be "dropped" — they are [css-break-**4**](https://www.w3.org/TR/css-break-4/) *additions*, so this is PeachPDF implementing the Level 3 value set, not tracking a removal (the #299 issue text has this backwards, and the first pass propagated it into the docs and tests before review caught it). Forward-porting them was considered and **declined** ([#328](https://github.com/jhaygood86/PeachPDF/issues/328), closed not-planned): Level 4 is a Working Draft, and PeachPDF does not implement draft-only values ahead of the spec settling. The compat question it raised is answered by the new **[Forward compatibility](docs/html-css-support.md#forward-compatibility)** section — only standards-compliant documents are guaranteed to render the same across versions; anything relying on a value the spec doesn't define may change as an area moves toward spec, and that is not a regression. Use that section (plus a **migration note** in the affected doc section) whenever a spec-correctness fix has a visible effect. Since no CSS path can put `"always"` in a break field any more, the dead arm came out of both duplicated forced-break tests (`CssBox.IsForcedBreakValue`, and `DomUtils.GetPrecedingKeepWithNextRun`'s §3.1 forced-beats-`avoid` check — they duplicate each other because `IsForcedBreakValue` is `private`; **widen both together** if #302 makes `left`/`right`/`recto`/`verso` forced).
3. **Legacy-alias plumbing hole closed**: `page-break-before|after|inside` were missing from `CssUtils._knownPropertyNames` and from `CssDefaults`' initial-value store, so `initial`/`unset`/`revert` silently no-opped on the legacy spelling while working on the modern one. Both now carry the three names (they share the modern names' `CssBox` storage, so the extra seed writes are idempotent).
Tests: `CssPropertyTests` gained per-property accept/reject theories asserted against the spec grammar rather than against the maps; `CssUtilsTests` covers the non-`always` half of the §3.3 alias table (`avoid` stays `avoid`, **not** `avoid-page`), snapshot/initial-value presence, and an end-to-end cascade round-trip (`break-before: recto` → `"recto"`, `break-before: always` → `"auto"`); `PageBreakIntegrationTests` pins the behavioral consequence both ways (`break-before: page` paginates, `break-before: always` does not). 100% diff coverage; full net8.0 suite green (5925). No showcase — parsing/plumbing with no new visible rendering capability. **Found and deferred**: `CssBoxProperties.InheritStyle` copies no break value in its `everything: true` branch, so a structural clone (repeated table header proxy, inline/block split) loses its break values — filed as [issue #327](https://github.com/jhaygood86/PeachPDF/issues/327), since fixing it changes layout behavior.
