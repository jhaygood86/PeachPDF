# CSS Grid named lines + `grid-template-areas`

_Landed 2026-07-23._

**CSS Grid named lines + `grid-template-areas`** (issue #261, closing two of the #232 grid deferrals): named grid lines and the named-area model now parse and place. `GridLine` gained a `Name` (bare `<custom-ident>` and the `<custom-ident> <integer>` Nth-line form); `GridTrackListGrammar` collects `[name]` groups in the top-level track list into `GridTemplate.LineNames` (name → sorted 1-based line numbers; names inside `repeat()` rejected — v1 deferral). A new shared `GridTemplateAreasGrammar` parses the quoted-string rows into a `GridAreas` grid (validating equal columns per row and that each named area is one filled rectangle; `.`/`...` empty cells), wired as a `grid-template-areas` property via the four touch-points. The engine builds per-axis line-name tables, merges each area's implicit `name-start`/`name-end` lines (col `C1+1`/`C2+2`, row `R1+1`/`R2+2`) into them, pads the explicit track defs to the area grid's counts (so the areas establish the track counts), and threads the tables into `ResolveAxis`, where `ResolveNamedEdge` resolves a named edge (Nth clamped, with the §8.3.1 `-start`/`-end` suffix fallback for area names). The `grid-column`/`grid-row`/`grid-area` shorthands became custom converters (`GridColumnRowShorthandValueConverter`/`GridAreaShorthandValueConverter` over a shared `GridPlacementShorthand`) implementing the §8.3.1 omitted-value copy rule — a bare `<custom-ident>` propagates to the paired/all edges (`grid-area: main` fills the whole area), while a line number/span leaves the omitted edge `auto`; the generic `WithOrder(...).Option()` DSL couldn't express this. **Prerequisite CSS-OM fix**: `ValueBuilder.Apply` marked any declaration value containing `[`/`]` invalid (default arm), dropping a named-line track list entirely under strict parsing — square-bracket tokens are now accepted in a value (mirroring the unicode-range `Range`-token handling). Verified by `GridLineGrammarTests`/`GridTrackListGrammarTests`/`GridTemplateAreasGrammarTests`, `GridLayoutIntegrationTests` (named-line placement, area edges, `grid-area: <name>` fill, the number-doesn't-copy and slash forms), and a `css_grid_areas` holy-grail showcase rasterized in **both** PDFium and MuPDF. **Still deferred** (#265): named lines inside `repeat()`, `span <name>`, and `auto`/`fr` row tracks not stretching to a definite container height.
