# `@property` registrations now honored in SVG `var()` resolution

_Landed 2026-07-22._

**`@property` registrations now honored in SVG `var()` resolution** (issue #213): the `@property` registry was threaded into `var()` resolution only through the HTML cascade (`DomParser.ResolveDeferredVarProperties` → `CssVarResolver.Substitute` with a `VarContext`); the SVG styling paths call the single-shot `CssVarResolver.Resolve(node, value)`, which passed no `VarContext`, so a registered custom property's `initial-value`/`syntax`/`inherits` were ignored in SVG. Now: (1) the registry-build loop is extracted into a shared `RegisteredProperty.BuildRegistry(CssData, CssValueParser)` (used by `DomParser.GenerateCssTree` and the SVG loader — one code path, per the "one parser" convention); (2) `CssVarResolver.Resolve` gained an optional `VarContext? context = null`; (3) both SVG source nodes carry a `VarContext?` field threaded through their ctors/`Children` and passed to `GetMatchedDeclarations`/`ResolveVar` — **standalone** SVG (`XElementSvgSourceNode`) builds its context from its own `<style>`'s `@property` rules (`ImageLoadHandler.LoadSvgFromStream` + the nested `data:image/svg+xml` case in `SvgTreeBuilder.BuildImage`), **inline** SVG (`CssBoxSvgSourceNode`) reuses the host document's already-built `HtmlContainerInt.RegisteredProperties`; (4) `SvgCssStyling.CascadeCustomProperties` drops `inherits:false` registered names from the inherited copy for standalone SVG (mirroring `CssBoxProperties.InheritStyle`; inline SVG already inherits through the registry-aware HTML cascade). So an unset registered property resolves to its `initial-value`, a syntax-mismatched set value falls back to the `initial-value`, and an `inherits:false` descendant uses the `initial-value` rather than an ancestor's value — in both standalone and inline SVG. This holds for every value tier, including the SVG inline `style=""` tier (`SvgTreeBuilder.ResolveStyledAttr` → `ISvgSourceNode.ResolveVar`, which now carries the context). HTML inline `style=""` already honored `@property` (inline declarations flow through the same `pendingVarProperties`/`ResolveDeferredVarProperties`/`VarContext` path as `<style>` rules — no code change, coverage added). See `SvgIntegrationTests` (standalone/inline initial-value + inline-`style=""` consumer, syntax fallback, inherits:false), `AtPropertyCascadeIntegrationTests` (HTML inline-`style=""` consumer: initial-value + syntax fallback), and `RegisteredPropertyTests.BuildRegistry_*`. No new showcase: an SVG whose fills come from `@property` initial-values renders identically to one with literal colors (a correctness/plumbing fix, not a new visible capability).
