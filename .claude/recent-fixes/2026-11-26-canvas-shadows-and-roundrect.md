# Canvas shadows are a separate layer; roundRect takes elliptical radii

- A shadow is the shape's alpha recolored to the shadow color, offset in device space (no transform touches the offset), blurred with sigma = shadowBlur / 2, drawn first with the shape's alpha and composite operation. Backends cut a layer to the visible surface, so the shadow is its own layer with the offset applied inside it (a shape outside the canvas can still cast a shadow in).
- roundRect converts every argument first (WebIDL), then returns for non-finite rectangles or radii, throws RangeError for 0 or more than 4 radii or a negative radius, and builds each corner as an arc with its own horizontal/vertical radius. A negative width/height mirrors the outline, so the first radius is the corner at (x, y). Leaves a new subpath at (x, y).
- Measured: html-canvas 1687 -> 1807 files (2952/5030 subtests).
- Still open in Phase 4: stroker edge cases (empty/zero-length subpaths, round joins, scaled arcs), isPointInPath, strokeRect zero-size.

## Stroking
- A stroke prunes zero-length line/curve pieces and drops subpaths left with nothing to draw (lone moveTo, a point closed on itself) before drawing: no dot, however round the caps (`PathData.PrunedForStroke`).
- `strokeRect` with a zero width or height is a line out and back, closed (joins, no caps).
- `FlatPath.ForStroke` (raster stroker): an open subpath that starts/ends on a curve gets one extra point 1e-3 of the parameter from that end, so a cap is square to the curve's tangent rather than the last flattened chord (a wide arc stroke showed a visible tilt). The pinned `arc-ellipse-curves` scene hash moved for that reason.
- `isPointInPath` counts points on the edge as inside and validates the fill rule enum; `Finite()` now converts every argument first (WebIDL).
- html-canvas then 1835 files, 2980/5030 subtests.

## Stroker leftovers (finished)
- A turn straight back on itself (cross product 0, dot < 0) has no "outside" to pick from the cross sign; `Stroker.AddJoin` now draws a round join as the half disc the path was heading into and nothing for miter/bevel. A *closed* two-point subpath is a real closed contour (line out and back: joins, no caps), where it used to be treated as open and capped (`closed && Count > 2` became `> 1`).
- A miter limit under 1 bevels every join (it used to fall back to 10); 0 still means "never set".
- `FlatPath.ForStroke(path, tolerance, halfWidth)`: each chord is stroked as a rectangle, so a chord's turn moves its ends by halfWidth * angle. When the stroke is wide against the curve (a 200 px stroke on a radius 25 arc) the cubic is cut so no chord turns more than 2 * tolerance / halfWidth (cap 4000), otherwise the rectangles near the circle's center overlapped into the wedge the arc must not cover.
- `arc()` between two angles a whole turn apart against its direction (0 to 2*pi counterclockwise, 2*pi to 0 clockwise) is a whole circle (what browsers draw), not no arc; equal angles are still no arc.
- `isPointInStroke` no longer approximates: it strokes the path in user space with `PathStroker` (the shared stroker, so dashes, caps, joins and a non-uniform scale) and tests the point against the outline with the nonzero rule. `Touches` is gone.
- Open: `isPointInPath` after `scale(Number.MAX_VALUE, ...)` (single-precision transform; issue 2495, accepted gap, expected failure).
- html-canvas now 1849 files, 2994/5030 subtests; floor 2984. PeachDrawing.Tests (441), PeachPDF.Tests, PeachBrackets.Scripting.Tests and PeachDrawing.PDF.Tests pass, with the pinned parity hashes unchanged.
- Native backends (Skia, Win2D, CoreGraphics) stroke with their own engines and were not changed; they were not checked against these cases (CoreGraphics cannot be built here).

## Phase 5: layers and filters
- `beginLayer`/`endLayer` are a stack of frames in `CanvasBitmap`: what is drawn while a layer is open goes to the frame's own op list and reaches the canvas (or the enclosing layer) as one composited op at `endLayer`, which `RecordWith`s the state the canvas had at `beginLayer` (alpha, operator, shadow, filter, clips; identity transform because each op carries its own). Inside, alpha/operator/shadow/filter start over. A `restore()` cannot pop a save made before the layer, `endLayer()` throws with no layer or a save still open inside it, `reset()` drops the layers, and everything that reads the canvas back (getImageData, putImageData, toDataURL, toBlob, convertToBlob, createImageBitmap, createPattern, drawImage from it) throws InvalidStateError while one is open. A promise-returning method rejects instead of throwing.
- `PeachDrawing.Core.FilterList` is the CSS filter-list grammar (Core has no CSS parser, so a color reader is passed in) and `ColorMatrix` gained the Filter Effects matrices as public statics; `FilterEffectResolver` in the engine now calls them rather than keeping its own copies. `ctx.filter` stores the text as written (`blur(  5px)` round-trips), ignores anything not valid, and a filtered drawing is drawn in a layer with the effects, inside the shadow and the alpha layer (filter, then shadow, then alpha/composite).
- `CanvasFilter` validates the primitives the way Chrome does (a present member must convert to a finite number, undefined included; unknown names are ignored) and applies gaussianBlur, colorMatrix and dropShadow. componentTransfer, convolveMatrix and turbulence are validated but not yet applied (they need Core layer effects and backend implementations), and `url()` SVG filters are not read.
- html-canvas 1903 files, 3058/5030 subtests; floor 3048.

## Issue 2495: the canvas transform is double precision and the path lives in user space
- `CanvasState.Transform` is an `Affine2D` (double; inverse scaled by the largest term so a determinant that overflows is not in the way) and the path being built is kept in the space the transform makes, as Chrome does: `SetTransform`/`Concat`/`Restore`/`EndLayer` rebase it by `old * new^-1`, a transform with no inverse leaves it alone. Drawing, `clip()` (stored on the canvas, in device space), and the hit tests take the path as it is; `isPointInPath`/`isPointInStroke` map the point back through the inverse. Before, the path was in device space and every fill/stroke inverted it again, which lost precision and overflowed a float at `scale(Number.MAX_VALUE, ...)`.
- Traps: a fill must clone the path (the script goes on adding to it before the recorded draw runs; it used to get a copy from `Transformed`), and the context's path methods now build with the identity so what is added is not moved by the transform.
- `isPointInPath.basic` (element and offscreen) pass; the accepted-gap note and expected failures are gone. html-canvas 1905 files, 3060/5030; floor 3050.

## Phase 5, filter primitives
- `ComponentTransferEffect` (256-entry table per channel, `BuildTable` from an feFunc description), `ConvolveMatrixEffect` and `TurbulenceEffect` are Core layer effects; the engine's own `FeConvolveMatrix`/transfer-table code now calls the Core/PeachDrawing copies (`FilterOps.ConvolveMatrix`, `ComponentTransferEffect.BuildTable`) and the engine's duplicate `FilterEdgeMode` enum is gone. The SVG convolution turns its kernel half way round and puts `targetX/Y` over the pixel; Skia correlates, so it is given the kernel reversed with the same offset; Win2D's effect is already the convolution (tested on WARP against the raster result). Turbulence replaces the layer, so Skia's version is an image filter from the noise shader and takes no input. Win2D's turbulence effect has no seed and is not used; CoreGraphics applies none of the three (issue 2496, accepted gap).
- `CanvasFilter` componentTransfer (tableValues must be an array: a number, an object or an object with a valueOf giving one throws), convolveMatrix (a kernel with no columns, or a divisor or target that cannot work, filters nothing) and turbulence are now applied, not just validated.
- Still not read: `url()` SVG filter references (they need the document's SVG filter tree evaluated through the engine's raster evaluator, and a Core effect that carries a raster callback), and the `:visited`/cross-origin tainting rules around them.
- html-canvas 1906 files, 3061/5030; floor 3052.

## Phase 5, url() filters
- `url(#id)` in a canvas filter (alone, quoted, or chained after CSS functions: `brightness(1.8) url(#green)`) runs the page's SVG `filter` element over the drawing. `ScriptDocument.GetSvgFilter` finds the element, rebuilds its outermost inline `svg` as a standalone XML tree (walking the DOM: the HTML serialization does not close empty foreign elements, so it does not parse back), cascades the page's own `<style>` text plus the svg's, builds it with `SvgTreeBuilder` and returns a `ScriptSvgFilter`; `SvgRasterFilterEvaluator.ApplyTo` evaluates it over a raster surface with the surface's area as the box the region is measured against.
- A filter is now a list of `FilterStep`s (effects, or one SVG filter): effects alone stay one layer with those effects (GPU where the canvas can), anything with a `url()` goes to a raster surface (`BeginRasterSurface`/`DrawRaster`, so it works on every backend) and runs the steps in the order written. An id that names no filter makes the assignment invalid (ignored).
- Not done: the origin-clean flag. The remaining `manual/filters` failures are tainting tests (`:visited` colors, cross-origin `feImage`, displacement-map tainted inputs); this engine has no tainting at all and never matches `:visited`, so they move to the pixels phase of the plan.
- html-canvas 1907 files, 3063/5030; floor 3058.

## Phase 6, text (first part)
- The WPT testharness runner installed no fonts at all (the reftest renderer pinned Liberation and Ahem; the testharness evaluator never did), so every canvas `measureText` was 0 and every text pixel test failed. `WptRenderer.InstallFontsAsync` is now shared. Do not read the earlier text failures as engine failures.
- `@font-face` fonts reach a script only after the page's scripts have run (the cascade registers them at layout), so a script that draws text with a web font saw the fallback. `ScriptDocument.LoadFontFacesAsync` parses the page's `style` elements and linked sheets and registers their fonts (the cascade's own `CascadeApplyStyleFonts`), once, after the scripts and before the load event, and `document.fonts.ready` is a real promise settled right after. `document.fonts.load` waits on it; `FontFace` objects and `fonts.add` are still stubs.
- `CanvasFont` parses and serializes the `font` shorthand (any order of style/variant/weight/stretch, absolute and relative sizes, a line height that is accepted and dropped, quoted and multi-word families, system fonts, no CSS-wide keywords, `var()`, or a `;`): `font` gives back `italic small-caps 12px "Unknown Font", sans-serif`, 400 is not written, sizes are pixels. A relative size is relative to the canvas element's computed font (10px when it is not in a document).
- `PeachDrawing.Core.TextRunMeasure` measures a run with the same shaping the canvas draws with: width with letter and word spacing (added after every cluster / every space), the ink box from the glyph outlines (cubics sampled at 8 points), the font's ascent and descent from `NormalLineAscent/Descent` (hhea, not the cell metrics `Font.Ascent` uses), the em square split in the ratio of ascent to descent, and the clusters. `textBaseline` is the line that many pixels above the alphabetic baseline (top = em ascent, hanging = 2/3 of it, middle = half the em height from the top, bottom = -em descent); hanging and ideographic follow what the tests measure, not a font's BASE table (not read yet).
- A canvas draws a word-spaced run word by word at the measured positions. Letter spacing and kerning go through `DrawString`'s own parameters.
- Not done: `getTextClusters`/`fillTextCluster`, `getSelectionRects`, `getIndexFromOffset`, `getActualBoundingBox`, `shapeText` (all tentative, about 85 files); bidi runs (a run is one direction), complex shaping centering, small-caps synthesis, `lang` effect on `locl` (the tr/en width test), variation selectors, `FontFace`.
- html-canvas 2002 files, 3160/5030; floor 3150. html-img-canvas-elements and html-dom floors untouched (they pass above them).

## Phase 6, ranges, shaped text and FontFace
- `PeachDrawing.Core.TextRunLayout` lays a string out as one `PeachDrawing.Text` paragraph line (no wrapping, base direction from `direction`, a `RunStyle` fallback that asks the render context for a font that has a missing character) and answers: the boundaries between characters (`Segmenter.FindGraphemeBoundaries`), `SelectionBoxes(start, end)`, `CaretX`, `IndexFromOffset`, the visual `Runs`, and `TryGetInk(start, end)` (outline bounds of the glyphs whose cluster is in the range; a glyph's cluster index is relative to its run's start). The canvas takes `width` from it only for non-ASCII text: ASCII text keeps the plain measure, which keeps a trailing space (the paragraph hangs it) and gives a control character the font's own advance.
- `IndexFromOffset` takes a point on a boundary as that boundary and otherwise asks the layout, 1e-4 to the left so that a point half way between two characters goes to the earlier one. The right-to-left ties are the one open variant of `index-from-offset-edges` (center, rtl).
- TextMetrics methods: `getTextClusters` accepts the options first (`getTextClusters({align})`) or after a range; a cluster's `x` is where its alignment point is from the text's own alignment point, its `y` how far its baseline is below the text's. `getActualBoundingBox` is relative to the alignment point and the baseline like the `actualBoundingBox*` members, a stretch with no ink is a zero box on the point. Index errors: an unsigned long that is negative is a TypeError; a range past the length (or, for clusters and bounding boxes, start > end) is an IndexSizeError, and `getSelectionRects` takes start > end.
- `FontFace`/`document.fonts`: a face loads through `ScriptDocument.LoadFontFaceAsync` (CSS `src` list or a buffer as a data address) when `load()` is called; `document.fonts.ready` is a promise that is settled when the page's sheets' fonts are registered and no face is loading, and a later load makes the next `ready` a new promise. The run loop (`RunFontLoadsAsync`) waits for faces a script started and runs the microtasks they release, until none is left. `document.fonts.load(font)` waits for `ready` first, so a page font is there when it resolves.
- Not done: the 64 subtests of `index-from-offset`, `selection-rects` and `advance-to-position` that compare with the DOM need `document.caretPositionFromPoint` and `Range.getClientRects` (a DOM geometry feature); small caps synthesis, `lang`-dependent shaping, variation selectors, complex-shaping centering, whitespace-only ink for U+3000.
- html-canvas 2090 files, 3316/5030; floor 3306. html-img-canvas-elements, html-dom and html-forms floors are unchanged and pass above them.

## Phase 6, DOM geometry for the text tests
- `Range.getClientRects`/`getBoundingClientRect` for a range inside one text node and `document.caretPositionFromPoint` come from the script probe (the document laid out again without scripts): `HtmlDocument.ProbeTextRects`/`ProbeCaretAt` over the recorded text runs. The probe now records them (`CloneWithoutScripts` sets `RecordTextRuns`). A word of a run knows where its characters are in its text node (`SourceStart`) and where each edge of them is (`TextWordSlice.Edges`, from the word's left edge); the run's own `CharacterOffsets` are ambiguous at a boundary between runs of different directions (the boundary after the last character of an RTL word and the one before a trailing `?` have two places), so the rectangles are made from the words' edges, plus the gap of the separating space when the range includes it, and stretches that touch on a line are one rectangle. An empty range is a rectangle with no width at the place.
- A trap: a run's `Owner` is its containing block (the element), not the text box, so walking up from `Owner.ParentBox` finds the wrong element (body).
- The probe is cached by markup (the last 8): a script that adds an element, reads where it is and takes it away again for each of many inputs lays the same document out once. Jint's memory limit counts allocation, not what is live, and 1800 probe layouts passed 4 GB before this; the runner's script memory limit is now 4 GB anyway, and its failure messages keep 900 characters.
- `getSelectionRects` rectangles are as tall as the DOM's line (ascent + descent + the font's line gap, the gap split above and below), so that they match the DOM within a pixel; a stretch with no width is a rectangle at the caret. `IndexFromOffset` takes every place a boundary has in each run it touches (`PlacedRun.GetCaretX`) and the nearest wins, with ties to the one first in reading order; the layout's own `PositionAt` is a hit test (the character under the point), not that.
- html-canvas 2094 files, 3420/5030; floor 3410. Not done: see `.claude/accepted-gaps/canvas-text-small-caps-lang-and-variation-selectors.md` (issue 2499).
