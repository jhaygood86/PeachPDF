# CSS Grid layout

_Landed 2026-07-23._

**CSS Grid layout** (issue #232 — [CSS Grid Layout Module Level 1/2](https://www.w3.org/TR/css-grid-2/)): a real grid track-sizing + placement engine, `CssLayoutEngineGrid` (`src/PeachPDF/Html/Core/Dom/`), modeled on `CssLayoutEngineFlex` (instance class, `PerformLayout` dispatched from `CssBox.PerformLayoutImp` for `display: grid`/`inline-grid`, which are also added to the block-ish sizing gate + generic-width-preskip and `DomParser`'s blockify/first-letter lists). Two shared grammars (the "one grammar" convention) live in `src/PeachPDF/CSS/`: `GridTrackListGrammar` (`<track-list>` → `GridTemplate`/`GridTrackSize` — lengths, `%`, `fr`, `auto`, `min-content`/`max-content`, `minmax()`, `fit-content()`, `repeat(<n>,…)` expanded inline, and `repeat(auto-fill|auto-fit,…)` recorded as a layout-time section) and `GridLineGrammar` (`<grid-line>` → `auto` | `<integer>` | `span <n>`). Layer A adds `grid-template-columns/rows`, `grid-auto-columns/rows`, `grid-auto-flow`, the `grid-column/row(-start/-end)` longhands + `grid-column`/`grid-row`/`grid-area` shorthands, and `justify-items`/`justify-self` + `place-items`/`place-content`/`place-self` (reusing the existing `align-*`/`justify-content`/`gap` families); each of the ~11 new box fields is wired through the four `CssBoxProperties`/`CssUtils` touch-points. Engine: column tracks size against the definite `GetBoxWidth` width via the §11 base/growth-limit model — `fr` tracks absorb free space through the §11.7 flex-fraction loop (honoring `minmax()` floors), intrinsic tracks take their base from measured item content; `repeat(auto-fill|auto-fit,…)` resolves its count from the container width, and `auto-fit` collapses empty repeated columns (zeroed, gap dropped). Placement resolves explicit line/span coordinates then auto-places the rest over a fixed (minor) / growing (major) axis occupancy grid — row flow fixes columns, column flow fixes rows, `dense` restarts the free-cell search from the origin; implicit tracks cycle `grid-auto-columns/rows`. Items are sized to their (possibly spanned) cell and translated there via the flex `ResizeItem`/`OffsetLeft`/`OffsetTop` idiom, honoring `justify-self`/`align-self` (default `stretch`; a non-stretched auto-width item shrinks to `GetFitContentWidth`), with `justify-content`/`align-content` distributing leftover container space among the tracks. Delivered as staged commits; verified by `GridLayoutIntegrationTests` (geometry per stage + a taller-than-a-page pagination case), `GridTrackListGrammarTests`/`GridLineGrammarTests`, and a `css_grid` showcase rasterized in **both** PDFium and MuPDF (fixed+fr tracks, spanning, dense backfill, `auto-fill`+`minmax` responsive cards). **Accepted gaps** (filed as issues): `grid-template-areas` + named lines ([#261](https://github.com/jhaygood86/PeachPDF/issues/261) — now **implemented**, see the Recent-fixes entry above), subgrid ([#262](https://github.com/jhaygood86/PeachPDF/issues/262) — now **implemented**, see the Recent-fixes entry above; residual edges [#276](https://github.com/jhaygood86/PeachPDF/issues/276)), masonry ([#263](https://github.com/jhaygood86/PeachPDF/issues/263)), the `grid`/`grid-template` mega-shorthands ([#264](https://github.com/jhaygood86/PeachPDF/issues/264) — now **implemented**, see the Recent-fixes entry above), and the assorted sizing/placement gaps consolidated in [#265](https://github.com/jhaygood86/PeachPDF/issues/265) (six of the seven — baseline item alignment, `calc()` in track functions, spanning-item intrinsics, `min-content` vs `max-content`, indefinite-% rows, implicit tracks from placement — now **implemented**, see the Recent-fixes entry above; only writing-mode/RTL was split out to [#278](https://github.com/jhaygood86/PeachPDF/issues/278)).
