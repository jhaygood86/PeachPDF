# `FragmentPainter`: paint extracted out of `CssBox` into its own phase

_Landed 2026-07-25._

**`FragmentPainter`: paint extracted out of `CssBox` into its own phase** (follow-on to #298; closes [issue #324](https://github.com/jhaygood86/PeachPDF/issues/324)). #298 made the fragment tree layout's *output* and pointed paint at it, but the paint *code* never moved — `CssBox` still carried ~1,000 of its 3,809 lines of painting plus a `protected virtual PaintImpCore` seven subclasses overrode, so it remained the DOM node, the style store, the layout algorithm *and* the painter. Three staged commits:
1. **`StackingOrder`** (`Html/Core/Paint/StackingOrder.cs`). `StackingParticipant`/`FlattenStackingContext`→`Flatten`/`SearchForHoistableDescendants`/`GetBoxesByLayers`→`ByLayers`/`IsLocalOrderingScope` moved out of `DomUtils`, plus `ActsAsInline` out of `CssBox` — Appendix E ordering is paint-order logic, not DOM traversal. **`NeedsStackingHoist`/`IsStackingContextBox` stay in `DomUtils`**: `HtmlContainerInt.ComputeFlowFlags` calls them at *layout* time for `HasStackingHoistCandidates`. Rules moved verbatim; the ~6 stacking cases migrated from `DomUtilsTests` to `StackingOrderTests`.
2. **`FragmentPainter`** (`Html/Core/Paint/`, partials `FragmentPainter.cs` / `.Decorations.cs` / `.Text.cs`, following the `ColorGlyphPainter`/`ColrV1.cs` precedent). `Paint(g, fragmentainer)` → `PaintFragment` (transform/`clip-path`/opacity) → `PaintTagged` (the tagged-PDF choke point) → `PaintContent` (type dispatch) → `PaintBoxContent` (the generic box paint). Decoration/text helpers are `static` and take the `CssBox` whose style they read. **A painter instance owns one page**, so `HtmlContainerInt._paintedFragments`/`TryClaimForPaint`/`ResetPaintClaims` are deleted and the already-painted `HashSet<BoxFragment>` (still `ReferenceEqualityComparer.Instance`) is the painter's; `PerformPaint` reduces to constructing one. `PaintCanvasBackground` becomes a static on the painter (`PdfGenerator`'s only other paint-layer call). **Per-type content painters, not a type switch**: `IFragmentContentPainter`/`FragmentContentPainters.For` (`Content/`), with `Image`/`Object`/`Svg`/`Frame` on a shared `ReplacedFragmentPainter` base (overflow clip → background → borders → word rect deflated by border+padding → draw), and `Hr`/`Marker`/`Proxy` standalone. Each box exposes only what its painter reads (`ReplacedWord`, `SvgDocument`, `IsReplaced`, `MarkerShape`/`OwnsContentImage`, `CssProxyBox.ApplySourceGeometry`); every `PaintImpCore` override is gone. `CssBox.ResolveWordFont` stays on the box (measurement uses it too) as `internal static`. `CssBox.cs` 3,809 → 2,776 lines.
3. **Synchronous paint** (#324). The chain was `async` only because `CssBoxImage`/`CssBoxObject` re-resolved content inside it; both already resolve in `MeasureWordsSize` (a replaced element must be decoded before it can be sized), so those calls only fired when measurement hadn't run — impossible for a box that has a fragment. `ValueTask` leaves `FragmentPainter`, the content painters, `HtmlContainerInt.PerformPaint`, `HtmlContainer.PerformPaint` and the `PdfGenerator` page loop; ~23 test files drop an `await`.
**Verified rendering-identical**: all 60 TestHarness showcases are byte-identical to the pre-change build after normalizing creation date, document `/ID`, font subset tags and link-annotation UUIDs — the only residue is annotation `/M` timestamps (4 files), a strictly cleaner result than #298's own. Full net8.0 suite green (5843), CLI suite green (93). Tests: `StackingOrderTests`; the existing paint suites (`BoxShadowPaintIntegrationTests`, `ClipPathPaintIntegrationTests`, `ObjectFitPaintIntegrationTests`, `TaggedPdfPaintOrderTests`, …) drive the new painter unchanged through `FragmentPaintHarness`. **Accepted gap at the time** ([#325](https://github.com/jhaygood86/PeachPDF/issues/325), **now fixed** — see the Recent-fixes entry): `ProxyFragmentPainter` still wrote the proxy's snapshot back onto the live source boxes, because `RenderUtils.ClipGraphicsByOverflow` resolved ancestor client rectangles off the live box tree.
