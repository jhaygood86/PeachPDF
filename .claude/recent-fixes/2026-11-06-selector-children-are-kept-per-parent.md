# The children a selector sees are kept per parent, so a wide parent is not rescanned for every element

#2217 made the sibling combinators and `:nth-child` see through the anonymous boxes layout wraps content in, and did it in `CssBox.SelectorChildren` by looking for a wrapper among **all** the box's children on every call. The structural selectors ask for a parent's children once per element they test, so a zebra-striped table of N rows did an N-wide walk N times (`tr:nth-child(even)`, `tr + tr`), and `SiblingIndex`, which exists to make that O(N), was never reached for a parent that did have a wrapper (its flattened list was a fresh `List<ICssDomNode>` each time, and the index is keyed on the parent's `List<CssBox>`). `SiblingIndexTests.ZebraStripedTable_CascadeIsNotQuadraticInRows` started failing on the slower macOS arm64 runner (7 to 20 s for the large table) and, intermittently, elsewhere.

- **`SelectorChildrenView`** keeps the answer per `Boxes` list in a `ConditionalWeakTable`, as `SiblingIndex` does, for parents of at least `SiblingIndex.MinChildren` children; a narrower parent is answered by looking, which is cheaper than remembering. With no wrapper the answer is the `Boxes` list itself (what it always was); with one it is a flattened `List<CssBox>` that is built once and never changed, so the same `SiblingIndex` is kept for it too.
- **How it proves itself on each use**, since `Boxes` is mutated freely with no choke point to invalidate from: the child count and the first and last child are unchanged, and every anonymous box met on the way (a wrapper at any depth, or an empty one that layout may fill later) has as many children as when it was looked at. The second check is the one that is not obvious: layout can create the anonymous box and move children into it without the parent's list changing in count, first or last, and without it a stale "no wrapper" answer is kept. A test fails when it is removed. Left unnoticed, by design: one middle child swapped for another with the size kept, which nothing in the cascade or layout does (the same limit as `SiblingIndex`).
- `CssBox.IsAnonymousWrapper` is now `internal` and split into `IsAnonymousBox` (no element, not a pseudo-element, not a text run) and "has boxes".

Evidence: the CLI on a zebra table of 24,000 rows takes 6.2 s against 8.6 s before (12,000 rows 4.0 against 4.6 s), with the output unchanged apart from the document id; the engine, `PeachPDF`, `PeachBrackets` and PDF suites pass on net10.0 in Release; the solution rebuilds with 0 warnings. Not measured on the macOS runner itself.
