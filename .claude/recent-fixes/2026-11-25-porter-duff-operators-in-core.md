# Porter-Duff operators are PaintBlendMode members, and a canvas element is a group

**Idea.** The ten Porter-Duff operators (`SourceIn`...`Xor`, `Copy`, `Clear`) are appended to `PaintBlendMode` and a canvas says whether it composites with them (`Canvas.SupportsCompositeOperators`). A 2D canvas applies an operator to the whole region, not only the shape (`source-in` clears everything the shape does not cover), so the shape is drawn in a layer over the canvas and the *layer* is composited with the operator: `BeginLayer(new LayerOptions(blend: op, Bounds: canvas rect))`. That is one primitive every backend already had, native on the GPU where there is one. `DestinationOut` is the eraser and `Copy` replaces pixels, so no separate erase or replace primitive exists. `CanvasBitmap.RecordComposite` (a whole-canvas CPU flatten with a per-pixel loop) is gone.

**Traps found by running it.**
- Drawn directly (no layer) an operator reaches only the shape: pixels with no source coverage are untouched. The raster `BlendModes.Blend` returned early for `sa == 0`; the operators must run before that return, because `destination-in` clears where the source is transparent.
- A canvas element has to be an isolated group. First attempt: operators composited against the *page* behind the canvas, so `clearRect` turned the page white-to-black. `CanvasBitmap.Replay` now wraps a drawing that uses an operator in a `Normal` layer over the canvas bounds.
- A PDF or SVG cannot express the operators (PDF's /BM has 16 names, SVG's mix-blend-mode no Porter-Duff). `PdfCanvas.BlendName` maps them (and `Plus`) to `Normal`; before this, a new enum member would have been written verbatim as an invalid /BM name. The scripting canvas replays through `BeginRasterSurface` + `DrawRaster` for such a target, so a canvas that uses an operator is an image there and one that does not stays vector.
- Win2D: a session cannot read the backdrop. `Win2dCanvas.Composite.cs` copies the composer's target to a second render target on the GPU (a render target can be a source for another device context, not for itself), combines it with the layer through a `CompositeEffect`, crops it to the layer's bounds and puts it back with `CanvasBlend.Copy`. It does not work on a host session, inside a recording, or inside an open geometry clip (Direct2D would composite the Copy result as a layer); those draw `source-over`.
- `putImageData` with a dirty rectangle always threw (found by the parity scenes).

**Verified.** Raster, Skia and Win2D (WARP) each pass the same 12 tests: all ten operators in a layer over opaque red and blue columns, direct draw of `DestinationOut` and `SourceIn`, no leaked native resources. The 32 canvas parity scenes are pixel-identical to before except `pd-with-clip` (an antialiased clip edge). PeachDrawing.Core/.Tests/.Skia/.Win2D/.PDF/.Svg, PeachBrackets.Tests, PeachBrackets.Engine.Tests and PeachPDF.Tests pass on net10.0. Zero warnings in the touched projects.

**Not done.** CoreGraphics is mapped (`CGBlendMode` has all ten) but was not built or run: no Mac here. The offscreen surface and the retained canvas surface are the next steps of Phase 1; `ImageBitmap`/`OffscreenCanvas` are still CPU wrappers.
