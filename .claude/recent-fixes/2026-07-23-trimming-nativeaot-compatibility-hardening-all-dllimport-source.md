# Trimming + NativeAOT compatibility hardening; all `DllImport` → source-generated `LibraryImport`

_Landed 2026-07-23._

**Trimming + NativeAOT compatibility hardening; all `DllImport` → source-generated `LibraryImport`.** *(The `src/PeachPDF.AotSmokeTest/` console app referenced below was later removed — the `peachpdf` CLI is the AOT smoke test now; see the entry above.)* The library now sets `IsAotCompatible=true` (`src/PeachPDF/PeachPDF.csproj`, alongside the pre-existing `IsTrimmable`/`EnableTrimAnalyzer`), turning on the AOT + single-file analyzers so IL2xxx/IL3050 surface at build time. Both TFMs build analyzer-clean and a real `PublishAot` of a new `src/PeachPDF.AotSmokeTest/` console app (renders HTML→PDF, exits non-zero on failure) compiles to a native binary and produces a valid PDF — proving the *whole* pipeline (MimeKit `HtmlTokenizer`, CSS/layout, StbImage, fontconfig, PDF writer) is AOT-safe with zero trim/AOT warnings, dependencies included. Changes:
1. **All 21 P/Invokes converted to `[LibraryImport]`** (the two interop files, the only native surface). `PdfSharpCore/Utils/LinuxSystemFontResolver.cs` (fontconfig, already `static partial`): each `[DllImport]…extern` → `[LibraryImport]…static partial`; the three nested `SafeHandle` types (`FcPatternHandle`/`FcObjectSetHandle`/`FcFontSetHandle`) needed their parameterless ctor made **`public`** because the source generator constructs return/out handles via `Activator.CreateInstance<T>()` (a private ctor is fine for classic DllImport marshalling but not for the generated `SafeHandleMarshaller<T>`). `Network/MimeTypeResolver.cs` (Windows Shlwapi + macOS CoreFoundation/CoreServices): the outer type and nested `NativeMethods` made `partial`; `AssocQueryStringW`'s unsupported **`StringBuilder` out-param rewritten to `[Out] char[]?`** with `StringMarshalling.Utf16` (replacing `CharSet.Unicode`/`ExactSpelling`), and its caller `TryGetFromWindows` now allocates a `char[]` and slices at the NUL terminator. `LibraryImport`'s generated code is `unsafe`, so **`AllowUnsafeBlocks=true`** was added (SYSLIB1062) — no hand-written unsafe code exists.
2. **`Marshal` AOT hotspot removed** (`LinuxSystemFontResolver.Read`): `Marshal.PtrToStructure<FcFontSet>` (annotated `[RequiresDynamicCode]` → IL3050) replaced with direct blittable field reads (`Marshal.ReadInt32`/`ReadIntPtr` at offsets 0/4/8); `Marshal.SizeOf<IntPtr>()` → `IntPtr.Size`.
3. **`PdfSharpAdapter.GetColorInt`**: reflective `Enum.TryParse(typeof(KnownColor), …)` → generic `Enum.TryParse<KnownColor>` (covered by new `PdfSharpAdapterColorTests`).
4. **Dead reflective/read-only code deleted.** `PdfInternals.CreateIndirectObject<T>` (broken — `ctorInfo` always null, zero callers) and the unused `PortableExtensions.GetProperties(this Type)` extension are gone. Per the fork being **write-only** (no `PdfReader`), the two genuinely-dead reflection-adjacent reader pieces were removed: `PdfDictionary.DictionaryElements.CreateValue` (zero callers — `GetValue` only ever routes through `CreateDictionary`/`CreateArray`) and the `PdfOutline` **import** cluster (the `PdfOutline(PdfDictionary)` transformation ctor + `Initialize`/`SplitDestinationPage`/`InitializeChildren`, reachable only from each other and never from the write path, which uses the `(PdfDocument)` ctor + `PrepareForSave`/`CreateDestArray`). **Deliberately kept** (write-reachable and already `[DynamicallyAccessedMembers]`-annotated, so AOT-safe as-is, *not* deletable): the `DictionaryMeta`/`KeyInfoAttribute`/`GetValueType`/`CreateDictionary`/`CreateArray` metadata reflection — it is load-bearing for `PdfDocument.Save` (first `VCF.Create`/`CreateIndirect` access of `/Root`, `/Pages`, `/Resources`, fonts, … reflectively instantiates the typed `Pdf*` object from its `[KeyInfo]` map); and the `Enum.Parse(defaultValue.GetType(), …)` in `GetEnumFromName` (reachable via the public `PageLayout`/`PageMode` getters, and not `RequiresDynamicCode`). Full net8.0 suite green (5557 tests); `docs/getting-started.md`/`README.md` gained a "Trimming and Native AOT" note. The solution was also converted from `PeachPDF.sln` to the XML `PeachPDF.slnx` format (`CONTRIBUTING.md` updated).
