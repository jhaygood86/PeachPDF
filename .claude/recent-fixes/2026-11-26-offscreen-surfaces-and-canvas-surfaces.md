# Offscreen surfaces: a canvas keeps a bitmap of its backend instead of replaying its history

**Idea.** `PeachDrawing.Core.OffscreenSurface` (from `Canvas.CreateOffscreenSurface`) is a bitmap of the canvas's own backend that stays open for drawing: a `Canvas` over it (one unit a pixel), `CreateSnapshot()` (an `Image` of the content now, drawable on a canvas `CanDraw` accepts, no read back), `ReadPixels()` (the one CPU read), `Clear()`. Win2D keeps a `CanvasRenderTarget` and the canvas over it is its own backdrop, so it composites with the Porter-Duff operators and a snapshot is a device-side copy. Raster keeps a pixel buffer, CoreGraphics a `CGBitmapContext` (not built here). PDF and SVG answer `null`, so a caller keeps a recording. A script canvas opts in with `HtmlDocumentOptions.CanvasSurfaces`: each `<canvas>` then draws into a surface as the script draws, reads `getImageData`/`toDataURL` from it, and the page shows a snapshot (taken once per change), instead of replaying the whole recording at every paint. The recording is still kept for a PDF, an SVG or another backend.

**Traps found by running it.**
- Skia is a CPU raster `SKSurface`, not a GPU one. A surface on the GPU may only be drawn on the thread that owns its GL context, and a script draws on its own thread; the existing retained layer records a measured Android failure for drawing a GPU target in the frame. Each changed frame is therefore one texture upload (`SkiaImage.GetImage(gpu)` on the drawing thread). A real GPU surface needs the drawing deferred to the paint thread: not done.
- A canvas created with `countsAsTile: true` takes the tile count back when disposed, so the creator must add it (`Counts.Tile(1)`); otherwise `Counts.Total` goes to -1.
- A page's blend modes must act on the canvas, not on the page behind it. The recorded replay applied `lighter`/`multiply` against the page (white page: wrong; the surface was right). Any drawing that composites with anything but `source-over` is now replayed as a group (`CanvasBitmap._needsGroup`); only a Porter-Duff operator on a canvas that cannot do them takes the raster seam (`_usesOperators`). Found by comparing the surface page with the recorded page: every scene agrees to under 1 level except the two blend scenes, which were 10.
- `ScriptCanvasPainting` gained `Owner` (what the drawing holds); `PublishCanvasPaintings` disposes the previous run's owners, the container disposes the rest, and a width/height change disposes the old bitmap.
- A helper's local named `Scene` shadowed the test `Scene` class; the shell's heredoc broke on long C# bodies: use the file tools for those.

**Verified.** The same seven tests pass on Raster, Skia and Win2D (WARP): keeps content across reads, snapshot independent of later drawing, clear, composites with operators, resources released (`Counts.Total` 0), non-positive size is null. 32 canvas scenes shown from a surface are within 0.8 levels of the recorded picture; reading back, resizing and `drawImage` of a canvas (a snapshot) agree. html-canvas WPT: 1,502 files, 2,593 subtests (+8 from the group fix); floor 2,583. Drawing, engine and PDF suites pass on net10.0; zero warnings in the touched projects.

**Not done.** GPU-resident Skia surface (see above); CoreGraphics unbuilt; `OffscreenCanvas`/`ImageBitmap` still wrap CPU images (Phase 7); `drawImage` of a canvas still replays the other canvas's recording rather than sampling its surface; the views (WinUI, Avalonia, Android, Apple) do not set `CanvasSurfaces` yet.
