# The container travels with the §4.3 movers too

_Landed 2026-07-26._

**The container travels with the §4.3 movers too** ([issue #365](https://github.com/jhaygood86/PeachPDF/issues/365), [CSS Fragmentation 3 §3.1](https://www.w3.org/TR/css-break-3/#break-between)). #303 made a break point before a container's first in-flow child the container's own, but only for the *declared* breaks. The retroactive movers — `break-inside: avoid`, §2 monolithic content, `orphans`/`widows` — went through `EarlyBreak.Discover`, which consulted the propagation anchor **only where the anchor yielded a keep-with-next run**, so `<div class="card"><table>…</table></div>` relocated the table and left the card spanning the boundary, painting an empty copy of its own background, border and padding on the page the table had just left.

**The guard that was there is a fit test, and the fix is to ask it of the anchor rather than to remove it.** Redirecting regardless bypasses `CanBeLaidOutAgain`'s destination-fit check — `TryRestartAt` has none of its own, so a box laid out again where it still does not fit breaks again from its new top, opens another pass, and is re-asked: #332's 100,000-page runaway. The anchor is mid-layout when the question is asked, so what is measured is exactly what the run case already measured — from the anchor's own top down to the bottom of the box that broke, since the anchor's own `ActualBottom` is not settled. A container that does not fit is left behind, which is a new rung on `BreakRelaxation`'s ladder (`ContainerLeftBehind`) rather than a silent skip.

**One latent defect had to be fixed for the redirect to work at all, and it is the interesting half.** `LayoutBlockChildren` applies the pass's incoming resumption record to the child at `start`, and `TryRestartAt` re-runs from the restart head — so where the head **is** that child, the loop re-applied the record on the re-run and told a box being *re-placed* to *continue*. It kept the line boxes an earlier fragmentainer produced and re-finalized them from the resumed index: `An item with the same key has already been added` out of `CssLineBox.AssignRectanglesToBoxes`, #374's crash from a third direction. Pre-existing but nearly unreachable before, since a run head is normally *before* the box that broke; §3.1 propagation makes it ordinary, because the container that travels is the very box the pass resumed into. Fixed with a `resumeConsumed` latch — the record is consumed once per loop.

Tests: `EarlyBreakLayoutIntegrationTests` (+3 — the container travelling for both `break-inside: avoid` and monolithic content, and the relaxation case where it is too tall for the destination and only the box moves). Each guard verified load-bearing by neutralizing it individually. Full net8.0 suite green (6323); **100% diff coverage**. **All 62 pre-existing showcases are pixel-identical**, which is the expected result — none of them relocates a container's first child; `paged_media_monolithic_content` gained a section that does, and it **prints the empty panel stub on the unfixed build**, verified in both PDFium and MuPDF.
