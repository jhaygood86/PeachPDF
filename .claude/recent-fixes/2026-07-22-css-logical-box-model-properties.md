# CSS logical box-model properties

_Landed 2026-07-22._

**CSS logical box-model properties** ([CSS Logical Properties & Values Level 1](https://www.w3.org/TR/css-logical-1/)). `margin-block`/`margin-inline`(+`-start`/`-end`), `padding-block`/`padding-inline`(+`-start`/`-end`), `inset`/`inset-block`/`inset-inline`(+`-start`/`-end`), `border-block`/`border-inline` and their `-start`/`-end` edge shorthands, per-edge `border-*-{width,style,color}` longhands, and 2-edge `border-{block,inline}-{width,style,color}`. PeachPDF is always LTR/horizontal-tb, so each maps 1:1 to a physical property (block-start→top, block-end→bottom, inline-start→left, inline-end→right). **The whole feature is Layer A only** — logical names *export to the existing physical longhand names* (`margin-top`, `border-top-width`, `top`, …) via the CSS-OM: single-value longhands are `AddLonghand` aliases to the physical longhand class (the `word-wrap`→`OverflowWrapProperty` precedent), and shorthands are new `ShorthandProperty` classes (`src/PeachPDF/CSS/StyleProperties/Logical/`) with `.Periodic(...)`/`WithAny(...For(...))` converters targeting the physical longhand labels. So Layer B (`CssUtils`/`CssDefaults`) needs **zero** changes — it already handles every physical longhand. **One serialization subtlety:** logical shorthands must be excluded from shorthand *reconstruction* when a declaration block is serialized (else `margin-top`+`margin-bottom` would collapse into `margin-block`, changing existing `ToCss` output) — `PropertyFactory.AddLogicalShorthand` records them in `_logicalShorthands`, and `GetShorthands` (the serialization query) filters them out while `CreateShorthand`/`GetLonghands`/`IsShorthand` (parsing) still work. See `LogicalBoxModelIntegrationTests` (each logical→physical mapping + real layout geometry) and `LogicalPropertySerializationTests` (no logical reconstruction; physical `border` still reconstructs). **Accepted gap:** the logical→physical mapping is *fixed* LTR/horizontal-tb — it does not consult the element's `direction`/`writing-mode`, so under `direction: rtl` `inline-start` still resolves to `left` (spec requires `right`), and vertical writing modes are mismapped. This is a genuine [CSS Logical 1 §1.2/§2](https://www.w3.org/TR/css-logical-1/) deviation, inherent to a fixed-orientation renderer whose layout engine has no vertical writing modes and only partial RTL (inline word-box mirroring via `CssLayoutEngine.ApplyRightToLeft`). Filed as [issue #215](https://github.com/jhaygood86/PeachPDF/issues/215).
