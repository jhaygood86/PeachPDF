# var() in a shorthand no longer overrides later longhands; closed details content is hidden by a box, not a rule

Found by loading peachpdf.net in the WinUI demo (three artifacts: gradient text drawn as a box, open menus).

**Gradient text as a box.** `background: linear-gradient(..., var(--x)); background-clip: text; color: transparent` painted a gradient rectangle behind transparent text. Not a text-outline or canvas problem (the raster and Win2D canvases clip correctly): the cascade applied every declaration containing `var()` after all plain ones, so the deferred `background` shorthand reset `background-clip` to `border-box` even though `background-clip: text` was written after it. `PendingVarMap` (Html/Core/Parse) now keeps the write order: deferred declarations resolve in source order, and a longhand written plainly after a deferred shorthand is not overwritten by the shorthand's expansion. Trap: the first test of this passed because a box of the same colour as the text also satisfied "enough red pixels"; compare against the literal-colour version instead.

**Open menus.** The UA rule `details:not([open]) > :not(summary) { display: none }` lost to an author `display: flex` on the panel. The HTML Standard hides closed content with `content-visibility: hidden` on the second slot (`::details-content`), which no author `display` can undo. `DomParser.WrapDetailsContents` now wraps everything after the first `<summary>` in a block (`CssBox.IsDetailsContent`) and, while the element is not open, forces the contents `display: none` after the cascade. `details` and `summary` also became `display: block` in the UA sheet (they were inline, which made the box vanish when an inline sibling followed).

**Also:** `HtmlDocument` queries and `PaintPageAsync` tolerate the moment a restyle has dropped the layout (a host that keeps handling input while awaiting a restyle crashed on a stale page index).

**Not done:** `content-visibility` as a property and `::details-content` styling (see the accepted-gap note).

**Flex item that is bare text was as tall as its words stacked.** `CssLayoutEngine.GetBoxHeight` took `box.Words.Sum(w => w.Height)` as a minimum height. A box that holds its words itself (the anonymous box around a flex item's loose text) with five words on one line was therefore five line-heights tall, so the row was too, and a centered image sat in the middle of that. It made peachpdf.net's footer logo drop below its text and turned Peach State's pill buttons into tall ovals with the label at the top. Now `Max`: words share a line, and the lines' height is already in `ActualBoxSizingHeight`. Trap: an ordinary block never showed it, because its words live in anonymous child boxes and this branch needs `box.Words` on the box itself; the flex tests all used element items. Test: `FlexboxIntegrationTests.AFlexItemThatIsBareText_IsAsTallAsItsLines...`.

**Auto margins on a flex or grid container were resolved against a width of 0.** Peach State's header wrapper is `.wrap { width: 100%; max-width: 1160px; margin: 0 auto }` on a `display: flex` box, and was pushed right by half the page. A block's offset is decided before the box resolves its own inline size (`CssBox` placement seam), so `CssLayoutEngine.FreeInlineSpace`'s definite-width branch read `ActualBoxSizingWidth` of a box that was still unsized: 0 for a flex or grid container, so the two auto margins split the whole containing block. A plain block only worked because an earlier generation had already sized it. The branch now works a length width out from the style (clamped by max-width then min-width, as the auto-width branch does) for flex and grid containers. Test: `FlexboxIntegrationTests.AutoMarginsCenterAContainerByItsUsedWidth_WhateverItsDisplay`.

**A flex item whose only content was an `inline-flex` button collapsed to 0 wide.** Peach State's nav is `<li><a class="btn">Connect With Us</a></li>` in a flex row. `CssLayoutEngineFlex.MeasureItem` measured an inline-only item from the words on its line, but an atomic inline box (inline-flex, inline-grid, inline-block, inline-table) is on the line as a box, not as words, so the item measured 0 (+ the 0.01 epsilon) and its button overlapped the previous item. Items with such a child are now measured from their content like a block child. Test: `FlexboxIntegrationTests.AFlexItemWhoseContentIsAnAtomicInline_IsAsWideAsThatInline`. (An `inline-block` child happened to work through a later pass; it now takes the same path.)

**A flex row's intrinsic width left out its items' declared widths.** Peach State's nav chevron is `<a class="link">Services <span class="caret"></span></a>` with `.caret { width: 7px; height: 7px; border-right/bottom: 2px }`. When the link (a flex container that is itself a flex item) was sized from its content, `CssBox.GetMinMaxSumWords`'s flex-row branch measured each item with `GetMinMaxWidth`, which deliberately leaves a box's own declared width out, so the empty caret contributed 0. The link came out too narrow, shrank the caret to its 2px border, and the chevron drew as a slash. A row now counts each item's declared (non-percentage) width, clamped by min/max-width. Test: `FlexboxIntegrationTests.AnEmptyFlexItemWithADeclaredWidth_...`.

Evidence: PeachBrackets.Tests (593) and PeachBrackets.Engine.Tests (17,961), PeachPDF.Tests (1,586), PeachDrawing.PDF.Tests (1,536) pass; demo screenshots of peachpdf.net before and after.
