# Android: touch exploration and ranges

- **Engine: `AccessibilityNode.Value`/`ValueMin`/`ValueMax`/`ValueText`.** Read in `ReadRange` for progress bars, meters, sliders, scroll bars and spin buttons: native `value`/`min`/`max` for `progress`, `meter`, range and number inputs, `aria-valuenow`/`-min`/`-max` otherwise. A `progress` with no value has `Value == null` (indeterminate); a `progress` or `meter` defaults to 0..1 and everything else to 0..100; a max below the min is raised to it so a host never gets an empty range; a range input with no value starts at the middle of its range, as the platform control does.
- **Hover is the whole of touch exploration.** TalkBack decides what to read from `TYPE_VIEW_HOVER_ENTER` events the host sends; `OnHoverEvent` finds the innermost node under the finger (`GetAccessibilityNodeAt`, then up to the nearest node the tree reads, since text runs and other leaves are not in the virtual-view table) and sends exit for the old part and enter for the new one. It does nothing unless touch exploration is on.
- **Not tried with TalkBack.** The events follow the platform's documented protocol but were not driven here; check on a device that a finger sweep reads parts in order and that lifting the finger sends the exit.
- **`ACTION_SET_PROGRESS` is compared by id**, because the binding's `Action` enum has no member for it (the action is an `AccessibilityAction` object, nullable in the binding).
