# Full SVG `<text>` layout model

_Landed 2026-07-24._

**Full SVG `<text>` layout model** ([issue #188](https://github.com/jhaygood86/PeachPDF/issues/188) closed; the text-positioning half of [#289](https://github.com/jhaygood86/PeachPDF/issues/289) folded in). Replaced the whole-run cursor model with a real SVG text-layout pipeline (build side `SvgTreeBuilder`, model `SvgElement`, render side `SvgRenderer`, plus `SvgValueParsers`/`SvgShapeToPath`). Pieces:
1. **Per-character `x`/`y`/`dx`/`dy`/`rotate` lists** (SVG 1.1 §10.4). New `SvgValueParsers.ParseLengthList`/`ParseNumberList`; `SvgTextElement` gained `XList`/`YList`/`DxList`/`DyList`/`RotateList` (scalars kept as the leading value for the fast path). At render, a `<text>` subtree is flattened to an addressable-character stream (`SvgRenderer.FlattenRun` → `GlyphInfo`), each run's lists assigned by subtree-relative index **innermost-wins** (`AssignPositionLists`; a nested run's own `FlattenRun` assigns first, so an ancestor list only fills unclaimed slots — `rotate`'s last value persists across its run). `LayoutGlyphs` advances a pen (absolute `x`/`y` starts a **text chunk**), then applies `text-anchor` **per chunk**. `PaintGlyphs` groups consecutive same-run, unrotated, in-flow characters into one selectable `DrawString` and paints anything positioned/rotated/gradient/stroked per glyph (each `rotate` about its own position). Bounds recompute from the same flatten (`MeasureTextBounds`), so the opacity-group tile can't drift.
2. **Cross-ancestor font inheritance + relative font-size** (gap 2). A lightweight `FontContext` (family/size/bold/italic — no `RFont`) now threads through `BuildElement` + all six container builders (`BuildGroup`/`BuildAnchor`/`BuildSwitch`/`BuildUse`/`BuildSymbol`/`BuildNestedSvg`), so a `<text>` inherits `font-*` from any ancestor `<g>`/`<svg>`/`<use>`. New `ComputeFontContext` (shared by containers and text) + `ResolveFontSize` resolve `em`/`ex`/`%` against the parent's used size and `rem` against the root's (`_rootFontSize`), replacing the fixed-16px/`ViewportDiagonal` font-size approximation.
3. **Whole-subtree whitespace collapsing + source-order interleaving** (gap 3). `SvgTextElement` now holds an **ordered `Content`** list (`SvgTextFragment` | `SvgTextSpan`, with `Text`/`Spans` as computed views), built by walking a new `ISvgSourceNode.ContentNodes` (loose text + element children in document order — implemented over `XElement.Nodes()` / `CssBox.Boxes`). A single `TextWhitespaceState` threaded through the build collapses whitespace across the whole `<text>` subtree (a boundary space lands on the following run's leading edge; only the subtree's leading/trailing whitespace is trimmed), and text authored *after* a child element keeps its place.
4. **`<textPath>` completion** (#289's positioning half). `RenderTextPath` now flattens the textPath's own text **plus nested `<tspan>`s** along the path (fixes the "`ABC` renders A+C" drop), applies per-character `rotate`/`dx`/`dy`, and honors `side="left"|"right"` (right reads from the far end, glyphs flipped 180°). New `SvgShapeToPath` lets a `<textPath>` reference a basic shape (`rect`/`line`/`polyline`/`polygon`/`circle`/`ellipse`), not just a `<path>`.
Verified in **both** PDFium and MuPDF (`svg` showcase section 19: ancestor-`<g>` font incl. `1.5em`, per-character x-list + per-glyph rotate, nested restyled `<tspan>` along a curve). Tests: `SvgTreeBuilderTests` (lists, font inheritance/em/%, whitespace/interleave, textPath side/shape/nested), `SvgTextOutlineTests` (per-glyph vs grouped-selectable paint, nested-tspan-along-path), `SvgIntegrationTests` (content-stream: inheritance changes rendering, em-against-ancestor, per-char shows, whitespace preserved, textPath nested glyphs). Docs: `docs/supported-svg-features.md` Text section. **Remaining accepted gaps** stay under #289 (see the [accepted-gaps entry](../accepted-gaps/svg-outlined-text-textpath-residuals.md)): `method="stretch"`/`spacing="auto"`, `userSpaceOnUse` per-glyph paint continuity, `objectBoundingBox` clip/mask static bbox on `<text>`, CFF/bitmap outline extraction, non-adaptive along-path flattening.
