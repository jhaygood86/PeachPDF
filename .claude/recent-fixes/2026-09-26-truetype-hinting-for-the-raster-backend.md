# TrueType hinting for the raster backend

`Typeface.TryGetOutline(glyph, OutlineRequest, ...)` returns a glyph fitted to the pixel grid by the font's own TrueType instructions,
and `PdfGenerateConfig.TextHinting` makes the raster backend draw the text it rasterizes with those outlines. The interpreter is a C# port
of FreeType 2.14.3's (`Internal/Hinting/FreeType/`, FTL licensed, `PORTING-NOTES.md` there lists every file and difference).

## What the load-bearing idea was

- **Everything FreeType-derived sits in one directory**, so the licence obligations (FTL.TXT unaltered, original headers plus a "ported and
  modified" line, the credit line in the docs, the CLI `--license`, the release archives and the Blazor demo) are one list, and the rest of
  the package is untouched by them. Only the interpreter/loader files were read; never the auto-hinter or a GPL-only file.
- **Bit-exact means 32-bit `long`.** FreeType's `FT_Long`, `FT_Pos` and `FT_F26Dot6` are C `long`, which is 32 bits on the Windows build
  the goldens come from; the port uses `int` with `unchecked` and 64-bit intermediates where FreeType has them. Rounding, `MulFix`,
  `DivFix`, `MulDiv` and the CORDIC `Hypot` were compared in isolation first (`HintingArithmetic.golden.json.gz`).
- **Immutable per-size state.** FreeType lets glyph programs write the cvt, storage and twilight zone for the *next* glyph. Here the state
  `prep` leaves is frozen and every glyph starts from a copy, and the goldens are generated by re-running `prep` before every glyph
  (`FT_Set_Char_Size` each time), which is the behaviour the copy reproduces. Without that, a glyph's outline would depend on load order
  and could not be cached or shared between threads (a test loads 390 glyphs forwards then backwards and compares).
- **Two interpreters.** `Standard` is v40 (vertical hinting only, backward-compatibility mode, `INSTCTRL` and tricky-font handling), fpgm
  run once per size before the mode is set; `Monochrome` is v35.

## What running it showed

- A random-opcode fixture font (`assets/fonts/HintingOpcodes.ttf`, from `generate_hinting_opcode_fixtures.py`, with composites) agrees
  with FreeType exactly and exposed three real bugs the bundled fonts did not: the maxp offsets, a missing code-range setup for glyph
  programs, and `SHZ` on a composite writing past the zone (FreeType relies on its allocation; here the loop is clamped to the zone).
- The existing glyf decoder threw `IndexOutOfRangeException` on scrambled tables; hostile-font tests found it, and
  `GlyphOutlineDecoder.TryGetGlyphOutline` now catches it.
- A hostile font must degrade, not throw: instruction, loop-work and recursion limits, bounds-checked tables, and any `HintingException`
  becomes "the scaled design outline, `IsGridFitted` false". A randomized fuzz test with a fixed seed runs in under a second.
- **A budget per glyph, not per program run.** FreeType counts instructions per run, so a composite glyph (each component runs its own
  program) multiplies the limit, and a composite of composites that each name the next glyph many times is exponential (a font of a few
  kilobytes, 30 components over 6 levels, is 30^6 loads). The instruction and loop-work budgets are shared by everything one glyph load
  runs, one load may read 1,024 glyphs, and the plain-outline decoder (`GlyphOutlineDecoder`) has the same component budget. Loop work
  also counts flips, `ROLL` and skipped code. Caches are bounded by count and, for glyphs, by weight (16 sizes, 4,096 glyphs, 1M weight).
- **No instructions, no grid fitting.** A TrueType font with no `fpgm`, `prep` or glyph programs is not "fitted": scaling it is all the
  loader would do, so `IsGridFitted` stays false and callers can tell (`TtFace.HasInstructions`).
- **Hinted edges are on pixel edges only if the baseline is.** The raster backend snaps the baseline to a whole device pixel for a
  grid-fitted glyph and maps the device-space outline back through the inverted transform; without that, crisp glyphs land half a pixel
  off and look no better than unhinted ones. Only a pure scale/translate transform is hinted.

## Deliberately not done

CFF hinting, the auto-hinter, `cvar`, bit-exact variable fonts, `gasp`/`LTSH`/`VDMX` and non-square pixels are accepted gaps (see
`.claude/accepted-gaps/text-hinting-*`). Layout, the PDF path and glyph advances used by layout stay unhinted, so nothing about a PDF's
text changes with `TextHinting`; `TextHintingPdfTests` compares whole files with hinting unset, `None` and each mode.
