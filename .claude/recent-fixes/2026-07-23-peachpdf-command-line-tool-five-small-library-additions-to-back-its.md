# `peachpdf` command-line tool + five small library additions to back its options

_Landed 2026-07-23._

**`peachpdf` command-line tool + five small library additions to back its options.** A new `src/PeachPDF.Cli/` project (net10.0-only, NativeAOT-published, conventional command-line argument grammar) renders HTML→PDF from the shell; it is also the library's AOT smoke test now, so `src/PeachPDF.AotSmokeTest/` was **removed** (its `.slnx` entry too). The parser (`ArgumentParser`, hand-rolled/reflection-free for AOT) recognizes only the options that map cleanly onto PeachPDF — any other flag is an `unknown option` error. `CliRunner` translates parsed options → `PdfGenerateConfig` + the right `RNetworkLoader` (file/URL/MHTML/stdin), combining multiple inputs into one PDF; `CliNetworkLoader : FileUriNetworkLoader` (so the adapter routes `file:` to it) enforces `--no-local-files`/`--no-network` and serves `http(s)` via a configured `HttpClient` (timeout/headers/UA/basic-auth/proxy/`--insecure`). `--show-license`/`--credits` print `LICENSE`/`THIRD-PARTY-LICENSES.md` embedded as manifest resources. Default page size is **US Letter**. The five enabling library changes (each default-unchanged so existing behavior is byte-identical): (1) `PdfGenerateConfig.Metadata` (new `PdfDocumentMetadata` — Title/Author/Subject/Keywords/Creator; each non-null field overrides the HTML-extracted value, applied in `ApplyDocumentMetadata`); (2) `--pdf-lang` → existing `PdfGenerateConfig.DefaultLanguage` (no library change: it already flows to the catalog `/Lang` when the document declares no `<html lang>`, and a document's own `<html lang>` still takes priority); (3) `PeachPdfCssContent.AddStyleSheet(string)` (stores the `RAdapter`, parses into the existing `CssData`, invalidates its lazy index via new `CssData.InvalidateIndex()`) — the CLI layers each `-s` sheet with last-wins; (4) `PdfGenerateConfig.Media` (default `"print"`) → `HtmlContainerInt.Media`, replacing the hardwired `"print"` at `DomParser.cs`'s media resolution (`--media`); (5) `PdfGenerateConfig.IgnoreAuthorStyleSheets` → `HtmlContainerInt`, gating whether `CascadeParseStyles` collects the document's own `<style>`/`<link>` author sheets (`--no-author-style`). Cross-platform NativeAOT release binaries (win-x64/arm64, linux-x64/arm64, osx-arm64) are built by a new `.github/workflows/release-binaries.yml` (native runners per RID, triggered on `release: published` + `workflow_dispatch`) and attached to the GitHub Release. CLI tests live in `src/PeachPDF.Cli.Tests/` (net10.0); the library additions are covered by `PeachPDF.Tests` (`PdfMetadataOverrideTests`/`CssContentAddStyleSheetTests`/`MediaTypeConfigTests`), and `test.yml` runs both into one coverage dir. Docs: new `docs/cli.md`, cross-linked from `README.md`/`docs/getting-started.md`. No new showcase (a CLI adds no new *rendering* capability).
