# Forced colors is applied in the Actual*Color getters; font scale is a root font size

- **Where it hooks in.** The colours painting reads all come from `DerivedStyle.ActualColor`, `ActualBackgroundColor`, the four `ActualBorder*Color`, `ActualOutlineColor` and `ActualColumnRuleColor`. Each passes its cached result through `ForcedColorsAdjuster`, which returns it untouched unless `Preferences.ForcedColors` is on and `forced-color-adjust` allows it. Adjusting the *cached* value (not the cascade) keeps `currentcolor`, inheritance and every colour function working, and costs one null check per read outside the mode. A user `!important` style sheet was rejected: it cannot honour `forced-color-adjust: none`.
- **Kind of element** (link, button, field, mark) is found by walking up from the box to the nearest `a[href]`, `button`/`select`, `input`/`textarea` or `mark`, because forced colors replaces inheritance.
- **Not done:** gradient backgrounds are not dropped, `inline-block` images and SVG `fill`/`stroke` are not recoloured, and the system colour keywords always read as the light palette (the static colour table has no per-document state). `<input type=button|submit|reset>` counts as a field, not a button.
- **Font scale** is `html { font-size: N% }` added to the user style sheet, like text spacing, so it is ignored when `StyleSheet` is set and scales only text sized relative to the root, as a browser's font size setting does.
- **Test fixtures use `pt` and `@page { margin: 0 }`**: the bitmap canvas is one pixel per point and the default page margin shifted the first version of the pixel assertions by 21.5 points.
