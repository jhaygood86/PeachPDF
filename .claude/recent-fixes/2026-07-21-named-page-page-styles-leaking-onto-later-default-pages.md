# Named-page `@page` styles leaking onto later default pages

_Landed 2026-07-21._

**Named-page `@page` styles leaking onto later default pages** (issue #126): after a `page: <name>` element ended, content reverting to the default (`auto`) page kept the named page's margins and margin-box (`@top-*/@bottom-* { content: none }`) suppression. Root cause: the used value of `page` was resolved **flow-based** — the `NamedPageElements` registry (`HtmlContainerInt.ActivePageName` = last registered name) was append-only and forward-sticky, only ever recording *named* assignments and never a reversion, so once a name registered it stayed active forever. Per CSS Paged Media Level 3 §3 the used value is **tree-based**: a box's own `page` unless `auto`, else its parent box's used value (root `auto` → `""`). Fix: `CssBox.PerformLayoutImp` now computes a per-box `UsedPageName` top-down (new `CssBoxProperties.UsedPageName`), forces a break on any used-name *transition* (`pageNameChanged`, now including a reversion whose used name comes from an un-named ancestor), and registers the *used* name — including an empty-string reversion entry — so `PageRuleResolver.ActiveNameAt*` and the geometry/margin-box consumers naturally revert. Registration stays gated on `hasExplicitPageName || pageNameChanged` (old behavior + reversions) so a same-named box relocated by the table pre-check still has an entry the tail can re-sync. See `NamedPageLayoutIntegrationTests`/`NamedPageGeometryAttributionTests`/`PageRuleResolverTests`. Out-of-scope follow-up (flex/table/multicol reversion): [issue #166](https://github.com/jhaygood86/PeachPDF/issues/166), noted under accepted gaps.
