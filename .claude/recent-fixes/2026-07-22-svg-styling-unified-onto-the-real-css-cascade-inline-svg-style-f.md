# SVG styling unified onto the real CSS cascade; inline `<svg><style>` fixed

_Landed 2026-07-22._

**SVG styling unified onto the real CSS cascade; inline `<svg><style>` fixed** (issues #159, #192): the SVG-local mini stylesheet (`SvgStyleSheet`, now deleted) is retired — SVG styling matches through PeachPDF's **full selector engine** (combinators, attribute selectors, structural pseudo-classes) with `var()` and `calc()`, for both inline and standalone SVG. The selector matcher (`CssData.DoesSelectorMatch` family + `GetStyleRulesByOrigin`) was generalized from `CssBox` onto a new `ICssDomNode` interface (`src/PeachPDF/Html/Core/ICssDomNode.cs`) — implemented by `CssBox` (explicit members; `NameComparison => InvariantCultureIgnoreCase`, HTML behaviour byte-identical) and by two SVG-flavored adapters (`SvgCssBoxDomNode` over an inline `CssBox`, `SvgXmlDomNode` over a standalone `XElement`; both `NameComparison => Ordinal` with case-sensitive `GetAttribute`, so SVG matches **case-sensitively** per XML/Selectors 4 §6 while HTML stays case-insensitive). The `::before`/`::after`/`::marker`/`::first-letter` *synthesis* branch stays gated behind `node is CssBox`. `var()` resolution (`DomParser.SubstituteVarReferences`) was extracted to `CssVarResolver` (takes `ICssDomNode`); `calc()` in SVG lengths delegates to `CssValueParser.ParseLength` (converting between SVG px and the parser's points via `1px = 0.75pt`). `SvgTreeBuilder.ResolveStyledAttr` keeps precedence `style=""` > matched author rules (`ISvgSourceNode.GetMatchedCssDeclarations`, var-resolved) > presentation attribute; `fill`/`stroke` are deliberately **not** made cascaded `CssBox` properties (avoids the presentation-attr precedence regression from `TranslateAttributes` and the per-property plumbing). Inline SVG participates in the HTML document cascade (an HTML `<style>` rule matching SVG elements applies — SVG 2 §6); standalone SVG is styled only by its own `<style>` (an SVG-local author `CssData` built in `ImageLoadHandler.LoadSvgFromStream`/`SvgTreeBuilder.BuildImage`, with a small custom-property cascade for `var()`). **Real cause of #159** (the old "MimeKit hoists the `<style>`" note was a misdiagnosis — the tokenizer keeps it under `<svg>`): a `DomParser` block-inside-inline correction reparented the inline SVG's foreign-content children because `ContainsInlinesOnlyDeep` descended *into* the replaced `CssBoxSvg` and saw its display:none `<style>` as block-in-inline content; fixed by treating a replaced element (`CssBoxImage`/`CssBoxSvg`) as an atomic inline leaf there, and by guarding the six restructuring `Correct*` passes to not descend into `CssBoxSvg` (inline SVG is foreign content, opaque to HTML box normalization). See `SvgIntegrationTests` (inline/standalone `<style>`, HTML-`<style>`→SVG, combinator/attr/structural selectors, case-sensitivity ±, `var()`, `calc()`, precedence, standalone isolation), `SvgCssDomNodeTests`, `SvgValueParsersTests` (calc). Residual gaps: em/rem-relative `calc()` approximation and #188 cross-ancestor `font-*` inheritance (see accepted gaps).
