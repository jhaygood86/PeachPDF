# `object-fit` / `object-position` on all replaced elements

_Landed 2026-07-22._

**`object-fit` / `object-position` on all replaced elements** (issue #236): both properties parsed and cascaded in the CSS-OM but had **zero render-side plumbing** — no `CssBox` accessor, no `CssUtils` bridge entry, and the replaced-box paint always stretched content to fill its content box. Now: (1) `ObjectFit`/`ObjectPosition` are surfaced on `CssBoxProperties` (defaults `fill` / `50% 50%`) and wired through `CssUtils._propertyGetters`/`_propertySetters`/`_knownPropertyNames` + the style-copy block (the three places every box property must appear); (2) a new `ObjectFitResolver.Compute(contentBox, natW, natH, fit, position, box)` returns the destination rect + a needs-clip flag, **reusing `BackgroundLayerResolver.ResolveSize("contain"/"cover", …)` for the fit geometry and `ResolvePosition` for placement** (the "one grammar" rule — `object-fit` cover/contain == `background-size` cover/contain, `object-position` == `background-position`); (3) a shared `ReplacedContentRenderer.Paint(g, contentBox, image, svg, box)` computes the intrinsic size (pixels → points via `Length.PointsPerPx`), calls the resolver, `PushClip`s the content box when the result overflows (`cover`, oversized `none`), and draws into the computed rect. **Every replaced box now calls this one renderer:** `CssBoxImage` (raster + `<img src="*.svg">`), `CssBoxObject` (image-resolving `<object>`), `CssBoxSvg` (inline `<svg>`), and a new `CssBoxVideo`. **`<video>` gained poster rendering** — since a static PDF can't play video, `CssBoxVideo` (modeled on `CssBoxObject`) renders the `poster` image as replaced content (falling back to a container with fallback DOM content when there's no poster), wired into `CssBox.CreateBox` via new `HtmlConstants.Video`. `fill` and the unknown-intrinsic case return the content box unchanged, so the default path is byte-identical (existing image/object/svg tests unaffected). Verified in `ObjectFitResolverTests` (pure geometry, all fit branches incl. unknown/zero-intrinsic), `ObjectFitPaintIntegrationTests` (a 2:1 PNG through `TestRecordingGraphics` — `DestRect` per fit + object-position for `<img>`/`<object>`/`<video poster>`, and the content-box clip for inline `<svg>` cover), and an `object_fit` showcase rasterized in **both** PDFium and MuPDF. `scale-down` uses the smaller of `none`/`contain`; `none`/`scale-down` positioning uses the intrinsic size in points.
