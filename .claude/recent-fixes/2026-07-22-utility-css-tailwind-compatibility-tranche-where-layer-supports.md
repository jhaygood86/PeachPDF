# Utility-CSS (Tailwind) compatibility tranche: `:where()`, `@layer`, `@supports`/`@container` indexing, and CSS Color 4/5 functions — plus a color-parsing consolidation that fixed a latent `hsl()`/`hwb()` crash

_Landed 2026-07-22._

**Utility-CSS (Tailwind) compatibility tranche: `:where()`, `@layer`, `@supports`/`@container` indexing, and CSS Color 4/5 functions — plus a color-parsing consolidation that fixed a latent `hsl()`/`hwb()` crash.** Driven by evaluating Tailwind v3/v4 output. Five pieces:
1. **`:where()`** — registered alongside `:is()`/`:matches()` (`PseudoClassNames.Where`, `SelectorConstructor` `PseudoClassFunctions`), reusing the `:is()` forgiving-list match path. The one real difference is **zero specificity** (CSS Selectors 4 §16): `MatchesSelector.Specificity` returns `Priority.Zero` when the keyword is `where`, so it flows through `CssData.GetMatchedSpecificity` and a `:where(...)`-authored reset loses to any real selector. See `RelationalPseudoClassSelectorTests`.
2. **`@layer` cascade layers** (CSS Cascade 5) — both the block form (`@layer name { … }`, incl. anonymous) and the order-declaring statement form (`@layer a, b, c;`) parse into new `LayerRule`/`LayerStatementRule` (`StylesheetComposer.CreateLayer` + `ReadLayerNames`; `RuleType.Layer`/`LayerStatement`, `RuleNames.Layer`). `CssData.IndexRules` threads a `currentLayer` name and a first-appearance `layerOrder` registry, tagging each `IndexedRule` with a `LayerRank` (unlayered = `int.MaxValue`); the cascade sort in `GetStyleRulesByOrigin` now orders by `(LayerRank, specificity, DocumentOrder)` — layer precedence **ahead of specificity**, so a later layer's low-specificity rule beats an earlier layer's `#id` rule, and unlayered beats all. See `CascadeLayerIntegrationTests`. (The three #237 residual gaps — `!important` layer reversal, nested-layer ordering, `@font-face`/`@property`/`@page` inside a layer not collected — and #240 `revert-layer` are now all fixed; see the cascade-layer correctness entry above.)
3. **`@supports`/`@container` inner-rule indexing** — `CssData.IndexRules` recursed into `ISupportsRule`/`IContainerRule` so their inner rules applied with the condition treated as met. **⚠️ Superseded:** this permissive indexing was later *removed* — `@supports`/`@container` blocks are now **ignored** (inner rules not indexed), because applying rules guarded by a condition PeachPDF can't evaluate is worse than dropping them. (Originally all three conditional-rule types were filed as [#235](https://github.com/jhaygood86/PeachPDF/issues/235); the **`@media` feature-query half is now evaluated** and `@supports` → [#283](https://github.com/jhaygood86/PeachPDF/issues/283) / `@container` → [#284](https://github.com/jhaygood86/PeachPDF/issues/284) are now handled by ignoring the block — see the `@media` Recent-fixes entry below.) See `ConditionGroupingRuleIntegrationTests`.
4. **CSS Color 4/5 functions as solid colors** — `oklch()`/`oklab()`/`lab()`/`lch()` and `color-mix()` now resolve to sRGB (Tailwind v4's default palette is oklch; opacity modifiers are `color-mix(in oklab, …, transparent)`). Verified in a `modern_colors` showcase (PDFium + MuPDF).
5. **Color-parsing consolidation (per the "one parser" rule).** Per user direction, tokenization + grammar parsing moved wholly into the CSS-OM: a new `ColorFunctionExtensions` (over the CSS-OM `FunctionToken` stream) parses every color function; `CssValueParser.GetColorByName` is reduced to a `Color → RColor` conversion via a new `ColorFunctionExtensions.ToResolvedColor` (its hand-rolled `oklch`/`color-mix` string-scanner was removed; the `hex`/`rgb`/`rgba` fast-paths stay, because the Layer B tokenizer emits `#000` as `Delim`+`Number`, not a `ColorToken`). The color-space math is centralized in one CSS-OM `ColorSpaceMath` (moved out of `Html/Core/Utils/ColorSpaceConverter`, which now delegates to it — one implementation for both solid-color resolution and gradient interpolation). `Color` gained `FromLab`/`FromOklab`/`FromLch`/`FromOklch`/`Mix`. **This fixed a real latent bug**: `hsl()`/`hwb()` as *solid* colors stack-overflowed (the CSS-OM's text-reconstructing `FunctionValueConverter` fed its own `"hsl(…)"` `CssText` back into `TryGetColor` forever) — now they resolve. **Layer A** keeps the strict comma-form converters first (so `hsla(50, …)` still serializes as `hsla(50deg, …)`), with lenient `Any`-arg fallbacks (`RgbLenient`/`Hsl…`/plus `Oklch`/`Lab`/`ColorMix`) appended so the CSS Color 4 space/slash forms and the new functions are *accepted* at parse time and carried through a `background:`/`border` shorthand to the color longhand for Layer B to resolve. See `ModernColorParsingTests`. (A *digit-leading* hex color used directly as a `color-mix()` operand, e.g. `#2563eb` — which used to fall through the same non-value-mode quirk `NormalizeHexColorTokens` works around for `box-shadow` — is now fixed; see the 2026-08-03 color-mix Recent-fixes entry.) Colors resolve at Layer B, so Layer A's `.OrDefault(black)` on unknown functions doesn't matter. HTML `filter` ([#234](https://github.com/jhaygood86/PeachPDF/issues/234)) remains a Tailwind-relevant gap. (CSS Nesting [#233], `object-fit`/`object-position` [#236], CSS Grid [#232], and the flex-column cross-axis alignment bug [#133] are now implemented — see their Recent-fixes entries.)
