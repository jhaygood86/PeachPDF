# `box-decoration-break` stored and exposed on `CssBox`

_Landed 2026-07-25._

**`box-decoration-break` stored and exposed on `CssBox`** ([issue #300](https://github.com/jhaygood86/PeachPDF/issues/300), [CSS Fragmentation 3 §6.2](https://www.w3.org/TR/css-break-3/#break-decoration)): the property was fully parsed in the CSS-OM (`CSS/StyleProperties/Box/BoxDecorationBreak.cs` + `Converters.BoxDecorationConverter`) but the parsed value went nowhere — no `CssBoxProperties` field, no `CssUtils` get/set, no initial-value entry — so a declaration was silently dropped at the Layer A → Layer B seam. Storage/plumbing only; the paint effect was out of scope here and is what this unblocked — **now implemented, see the §6.2 entry above** (#309/#310/#311 landed together). The diagnosis recorded here is what that work was built on, and is still the reason the property could not simply be described as "PeachPDF already does `slice`": across a *page* it was slice-like (a fragment paints its whole border/background rect and the page clip cuts it), but an inline box split across *lines* was mixed — `BordersDrawHandler` was correctly gated on `isFirst`/`isLast` and `CssImagePainter` gated a URL layer on `isFirst`, yet `FragmentPainter.PaintBackground` re-resolved the background color, every gradient layer and `box.ComputeRadii` against **each line's own rect**, so a rounded/gradient-filled wrapping inline rendered closer to `clone`. The real work was therefore the *line* case as much as the page case — though the edges turned out **not** to be the `lines[i]` index this note predicted (a per-page index is wrong for a box that also crosses a page), nor `BoxFragment.IsFirstFragment`/`IsLastFragment`. **Layer A needed no change**: `BoxDecorationConverter.OrDefault(false)` already expands to `Toggle(clone, slice)` + all five CSS-wide keywords, and `IdentifierValueConverter` hands the keyword itself to Layer B for `DomParser` to resolve. Pieces:
1. **`CssBoxProperties.BoxDecorationBreak`** (default `CssConstants.Slice`; new `CssConstants.Slice`/`Clone`), declared beside the `break-*` trio.
2. **The four plumbing places**: `CssUtils._propertyGetters`, `_propertySetters` (with a `slice`/`clone` guard, following the `hyphens` precedent — `break-*` doesn't validate, but this is the only defence for direct `SetPropertyValue` callers), `_knownPropertyNames` (the `revert` snapshot), and `CssDefaults._allInitialValues` (the seed *and* `initial`/`unset`/`revert` resolution). Deliberately **not** in `CssDefaults.InheritedProperties` — it is not inherited, which is exactly what makes `unset` mean `initial` for it.
3. **Copied in `InheritStyle`'s `everything: true` branch** — the same reasoning as the adjacent `PdfTagType` block: that branch is a structural *clone* path (`CssProxyBox`'s repeated header/footer, `DomParser`'s inline/block split), not inheritance, so a non-inherited property must be copied there while staying out of the always-inherited branch. This is #327's shape, but behaviour-neutral here because nothing reads the value yet — **#327 itself (the `break-*` half) is still open and deliberately untouched**, since copying break values there changes layout.
Also fixed: the stale `orphans`/`widows` doc-comment above them, which claimed they "have no effect on pagination" — `CssBox.PerformLayoutImp` has enforced them (whole-box push, block flow only, skipped for a box taller than one page, inert in multicol) for some time. Tests: `BoxDecorationBreakCascadeTests`, on the shared `TestSupport/LayoutHarness` (the value set; all four CSS-wide keywords against a lower-priority `clone` — the two rules must be *separate*, since a second declaration in one block replaces the first at parse time and the box would never hold `clone` to reset; `inherit` vs. not-inherited; and **both** clone call sites, a repeated `<thead>` proxy and a block-in-inline split). Plus rows in `CssUtilsTests`' round-trip / invalid-value tables, a snapshot+initial-value fact, and Layer A global-keyword/reject theories in `CssPropertyTests`. Each edit was verified load-bearing by reverting it individually — **including a `@layer` `revert-layer` case added after review**, which is the only thing that distinguishes the `_knownPropertyNames` entry (roll back to the snapshot) from the `CssDefaults` one (roll back to the initial value): every other keyword case lands on `slice` either way, so they'd pass with the known-name entry deleted. Docs: `docs/html-css-support.md` Page Breaks row. No showcase — plumbing with no new visible rendering capability.
