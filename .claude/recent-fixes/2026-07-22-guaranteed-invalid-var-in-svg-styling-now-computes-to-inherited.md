# Guaranteed-invalid `var()` in SVG styling now computes to inherited/initial instead of falling through

_Landed 2026-07-22._

**Guaranteed-invalid `var()` in SVG styling now computes to inherited/initial instead of falling through** (issue #206): per CSS Custom Properties 1 §3, a declaration whose `var()` is guaranteed-invalid (missing custom property + no fallback, or cyclic) is *invalid at computed-value time* — it still **wins** the cascade, and the property computes to its inherited (or initial) value, rather than the cascade rolling back to a lower-priority declaration. The SVG path did the opposite: `SvgTreeBuilder.ResolveStyledAttr` fell through to the next tier when `ISvgSourceNode.ResolveVar` returned null (inline `style=""`), and `SvgCssStyling.GetMatchedDeclarations` *dropped* an invalid matched declaration entirely (so it fell through to the presentation attribute). Fixed by making each tier that **declares** the property authoritative: (1) `GetMatchedDeclarations` now keeps an invalid winner as a **`null` value** (present-but-invalid, `IReadOnlyDictionary<string, string?>`) rather than removing it — winner-last still overwrites, but the null signal survives (`ISvgSourceNode.GetMatchedCssDeclarations` return type updated to match); (2) `ResolveStyledAttr` returns the winning tier's result unconditionally (inline `style=""` returns `ResolveVar(value)` even when null; a matched entry present with null returns null) — a null return means "invalid at computed-value time", and since the SVG paint consumers already map a null `Attr(...)` to the inherited paint (`ApplyCommon`'s `?? inherited.Fill` etc.) or the property's initial default, no per-property changes were needed. Presentation attributes are the lowest author tier (SVG 2 §6.3, specificity 0), so a `<style>` rule or inline style with an invalid `var()` correctly suppresses them. HTML was already spec-correct here (`AssignCssBlock` defers only the winning declaration's raw value into `pendingVarProperties`, and `GetGuaranteedInvalidFallback` computes inherited/initial; a later plain value removes the pending var). See `SvgIntegrationTests` (matched-rule and inline-`style=""` invalid var → inherited, presentation attr suppressed) and `CustomPropertiesIntegrationTests.Var_GuaranteedInvalid_InWinningRule_DoesNotRollBackToLowerRule` (HTML parallel).
