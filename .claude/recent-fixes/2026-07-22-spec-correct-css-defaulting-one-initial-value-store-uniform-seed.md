# Spec-correct CSS defaulting: one initial-value store + uniform seed; Layer B made longhand-only

_Landed 2026-07-22._

**Spec-correct CSS defaulting: one initial-value store + uniform seed; Layer B made longhand-only.** The cascade now implements [CSS Cascade & Inheritance 4 §2.1](https://www.w3.org/TR/css-cascade-4/#defaulting) ("specified value = cascaded value, else inherited (if inherited) else initial") from a **single** authoritative initial-value store. Previously `CssDefaults` held two overlapping dictionaries — a public `InitialValues` (~40-entry *curated* seed subset) used by `DomParser.CascadeApplyStyles` step 1, and a private `_allInitialValues` (~90-entry comprehensive superset) backing `GetInitialValue` for `initial`/`unset`/`revert` — whose shared keys were byte-duplicated and could silently drift. Now `_allInitialValues` is the *only* store; `InitialValues` is a read-only view of it, and the seed loop iterates it so **every** property is seeded (no curated subset), values coming from the same place the global keywords resolve from. Two seed-correctness fixes fell out: the initial `font-family` is now `CssConstants.DefaultFont` (the platform-resolved UA default, [CSS Fonts 4 §2.2](https://www.w3.org/TR/css-fonts-4/#font-family-prop)) not the literal `"serif"`; and `hr { display: block }` was added to the UA sheet (the uniform seed now sets display's `inline` initial on every element, so `<hr>`'s block-ness must come from the UA sheet, not a seed omission). **One intentional structural exception:** an anonymous box (`box.HtmlTag is null`) skips the `display` seed, because an element-less box's display is assigned by *box generation*, not by cascading display's initial ([CSS Display 3 §1.1 "the box tree"](https://www.w3.org/TR/css-display-3/#box-tree); CSS2 §9.2.1.1 anonymous block boxes; §17.2.1 anonymous table objects; [CSS Flexbox §4](https://www.w3.org/TR/css-flexbox-1/#flex-items) anonymous flex items) — seeding `inline` would clobber it. Separately, **Layer B (`CssUtils.SetPropertyValue`/`GetPropertyValue`) is now longhand-only**: the CSS-OM (Layer A, `src/PeachPDF/CSS/`) already expands every shorthand to longhands on *all* paths (parse-time `StyleDeclaration.SetShorthand`, `var()`-deferred `DomParser.ApplyResolvedPropertyValue`, and the `initial`/`unset`/`revert` keywords), so Layer B's shorthand handling was fully dead — all of it removed (border/margin/padding/flex/flex-flow/gap/columns/column-rule/list-style/border-radius/text-decoration setters + their helper/parse methods), along with the vestigial `CssBoxProperties.BorderRadius`/`TextDecoration` shorthand-expander properties and a dead cascade-time text-decoration propagation pass. `CssBox.PaintDecoration` now reads the `text-decoration-*` longhands directly and draws each space-separated `text-decoration-line` keyword (so `text-decoration-line: underline overline` paints both). See `InitialValueDefaultingTests` (single store, uniform seed, `hr` block, anonymous-box structural display + inheritance) and `CssUtilsTests` (Layer B ignores shorthands; shorthands still expand end-to-end via Layer A).
