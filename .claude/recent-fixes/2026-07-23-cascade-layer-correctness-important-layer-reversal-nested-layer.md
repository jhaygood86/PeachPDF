# Cascade-layer correctness: `!important` layer reversal, nested-layer tree ordering, at-rules inside `@layer`, and layer-aware `revert-layer`

_Landed 2026-07-23._

**Cascade-layer correctness: `!important` layer reversal, nested-layer tree ordering, at-rules inside `@layer`, and layer-aware `revert-layer`** (issues #237 + #240 — the four deferred residuals from the Tailwind tranche's `@layer` support). One unifying refactor plus four fixes:
1. **Rank storage moved post-walk.** `CssData.IndexedRule` now carries the rule's `LayerName` (string, null = unlayered) instead of a baked-in `int LayerRank`; the numeric rank is resolved lazily at sort time (`RankOf`) from `_layerRanks`, which is only computable *after* the whole layer tree is walked. A new `LayerRegistry` (replaces the flat `layerOrder` dict) records the tree during the walk and computes ranks in `ComputeRanks`. `HasCascadeLayers` gates the layer-aware paths so a no-`@layer` document is byte-identical to before.
2. **`!important` layer reversal** (#237 gap 1, CSS Cascade 5 §6.4.2). New `CssData.GetAuthorStyleRulesForCascade` matches author rules **once** and returns them in BOTH the normal order (`OrderBy(rank)`) and the `!important` order (`OrderByDescending(rank)` — unlayered first/loses, earliest layer last/wins; specificity/source-order within a layer unchanged), each rule paired with its rank (`LayeredStyleRule`). `DomParser.CascadeApplyStyles`' author-important pass uses the reversed list.
3. **Nested-layer tree ordering** (#237 gap 2). `LayerRegistry` assigns each layer a path of first-appearance indices from the root down; ranks come from a lexicographic sort of those paths, so a parent's whole subtree is **contiguous** and its sub-layers are ordered by first appearance within the parent (`@layer a.b; @layer c; @layer a.d;` → `a.b < a.d < c`, not the old flat `a.b < c < a.d`). A dotted `@layer a.b` registers each ancestor prefix (implicit `a`). **Accepted simplification** ([#246](https://github.com/jhaygood86/PeachPDF/issues/246)): when a layer mixes direct rules with its own nested sub-layers, the parent's direct rules rank before those sub-layers (prefix-first in `ComparePath`); the exact CSS Cascade 5 §6.2 interleaving isn't modeled (utility frameworks never emit this shape). Characterized by `NestedSublayer_VsParentDirectRules_CharacterizesCurrentOrdering`.
4. **At-rules inside `@layer`** (#237 gap 3). New `CssData.EnumerateRulesRecursive`/`FlattenRules` descend `@layer`/`@media`/`@supports`/`@container`; the three collectors (`CascadeApplyStyleFonts` for `@font-face` — per-stylesheet so `src url()` still resolves against the sheet's `BaseUri`, `RegisteredProperty.BuildRegistry` for `@property`, and the `@page` collection in `GenerateCssTree`/`CascadeApplyPageStyles`) now use it, so an at-rule nested in a layer is found.
5. **Layer-aware `revert-layer`** (#240, CSS Cascade 5 §6.1). `AssignCssBlock`/`AssignCustomPropertyDeclaration` gained a separate `revertLayerTarget` (distinct from the prior-origin `revertTarget` that plain `revert` still uses). The new `ApplyAuthorRulesInLayerBands` walks the author rules in application order and, whenever the layer rank changes, snapshots the box state (= all lower-priority layers + prior origins) as that band's `revert-layer` target — correct for both the normal (ascending) and `!important` (descending) passes since "state before this band" is exactly the lower-priority accumulation in each. Snapshots are only taken when `HasCascadeLayers && RulesUseRevertLayerKeyword` (new helper), so `revert`/no-layer behavior is unchanged. UA/inline passes pass `revertLayerTarget == revertTarget` (not in layers). See `CascadeLayerIntegrationTests` (important reversal, nested contiguity, revert-layer reveals lower layer, revert still rolls back to origin, custom-property revert-layer) and `CascadeLayerAtRuleCollectionTests` (enumerator + `@property`/`@page` inside a layer). 100% diff coverage; full net8.0 suite green (no cascade-core regressions).
