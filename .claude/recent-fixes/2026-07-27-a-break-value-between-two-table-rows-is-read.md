# A break value between two table rows is read

_Landed 2026-07-27._

**A break value between two table rows is read** ([issue #314](https://github.com/jhaygood86/PeachPDF/issues/314), [CSS Fragmentation 3 §3.1](https://www.w3.org/TR/css-break-3/#break-between)). The break point between two rows is a class-A break point like any other, and the engine had only ever broken on *geometry* — `EstimateRowHeight` against the remaining band. The values have cascaded onto the row boxes since #299 and nothing read them, so `break-before: page` on a `<tr>` did nothing at all.

**The load-bearing decision is where to ask, and it is the engine's own row loop rather than a pass after it.** The flex/grid shape (#315) is a relocation pass that runs *after* placement, and it cannot serve here: a table's page break is what creates the repeating header's `CssProxyBox` for the new page, so a row moved by anything other than the loop that places rows arrives on a page with no header. Taking the break where the geometric test is already taken means the proxy, the footer reservation and `PageBreakBottoms` all follow for free — the new condition is a disjunction with `WillCrossPageBoundary`, not a new mechanism beside it.

**Both sides of the break point are read, and at their propagation anchors.** A `break-before` on a `<tbody>` is a value at the break point before its first row and a `break-after` on one is a value after its last — but the row group is not a box this engine places (`AssignBoxKinds` flattens the rows into `_bodyRows`), so the row is the only place it can be acted on. `BreakPropagation.ForcedBreak{Before,After}At` reads *down* a chain, so it has to be asked at the anchor: `AnchorForBreakBefore` for the following row and a new `AnchorForBreakAfter` — the symmetric counterpart, which was simply missing — for the preceding one. Asking the row directly finds a `<tbody>`'s value nowhere.

**`break-inside: avoid` on a row needs nothing**, and that is worth stating rather than looking like an omission: the engine never splits a row, so a row that would cross a boundary is already moved whole by the geometric test. The value is satisfied by construction. The page context is likewise the only one asked, because moving a row to the next page's content top is the only vehicle this engine has; a `column` value names a context the table does not establish and is left to the multi-column container the table may sit in.

**All 65 pre-existing showcases are byte-identical** — the expected result, since none declares a break value on a row. New showcase `paged_media_table_row_breaks` does, and **on the unfixed build its 26 rows flow onto a single page with the declaration ignored entirely**; verified in both PDFium and MuPDF, header repeating onto the page the break opens. Full net8.0 suite green (6464); **100% diff coverage**. Tests: `TableRowBreakValueTests` (5 — the no-value control, `break-before` on a row, `break-after` on the one before it, a `<tbody>`'s own value seen at its first row, and the repeated header surviving a forced break).
