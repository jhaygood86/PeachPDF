# `text-transform: uppercase`/`lowercase` use full case mappings

**What:** `PeachDrawing.Text.Unicode.CaseMapper` (public: `ToUpper`/`ToLower`, a `language`, and a `sourceIndices` map) implements Unicode's default case conversion: the 102 multi-character uppercase mappings of `SpecialCasing` (`ß` -> `SS`, ligatures, Greek with iota subscript), `İ` -> `i̇`, the Greek final sigma from its context, and the Turkish/Azerbaijani i (not when a script subtag other than `Latn` is present: WPT `writing-system-text-transform-001` uses `tr-Cyrl`). The multi-character table is generated from Python's `unicodedata` (Unicode 13) into `Internal/Text/CaseMappingData.g.cs`; the one-to-one mappings come from `Rune`. `TextTransformer.ApplyFull` is what HTML calls; `TextTransformer.Apply` stays one-to-one for SVG, whose per-character positioning relies on the length not changing.

**The load-bearing part, found by reading, not running:** `CssBox.AppendWordsFromText` indexed everything resolved per character of the box's own text (bidi levels, scripts, joining forms, USE and Khmer categories, the original-text slice) by the position in the *transformed* text, which was only valid while the transform kept the length. It now reads them through the map the transform returns (`SourceIndexAt`, `_transformSourceMap` for the slicers in `AddWord`); `SourceStart` is `-1` (unmappable) when the length changed, as it already was for small-caps fragments. Without this a length-changing transform reads past the end of those arrays.

**Measured:** css-text 854 -> 861 on a Mac, css2-flow +1 (floors 828 -> 835 and 1819 -> 1820). Lost: `text-transform-upperlower-016` (Greek Extended): it pairs `ᾀ` with `ᾈ`, the simple mapping, while the full mapping gives `ἈΙ`, which is what the specification asks for. The new tests: `CaseMapperTests` (`PeachDrawing.Text.Tests`), `TextTransformFullCaseMappingTests` (engine; one has Hebrew after a sharp s to prove the bidi levels follow).

**Not done:** Lithuanian (adds and removes combining dots above), titlecase for `capitalize` (the first letter of a word still uses the simple mapping, so `ß` and `ǆ` are wrong), `text-transform: full-width` before white space collapse, and the remaining `text-transform-capitalize` / `tailoring` / `shaping` tests. `AddWord` still falls back to the transformed text as the word's original when the two differ in length, so a `::first-line` text-transform re-derives from the transformed word.
