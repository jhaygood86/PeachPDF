# `text-transform` uses full case mappings, title case and Unicode 18 data

**What:** `PeachDrawing.Text.Unicode.CaseMapper` (public: `ToUpper`/`ToLower`/`ToTitle`, a `language`, and a `sourceIndices` map) implements Unicode's default case conversion: the multi-character `SpecialCasing` mappings (`ß` -> `SS`, ligatures, Greek with iota subscript), title case (`ß` -> `Ss`, `ǆ` -> `ǅ`, Georgian staying lowercase), `İ` -> `i̇`, the Greek final sigma from its context, and the Turkish/Azerbaijani i and Lithuanian dot-above rules (conditional entries of `SpecialCasing.txt`, written out as context rules in `CaseMapper.cs`: Final_Sigma, After_Soft_Dotted, More_Above, After_I, Not_Before_Dot). A script subtag other than `Latn` (`tr-Cyrl`, WPT `writing-system-text-transform-001`) turns the tailorings off.

**Data:** `assets/unicode/generate_case_mapping_tables.py` generates `Internal/Text/CaseMappingData.g.cs` from the Unicode 18.0.0 files checked in beside it (`UnicodeData.txt`, `SpecialCasing.txt`, `PropList.txt`, `DerivedCoreProperties.txt`): the one-to-one mappings too, so nothing depends on the Unicode version of the .NET runtime (`Rune.ToUpperInvariant` follows the runtime's). An earlier version of this change took the multi-character table from Python's `unicodedata` (Unicode 13); do not go back to that. `CaseMapperConformanceTests` reads the same files and checks every unconditional `SpecialCasing` entry and every `UnicodeData` one-to-one mapping.

**The load-bearing part, found by reading:** `CssBox.AppendWordsFromText` indexed everything resolved per character of the box's own text (bidi levels, scripts, joining forms, USE and Khmer categories, the original-text slice) by the position in the *transformed* text, valid only while the transform kept the length. It now reads them through the source-index map the transform returns (`SourceIndexAt`, and `_transformSourceMap` for the slicers `AddWord` calls); `SourceStart` is `-1` (unmappable) when the length changed. A word that changed length keeps its source as `OriginalText` (the small-caps and per-codepoint paths, which slice it by position, still fall back to the transformed text), so a `::first-line` text-transform re-derives from the source.

**`full-width` collapses first:** css-text-3 collapses white space before `text-transform`, but the transform ran on the raw text, turning every space of `x   x` into an ideographic space (which no longer collapses). `TextTransformer.ApplyFull` now collapses the runs the box collapses (`!PreservesSpaces`, and segment breaks unless `PreservesBreaks`) into one U+3000 as it maps, with the source map covering the shortening. `TextTransformer.Apply` stays one-to-one (and on .NET's mappings) for SVG, whose per-character positioning relies on the length not changing.

**Measured:** css-text 854 -> 869 on a Mac over this and the commit before it, css2-flow +1 (floors 828 -> 843 and 1819 -> 1820). Lost: `text-transform-upperlower-016` (Greek Extended): it pairs `ᾀ` with `ᾈ`, the simple mapping, while the full mapping gives `ἈΙ`, which is what the specification asks for.

**Not done:** `capitalize` finds a word start by white space, not by UAX #29 word boundaries; SVG text still uses the .NET one-to-one mapping; the remaining `text-transform-capitalize`, `tailoring` and `shaping` WPT tests were not looked at.
