# Color emoji via vector glyph outlines (`COLR`/`CPAL`, v0 + v1)

_Landed 2026-07-24._

**Color emoji via vector glyph outlines (`COLR`/`CPAL`, v0 + v1)** ([issue #175](https://github.com/jhaygood86/PeachPDF/issues/175), the `COLR` half): color-glyph fonts now render — each color glyph is **decoded and drawn as native PDF vector content** instead of embedding the font program and showing CID text (the maintainer-directed approach; the reusable glyph-outline decoder also unblocks future text-to-outline work). Landed as a namespace refactor first, then the feature. Pieces:
1. **All font handling extracted into a `PeachPDF.Fonts` namespace** (its own commit): `PdfSharpCore/Fonts/**` → `src/PeachPDF/Fonts/**` (ns `PeachPDF.Fonts`), `PdfSharpCore/Fonts.OpenType/**` → `Fonts/OpenType/**` (ns `PeachPDF.Fonts.OpenType`), plus `FontResolver`/`TtfFontDescription`/`LinuxSystemFontResolver`/`FontFamilyModel` moved in from `Utils`/`Internal`. `RuneRange` stays in ns `PeachPDF` (public API — no break). Pure mechanical move (byte-identical behavior). The OpenType readers keep their PDFsharp-origin license headers even though they now live outside `PdfSharpCore/`.
2. **`GlyphOutlineDecoder`** (`Fonts/OpenType/`) — a reusable `glyf`→vector-contour decoder: simple glyphs (flag RLE + delta coords), composite glyphs (component offsets + F2Dot14 2×2 transforms, depth-guarded), implied on-curve midpoints, and quadratic→cubic elevation (path layer is cubic-only). Gates on `glyf` (CFF declines). Reference layout: `Woff2Converter.UntransformGlyf`.
3. **`ColrTable` + `CpalTable`** (`Fonts/OpenType/`, read in `OpenTypeFontface.Read`, optional/never-throw): CPAL swizzles on-disk BGRA→RGBA once via a portable `Vector128.Shuffle` (SSSE3/AdvSimd) + scalar fallback. COLR reads v0 base/layer records and, for v1, lazily parses the paint graph (`PaintColrLayers`/`Solid`/`Linear|Radial|Sweep Gradient`/`Glyph`/`ColrGlyph`/`Transform` family/`Composite` + `ColorLine`) into a `ColrPaint` model; `PaintVar*` read at default instance. `OpenTypeDescriptor` exposes `IsColorFont`/`ColorTable`/`ColorPalette`/`TryGetGlyphOutline`.
4. **`ColorGlyphPainter`** (`Drawing.Pdf/`, two partials — v0 + `ColrV1.cs`) driven from `XGraphicsPdfRenderer.DrawString`: the descriptor is resolved via `FontDescriptorCache.GetOrCreateDescriptorFor` (so a color font is **never realized/embedded** — no unused subset), and for a color font the CID `Tj` build + `AddChars` are skipped in favor of vector fills. v0 fills each layer's outline in its `CPAL` color bottom-to-top (`0xFFFF` = foreground); v1 recursively interprets the paint graph in world space through a `ColrAffine` glyph→world map, using the shared `XGraphics` for glyph clips (`Save`/`IntersectClip`/`Restore`), solid/gradient fills (`X{Linear,Radial,Conic}GradientBrush`), and blend-mode compositing (`XGraphicsPdfRenderer.SetBlendMode` → PDF `/BM` ExtGState). Linear `repeat`/`reflect` extend tiles/mirrors the stops and extends the axis (PDF shadings only pad).
Verified in **both PDFium and MuPDF** against the real COLR v1 Noto Color Emoji and a hand-authored fixture. Tests: `GlyphOutlineDecoderTests`, `ColrCpalTableTests`, `ColorGlyphRenderingIntegrationTests` (incl. a real-Noto smoke test); fixtures `ColorTestV0/V1.ttf` (CC0, generated by `assets/fonts/generate_color_fonts.py`) + `NotoColorEmoji-Subset.ttf` (OFL). Showcase: `color_emoji` (real Noto emoji hero + per-paint-feature breakdown). Docs: `docs/html-css-support.md` Per-character font matching + `docs/license.md`. **Remaining color-glyph gaps** ([issue #287](https://github.com/jhaygood86/PeachPDF/issues/287)): bitmap `CBDT`/`CBLC` + `sbix`, SVG-in-OpenType, `COLR` over CFF, COLRv1 variable paints, and non-expressible Porter-Duff composite modes (→ source-over); linear `p2`-rotation reduces to the `p0→p1` axis, radial repeat/reflect is pad-only, and a radial gradient's nonzero inner radius (`r0`) collapses to the focal point. Color glyphs are vector art, so no `/ToUnicode`/selectable text.
