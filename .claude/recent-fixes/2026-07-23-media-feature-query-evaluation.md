# `@media` feature-query evaluation

_Landed 2026-07-23._

**`@media` feature-query evaluation** (issue [#235](https://github.com/jhaygood86/PeachPDF/issues/235), the `@media` half — the `@supports`/`@container` halves were split out to [#283](https://github.com/jhaygood86/PeachPDF/issues/283)/[#284](https://github.com/jhaygood86/PeachPDF/issues/284) and stay permissive): `@media` conditions were parsed but never evaluated — `CssData.EnclosingMediaMatches` only compared `Medium.Type`, so every `@media (min-width: …)` block applied and the last-declared breakpoint always won regardless of page size (Tailwind's `sm:`/`md:`/`lg:`/`dark:` all collapsed to "largest wins"). Now feature conditions are evaluated against the page box + the renderer's characteristics, per [Media Queries 4](https://www.w3.org/TR/mediaqueries-4/). Pieces:
1. **`MediaQueryContext`** (`src/PeachPDF/Html/Core/MediaQueryContext.cs`, a `readonly record struct`) carries the media type + page-box width/height (points, nullable → permissive when unknown) + resolution dpi + `PreferredColorScheme`. Built once in `DomParser.GenerateCssTree` via `FromContainer(htmlContainer, mediaType)` from `htmlContainer.PageSize` (the full sheet during the CSS-tree build — the correct page box), threaded through `CssData`'s query methods (`GetStyleRules`/`GetUserAgentStyleRules`/`GetAuthorStyleRules`/`GetFirstLineStyleRules`/`GetAuthorStyleRulesForCascade`/`GetStyleRulesByOrigin`/`GatherMatchedRules`) in place of the bare `string media`. Non-HTML callers (SVG styling in `SvgCssDomNodes`) pass `MediaQueryContext.TypeOnly(media)` → geometry-null → permissive, unchanged behavior.
2. **`MediaQueryMatcher`** (`src/PeachPDF/Html/Core/MediaQueryMatcher.cs`) replaces `EnclosingMediaMatches`: per `Medium`, `typeMatches (null/empty type ⇒ all) && all features match`, then `not` negates the **whole** query (MQ4 §3.1, was type-only). Evaluates `width`/`height`/`device-*`/`inline-size`/`block-size` (px→pt via `Length.PointsPerPx`; **MQ `em`/`rem` resolve against the initial 16px, not the doc root**), `orientation`/`aspect-ratio` (from page box), `resolution`/`device-pixel-ratio` (vs 96dpi), `color`/`color-index`/`monochrome`/`grid` (fixed print device), `prefers-color-scheme` (config), and the static-document discretes (`hover`/`pointer`/`update`/`scripting` → `none`, `prefers-reduced-motion` → `reduce`, `prefers-contrast`/`prefers-reduced-transparency` → `no-preference`). Handles both the `min-`/`max-` prefix and the v4 **range syntax** (`width >= 48rem`) via a new `MediaFeature.Comparison` (exposes the parsed `>`/`<`/`>=`/`<=`/`:` operator) + `AsLength`/`AsResolution`/`AsRatio` typed accessors on `MediaFeature`.
3. **New registered features** (`FeatureNames` + `MediaFeatureFactory` + one class each, `Converters.Any`): `prefers-color-scheme`, `prefers-reduced-motion`, `prefers-contrast`, `prefers-reduced-transparency`, `update`, `any-hover`, `any-pointer` — previously *unregistered*, so they failed to parse → became `not all` → never applied (this is why `dark:` couldn't work at all before). **Unsupported-feature policy (one rule, both tiers): a feature PeachPDF can't evaluate ⇒ the block is ignored.** A feature name the CSS-OM doesn't register fails to parse → `not all` (matches nothing) upstream; a *registered* feature this matcher doesn't model (e.g. `scan`) hits `default: return false`. Both are MQ4's "unknown feature is false". (A feature that IS modeled but whose runtime *context* is missing — e.g. a `width` query with no page geometry, standalone SVG — stays permissive; that's an unknown context, not an unsupported feature.)
4. **New config** `PdfGenerateConfig.PreferredColorScheme` (`PdfColorScheme.Light`/`Dark`, default Light) → `HtmlContainerInt.PreferredColorScheme` (set in `PdfGenerator.SetContent`), so `@media (prefers-color-scheme: dark)` / Tailwind `dark:` render when the caller opts in.
**Same-directive companion change — `@supports`/`@container` blocks are now IGNORED, not applied.** Per the "unsupported at-rule ⇒ ignore the whole block" rule, `CssData.IndexRules`/`FlattenRules` no longer descend into `ISupportsRule`/`IContainerRule` (they used to index the inner rules in place, treating the condition as met). PeachPDF has no supports/container-query engine, so rather than apply rules guarded by a condition it can't test (which would apply a `not`-guarded fallback and its enhanced counterpart at once), the inner rules — and any at-rule nested in them — are dropped. This reverses the earlier permissive indexing (see the #235 note in the Tailwind-tranche entry) and effectively closes [#283](https://github.com/jhaygood86/PeachPDF/issues/283)/[#284](https://github.com/jhaygood86/PeachPDF/issues/284) as "ignore" rather than "evaluate". Resolution/`device-pixel-ratio` evaluate against a fixed 96 dpi (1 dppx) — NOT `PixelsPerInch` (which is a rasterization scale, default 72). Verified by `MediaQueryLayoutIntegrationTests` (a ~64-row theory covering every feature branch + `not`/comma-OR/type + the unsupported-feature-ignored behavior + square-page orientation + the `prefers-reduced-motion` boolean form, plus a same-stylesheet-two-page-widths grid-column-count assertion), `ConditionGroupingRuleIntegrationTests` (@supports/@container inner rules dropped; a top-level rule for the same element still applies), and a `responsive_media_{wide,narrow,dark}` showcase trio (one stylesheet, three configs) rasterized in **both** PDFium and MuPDF. Docs: `docs/html-css-support.md` CSS Media Queries table + `@media`/`@supports`/`@container` at-rule rows. **Accepted gaps:** MQ4 double-range (`400px <= width <= 700px`) and reversed (`768px <= width`) forms aren't parsed (Tailwind emits neither); a `%` in a media length resolves against 0.
