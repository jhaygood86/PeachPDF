# SVG `<style>` cascade now honors `!important` and resolves `revert`/`revert-layer`

_Landed 2026-07-22._

**SVG `<style>` cascade now honors `!important` and resolves `revert`/`revert-layer`** (issue #205): `SvgCssStyling.GetMatchedDeclarations` previously merged author rules winner-last by specificity/source order only — it ignored `IProperty.IsImportant` (so an `!important` declaration won only if it also sorted last) and passed `revert`/`revert-layer` through as literal strings to the SVG value parsers (which don't understand them). Now the merge runs **two passes** (CSS Cascade 4 §6.3): a normal pass then an `!important` pass, each winner-last; because the important pass runs second and always overwrites, an `!important` author declaration beats every normal author declaration regardless of specificity. And a winning `revert`/`revert-layer` declaration (CSS Cascade 4 §6.1) is now resolved to the **null-present** signal (the same one the #206 guaranteed-invalid-`var()` fix uses): the declaration still wins the cascade but the property computes to its inherited/initial value rather than falling through to a lower-priority declaration — since an SVG presentation attribute is itself author origin (SVG 2 §6.3, specificity 0), reverting the author cascade rolls back *past* it, and the null-present signal (which `ResolveStyledAttr` maps to inherited/initial, never the presentation attribute) is exactly right. No `@layer` support in SVG styling, so `revert-layer` with no prior layer behaves as `revert`. See `SvgCssDomNodeTests` (important-beats-higher-specificity-normal, important-vs-important, revert null-present, revert-loses-to-higher-specificity, important-revert, custom-property exclusion) and `SvgIntegrationTests` (`!important` end-to-end, inline and standalone).
