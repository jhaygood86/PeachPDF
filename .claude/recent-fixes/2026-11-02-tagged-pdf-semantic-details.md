# Tagged PDF takes details from the accessibility tree

`FragmentPainter.PaintTaggedContent` now passes `StructureTagMapper.DetailsFor(box, classification)` to the sink, and `StructureTagMapper.AltFor` falls back from `alt` to the node's name for math, SVG and images.

- **The tree is built lazily per document and kept on the container** (`HtmlContainerInt.SemanticTree`, reset where the text-run cache is, `ResetSemanticTree`), because the painter has the container and not the `HtmlDocument`. It is built the first time tagging asks for a name, after layout, so a document that is not tagged never builds it for this.
- **Sink changes are additive.** `IStructureTagSink` gains `OpenGroupingElement(..., StructureDetails?)` and `OpenContentElement(..., altText, StructureDetails?)` with default implementations that call the old ones, so an existing sink keeps working; `PdfTagRecorder` gets matching overloads. An element is opened once per page its content reaches, so the recorder applies details **once** (`ApplyDetailsOnce`) - applying them on every open would append duplicate `/A` entries.
- **Order is still paint order.** The structure tree's children follow the order things were painted in, not the document, so a test that compares element order against the source fails (a `Table` came before the `H1`). That is the known coupling between reading order and z-order, not something this change touches; assert on sets.
- **Not done:** `/Headers` and `/ID`/IDTree, `/ActualText`, `/E`, link and widget annotation names (`/Contents`, `/TU`), `/RoleMap`, the PDF/UA identification and validation. Those are the next slice.
- **A raw PDF string holds only ASCII.** `PdfStructureElement.AlternateText` wrote `/Alt` with `SetString(key, value)`, so any non-ASCII alt text (an accented, Arabic or Japanese `alt`) threw `RawString contains invalid character` inside paint and failed the whole tagged render. It was always there for `alt`; the new alternative texts (a formula's reading of Arabic text) hit it in four `MathSourceParityTests` cases, which is how it was found. ASCII keeps its old raw form (byte-identical); anything else is a Unicode text string. `AlternativeTextInAnyScriptIsWritten` pins it.
