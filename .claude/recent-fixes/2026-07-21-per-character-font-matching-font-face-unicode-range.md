# Per-character font matching / `@font-face` `unicode-range`

_Landed 2026-07-21._

**Per-character font matching / `@font-face` `unicode-range`** (issue #158): font matching became codepoint-aware, replacing the old per-run model. `FontFamilyModel.Faces` is now a list of `FontFaceEntry` (each carrying its codepoint `RuneRange`s — explicit `unicode-range`, or `null` meaning "whatever the font's `cmap` covers", computed lazily via `CMapCoverage.Extract`), and `FontResolver.ResolveTypeface` takes an optional `Rune?` that filters faces by coverage then style-matches (a codepoint-less call is byte-identical to before, so every existing matching test is preserved). The codepoint threads through `FontResolvingOptions.Codepoint` → `XFont` → `XGlyphTypeface.GetOrCreateForCodepoint` (keyed by resolved face, not by codepoint, so a multi-script run doesn't spawn a typeface per character). In layout, `CssBox.AddWord` splits a word into per-face fragments (composing with the small-caps split; reuses `SuppressWrapBefore`) only when needed — a fast-path scan (`NeedsPerCodepointFont`, using `RFont.HasGlyph`) keeps ordinary fully-covered text a single word at zero new cost. Cross-family fallback required retaining the full authored stack: `CssBoxProperties.FontFamilyList` (the cascade collapses `FontFamily` to the first existing family). **Content-addressed identity** (the browser way — a font is identified by its bytes, not its self-reported `name`): two different files sharing an internal name (a common webfont-subset pattern) no longer collide — `FontResolver._CustomFonts` disambiguates on a content checksum (collision-only, preserving `FaceName == internal name` for the common case), `PdfFontTable.ComputeKey` includes `FontSource.Key`, and both `FontFactory.CacheFontSource`'s `FontSourcesByName` and `OpenTypeFontfaceCache.AddFontface` tolerate a same-name/different-bytes second entry instead of throwing. Two lexer/CSS-OM prerequisites were also fixed: `Lexer.UnicodeRange` now parses the `start-end` range form after a start of fewer than 6 hex digits (`U+41-5A`), and `ValueBuilder.Apply` accepts `TokenType.Range` so a `unicode-range` declaration survives strict (non-tolerant) parsing. Public API: `PdfGenerator.AddFontFromStream(stream, IReadOnlyList<RuneRange>)`. See `UnicodeRangeLayoutIntegrationTests`, `FontResolverCodepointTests`, `SameInternalNameSubsetTests`, `UnicodeRangeParserTests`. Residual boundaries (all-installed-font last resort; astral/format-12 coverage) noted under accepted gaps.
