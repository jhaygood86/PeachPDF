# Android: typing into a text field

`HtmlView.TextInput.cs` carries Android's text input to the engine's editing model. The arithmetic that does not need Android is in `Logic/` and tested without a device: `ImeEdits` (what `commitText`, `setComposingText` and `deleteSurroundingText` do, and the `InputType`/action for each field type) and `CaretMoves` (the same caret arithmetic as the WinUI view).

- **Not tried against a real keyboard.** The view builds and the arithmetic is tested, but no soft keyboard, IME composition or TalkBack was driven here; the connection was written from the platform's documented rules. The first thing to check on a device is composing text (Gboard's suggestion strip, a CJK keyboard): `setComposingText` must replace the composing region, not append.
- **The base class reads from a mirror.** `GetTextBeforeCursor`, `GetTextAfterCursor` and `GetSelectedText` cannot be overridden in the .NET binding (they are not virtual), so `FieldInputConnection.Editable` returns a `SpannableStringBuilder` copy of the field with the selection set, and the base class answers from it. A password is mirrored as bullets. The composing region is not mirrored (the binding has no way to set one); every composing call is overridden, so the engine's own composition is the truth.
- **Key events from the keyboard.** `BaseInputConnection.sendKeyEvent` dispatches to the view, so a soft keyboard's Backspace and arrows arrive at `OnKeyDown` like a hardware key; `HandleEditKey` handles them once.
- **The action key leaves the field.** `performEditorAction` steps the page's focus on (`StepFocus`), as Enter does in a form field elsewhere; there is no form submission yet.
- **A tap on a field** focuses it (`FocusTextFieldAt`, before the check box and link handling) and puts the caret with `GetEditIndexAt`. Dragging selection handles and a long-press menu are not done.
- **Accessibility.** A text field node is `Editable` and offers `ACTION_SET_TEXT`, `ACTION_SET_SELECTION` and `ACTION_PASTE`.
