# CSS Nesting

_Landed 2026-07-22._

**CSS Nesting** (issue #233 — [CSS Nesting 1](https://www.w3.org/TR/css-nesting-1/)): nested style rules and the `&` nesting selector now parse. **Resolved at parse time into ordinary flat rules**, so the matcher/cascade need zero nesting awareness. Pieces:
1. **Classification without a token buffer** (`StylesheetComposer.FillDeclarations`, the line-~745 branch). A new `TryCreateNestedRule`/`IsNestedRuleAhead` scans the upcoming construct bracket-depth-aware for the first top-level `{` (→ nested rule) vs `;`/`}`/EOF (→ declaration). This resolves the `div { }` (type selector, first token is an Ident like a property name) and `a:hover { }` (ambiguous with `a: hover`) cases via `{`-before-`;`, not a fragile first-token heuristic. A **`--` custom-property guard** keeps `--x: …` a declaration. `FunctionToken`s are opaque (the lexer already balanced their parens), so only bare round/square brackets count toward depth; a `{` inside a `url()`/string never triggers.
2. **Faithful lexer rewind — NOT a token buffer** (the subtle part). A token pushback buffer would corrupt hex colors: the lexer tokenizes `#123456` differently in value vs non-value mode (`Lexer.IsInValue`), and a buffered value replayed into `CreateValue` desyncs. Instead the classifier *rewinds* on the declaration branch and lets the unchanged declaration path re-lex in value mode. `NextToken` records `_markBeforeLastToken = _lexer.InsertionPoint` (a raw source index) before each token; the declaration branch calls `LexerBase.RewindTo(mark)`, which sets `Source.Index` directly and re-primes `Current` — deliberately *not* the `InsertionPoint` setter, whose `BackNative` loop is not a faithful inverse across `\r\n` normalization (that mismatch broke `CssCasesTests` unicode-escape/CR cases mid-implementation). Line/column aren't rewound (they only affect reported positions, never token content). The nested branch never rewinds — it proceeds from just after `{`.
3. **`&` resolution** (`CreateNestedStyleRule`/`ResolveNestedSelector`). The nested prelude's source text is sliced with the same raw marks and resolved against the enclosing rule's `SelectorText` (nearest `StyleRule` on `_nodes`): each `&` → `:is(<parent>)` (giving `&` the parent's specificity); a prelude with no `&` becomes `:is(<parent>) <prelude>`, which uniformly yields both the implicit-descendant (`.b` → `:is(p) .b`) and leading-combinator (`> .b` → `:is(p) > .b`) forms. The `&` substitution is **string-aware** (a char scanner tracking quote state), so a `&` inside an attribute-value string (`[data-x="a&b"]`) is preserved and doesn't wrongly flip the rule off the descendant branch — caught by post-change review. The resolved string is parsed via `Parser.ParseSelector` — `:is()` accepts complex/nested args (`MatchesFunctionState` feeds a full child `SelectorConstructor`), so deep nesting `:is(:is(.a) .b) .c` works. `SelectorConstructor` is untouched (resolved text has no `&`).
4. **Storage + indexing.** `StyleRule` gained a `NestedRules` list (`IStyleRule.NestedRules`); the resolved nested rule is attached to its parent. `CssData.IndexRules` recurses into `NestedRules` in the **same** media/`@layer` context and `ref order`, so nested rules inherit the parent's context and sort right after it in document order. `CollectIndexKeys` already buckets the resolved selectors well (a `:is(...) .title` indexes under `.title`).
See `CssNestingIntegrationTests` (implicit descendant, `&`-compound, type-selector & type:pseudo nesting, child combinator, multi-level, parent-list, hex-color regression, declaration-after-nested, `@media`/`@layer` inheritance, url-brace). **Accepted gaps** ([#253](https://github.com/jhaygood86/PeachPDF/issues/253)): nested at-rules (`@media`/`@layer`/`@supports` *inside* a style rule) aren't handled (place at top level); a custom-property value literally containing a `{` (e.g. `--x: { }`) is classified as a declaration but hits a pre-existing `CreateValue` brace limitation — neither occurs in real utility-framework output. `#233`-family efficiency note: a resolved subject hidden in `:is()` (e.g. `&:hover` → `:is(.card):hover`) buckets Universal (full-scan), correct but slower.
