# Table bug batch 2 (stalls, rtl columns, legacy alignment, min-width, float avoidance)

Issues fixed: #2297, #2298, #2299, #2300, #2186, #2187, #2196. Looked at and left open: #2220, #1440, #691, #1195.

- **Stall guard** (`HtmlContainerInt.SlotNeutral`): flex, flex-column and grid tokens are compared like block and table ones, and a `BlockBreakToken`'s `ResumeTopOverride` (the top of the fragmentainer it resumes in) is slot-neutral too. #2300 was exactly that: the innermost cell's token carried a top 120pt further down on every pass, so `IsSameProgress` was never true and the run went to the pass cap. The abs-pos/float pass loop in `CssBox.LayoutBlockChild` has the same stall counter (`HtmlContainerInt.MaxStalledPasses`) and a 1000-pass cap instead of 10,000.
- **#2297** (`CssLayoutEngine.CannotFitBelowTheFloatsEvenOnAFreshPage`): the line beside a float, moved below it, did not fit the page because a repeated header takes room at the top of every page. The question was only asked of a line at the very top of the page, which a line in a table never is. It is now also asked for any line while a header repeats (`FragmentainerContext.ResumeContentInset`), with the header taken from the fresh band. Found by tracing the token chain per pass with a temporary log in the driver loop: the break was before the first word of the innermost cell, not a float break. The three `StalledPaginationTests` that pinned `LastResortRelayouts == 1` now expect 0.
- **rtl** (`MirrorColumnAxis`): mirrored at the one place a cell's `Location` is set, with the column cursor kept in logical (left-to-right) terms. Trap: the cursor was reassigned from `cell.ActualRight` after placement, which is the mirrored edge. Collapsed borders are not mirrored (accepted gap).
- **Legacy alignment**: no new enum values; the origin of an inherited `text-align` is found by walking up to the first ancestor whose value differs from its parent's.
- **#2187** (`ExtentBesideFloatsWithBottom`): a table too wide for the room beside the floats moves to the lowest bottom of the floats that narrowed it, repeatedly.
- **#2220**: the float is at the top of the cell in layout for default, top and bottom `vertical-align`; the 1.5px does not come from layout (`FloatInTableCellPlacementTests` pins that).
- **#1440**: resetting a plain inline box's `Location` at flow entry made the drift worse, because the cell alignment measure reads that location; reverted. A fix has to change what the measure reads, or recompute `Location` from the rectangles at flow exit.
