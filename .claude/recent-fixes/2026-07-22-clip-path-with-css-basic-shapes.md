# `clip-path` with CSS basic shapes

_Landed 2026-07-22._

**`clip-path` with CSS basic shapes** ([CSS Masking Module Level 1](https://www.w3.org/TR/css-masking-1/) / [CSS Shapes Level 1](https://www.w3.org/TR/css-shapes-1/)): `polygon()` (optional `nonzero`/`evenodd` fill rule), `inset()` (1–4 edge offsets), `circle()` / `ellipse()` (length-percentage or `closest-side`/`farthest-side` radius, optional `at <position>`), and `none`. **Architecture (per the "one grammar, one parser" rule):** the value grammar lives in one shared `BasicShapeGrammar` (`src/PeachPDF/CSS/BasicShapeGrammar.cs`, `TryParse(IReadOnlyList<Token>) → ParsedBasicShape?`, keeping raw component strings — the `BackgroundPositionGrammar` precedent) used by BOTH layers: Layer A's `ClipPathValueConverter` validates through it (so `clip-path: banana` is *dropped at parse time*, and the authored text is preserved for Layer B), and Layer B's `CssClipPathResolver.TryBuildClipPath(g, value, referenceBox, box, out path, out useEvenOdd)` resolves the same parse result against the border-box (percentages, `closest-side`/`farthest-side` distances, circle-radius `%` against `√(w²+h²)/√2`) and builds an `RGraphicsPath`. The paint hook is in `CssBox.Paint`: the clip is `PushClip`/`PopClip`-bracketed around the whole element paint (`PaintImp`), *inside* the transform push so clip and content transform together (CSS Masking 1 — the clip is in the element's local coordinate system). Verified end-to-end by rasterizing a polygon/inset/circle/ellipse showcase in **both** PDFium and MuPDF. See `BasicShapeGrammarTests` (grammar + Layer-A accept/reject), `ClipPathResolverIntegrationTests` (resolver geometry), `ClipPathPaintIntegrationTests` (recording-graphics push/pop bracket + resolved coordinates, and invalid-value drop). **Accepted gaps** ([issue #217](https://github.com/jhaygood86/PeachPDF/issues/217)): `inset()`'s `round <radius>` corners aren't rendered (parsed + captured, but the clip is rectangular); a non-default `<geometry-box>` reference box (margin/padding/content-box) isn't honored (always border-box); `path()`/`url()` clip sources are unsupported. (`calc()` inside a **`polygon()` coordinate** IS now handled — `BasicShapeGrammar.IsLengthPercentage` accepts a calc-family `FunctionToken` and `CssClipPathResolver`'s per-coordinate `ParseLength` evaluates it — done as part of the Charts.css area/line work; a calc() inside `inset()`/`circle()`/`ellipse()` still isn't.)
