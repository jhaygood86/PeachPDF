# `box-shadow` painting (outset/inset, offset/blur/spread, multiple layers, `border-radius`), with a vector-blur approximation

_Landed 2026-07-22._

**`box-shadow` painting (outset/inset, offset/blur/spread, multiple layers, `border-radius`), with a vector-blur approximation.** box-shadow was registered in Layer A but unwired/unpainted. Now: a shared `BoxShadowGrammar` (`src/PeachPDF/CSS/BoxShadowGrammar.cs`, `TryParse(tokens) → List<ShadowLayer>`, raw component strings — the `BasicShapeGrammar`/`AspectRatioGrammar` precedent) validates the value in Layer A (`BoxShadowValueConverter`, replacing the old `MultipleShadowConverter` so there is ONE grammar) and is re-parsed in Layer B at paint time. `CssBox.PaintBoxShadows` is hooked into `PaintImpCore`'s fragment loop — outset shadows just *before* `PaintBackground` (behind the box), inset just *after* (clipped to the padding box) — painting layers in reverse so the first-listed is on top. **Blur** (PDF has no native blur filter) is approximated with **concentric overlapping fills**: `clamp(round(2·blur),6,40)` rounded-rect (outset) or even-odd ring (inset) paths whose source-over accumulation ramps alpha from the edge inward, with per-layer alpha `a_k = 1 − (1−T_k)/(1−T_{k−1})` (the compensation is essential — a constant per-layer alpha collapses an *opaque* shadow color to a hard edge). Overlapping (not abutting) layers avoid the double-blend seam lines the initial edge-band/corner-wedge approach produced (caught by rasterization). `border-radius` is honored (corner radii grown by spread). **Two real bugs found via rasterization:** (1) digit-leading hex colors (`#08f`/`#000`) tokenize as `Delim("#") + number` in Layer B's non-value-mode tokenizer (`CssValueParser.GetCssTokens`) rather than a color token — fixed with `NormalizeHexColorTokens` in the grammar + accepting bare `Hash` tokens; (2) `PushClipExclude` is a no-op in the PDF backend, so inset uses even-odd ring paths rather than a clip-subtract. Verified in **both** PDFium and MuPDF (offset/blur/spread/inset/rounded/stacked/neumorphism). See `BoxShadowGrammarTests` (grammar + Layer-A accept/reject) and `BoxShadowPaintIntegrationTests` (outset-before-/inset-after-background ordering, solid-vs-blur, `none`). **Accepted gaps** ([issue #221](https://github.com/jhaygood86/PeachPDF/issues/221)): the blur isn't a true Gaussian; an outset shadow doesn't knock out the element's own area (shows through a transparent element); a rounded `inset` shadow's inner-hole corners are square.
