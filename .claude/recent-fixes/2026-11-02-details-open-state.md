# `details` open state

A UA rule hides everything but the summary in a `<details>` without `open` (`details:not([open]) > :not(summary) { display: none }`), and `HtmlDocument.SetOpenAsync` lets a host toggle it.

- **Attribute changes now reach the cascade.** Form changes used to be re-applied *after* the parse (`ReapplyFormChanges`), which was too late for any selector that reads them; `details` needs the `open` attribute present when the UA rule is matched and when layout decides what to lay out. The container now carries the changes (`AttributeOverrides`, the same dictionary the form API records into) and `DomParser.GenerateCssTree` applies them to the tags right after numbering the elements, before anything reads them. This is the groundwork the restyle in the accepted gap for `:checked` needs (issue #2113): what is left there is only a way to ask for the restyle after a synchronous form change.
- **A sibling combinator in the default sheet costs the whole document.** The first version also hid the second summary with `details:not([open]) > summary ~ summary`, and `SiblingStyleSharingTests.RowsAndCellsWithNoPositionalRule_ShareTheirStyles` failed: one unstable rule in the UA sheet turns off the cascade's sibling style sharing everywhere, not only for summaries. A second summary is invalid HTML, so it is left shown and the limit is written in the sheet's comment and the docs. (The `:not(summary:first-of-type)` form I tried first did not hide the second summary either.)
- **`RestyleAsync` is the old tail of `ApplyStateAsync`,** moved so both a pointer/focus change and `SetOpenAsync` use the one geometry comparison and dirty-region logic.
