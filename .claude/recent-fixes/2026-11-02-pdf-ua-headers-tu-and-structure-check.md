# PDF/UA: header ids, field names and a structure check

- **`/ID` and `Headers`.** `StructureDetails.ElementId` (a `th`'s tree id) and `HeaderIds` (from a cell's `headers` attribute, resolved through the tree's `ColumnHeaders`/`RowHeaders`) become `PdfStructureDetails.Id` and a `Table` attribute `Headers`; the recorder indexes the ids in `/IDTree` at `Finish`. Only a cell that says `headers` gets the attribute: scope and layout already head the rest, and a list on every cell would bloat large tables.
- **`/TU` is the accessible name**, not just the placeholder: `PageFormField.AccessibleName` is the tree's name for the control (label, `aria-label`, `title`); it wins over the placeholder, which stays the fallback. The collector takes the tree lazily so a page with no fields never builds it for them.
- **`CheckStructure`/`AccessibilityWarnings`** report heading level skips, tables with no `TH` and figures with no description. They report and never throw: skipping a level is legitimate HTML, and a validator that fails a render would be turned off.
- **Found by veraPDF, not by reading:** a label and a field between two blocks, or a body of only inline content, left `Span` directly in `Document`, which UA-2 rejects. The fix wraps them in a `P` only when a bare inline element is among them - a first version wrapped every inline run and moved `Figure`, `Formula` and `Link` under new paragraphs, breaking a dozen structure-tree tests that were right.
