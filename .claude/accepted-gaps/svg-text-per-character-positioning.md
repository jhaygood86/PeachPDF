# SVG text §10.4 per-character positioning edge cases

**SVG text §10.4 per-character positioning edge cases** (out of scope from the #188 text-model work): a nested run's `rotate` is resolved as override (`AssignPositionLists` uses `gi.Rotate ??=`) rather than *added* to the ancestor's value as SVG 1.1 §10.4 specifies (SVG 2 effectively reduces this to per-character resolution, and the common single-list + last-value-persist case is correct); and when a `<text>` mixes straight text with a `<textPath>`, the ancestor's `x`/`y`/`dx`/`dy`/`rotate` list is indexed by position among the *straight* characters only (`SvgRenderer.FlattenRun` routes textPath glyphs into a separate list), so a multi-value list mis-aligns for characters after the textPath — both rare combinations. Filed as [issue #296](https://github.com/jhaygood86/PeachPDF/issues/296).
