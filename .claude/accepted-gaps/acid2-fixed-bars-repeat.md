# Acid2's fixed bars repeat onto a page `.intro` does not cover

Collapsing Acid2 down to 2 pages exposed, rather than fixed, a second Appendix-E/paged-media mismatch: `.picture p`/`.picture p + p` (two `position: fixed` bars forming the face's "scalp") correctly repeat identically on every generated page (standard CSS Paged Media running-element behavior, confirmed end-to-end by `FixedPositionPaginationIntegrationTests`) — but `.intro` (`z-index: 2`, meant by the fixture's own CSS comment to cover them) is normal-flow and only ever lands on the page it's naturally laid out on. Since `.intro` and `#top`/`.picture`'s real content now land on two *different* kept pages, the fixed bars still bleed onto the second, uncovered page — a smaller version of the same "Acid2 assumes one non-scrolling viewport" mismatch already documented elsewhere in this list, and inherent to a non-scrolling paginated renderer (there's no single viewport for `.intro` to sit in front of both landing spots at once). Not fixed, and not attempted: a geometry-based heuristic (suppress a fixed box's repeat on any page lacking a same-context, higher-z-index box that happens to overlap it elsewhere) was considered and rejected as a coincidence-prone rule that could silently vanish legitimate fixed print headers/footers elsewhere in a real document. See `Acid2RegressionTests.FixedBars_RepeatOntoPage2_KnownResidualNotCoveredByIntro`, which documents this as a known boundary rather than a silent gap.
