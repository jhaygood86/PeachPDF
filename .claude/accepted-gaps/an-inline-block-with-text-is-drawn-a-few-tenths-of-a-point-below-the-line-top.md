# An inline-block with `vertical-align: top` that holds text is drawn a few tenths of a point below the line top

An `inline-block` with a fixed height and `vertical-align: top` whose content is inline text sits a little lower than the top of its line (0.324pt for 12pt Liberation Sans, which has Arial's metrics; the amount follows the font, so a test that reads such a box's position back differs by that much between platforms with different default fonts). The same box empty, or with its text in a block child, is at the line top, and CSS 2.1 section 10.8.1 puts it there whatever the strut's font is. No floats are involved, so a float placed against that line is placed against the correct line bottom and the box alone is off by the difference (tracking issue #2233). Tests that read such a box back leave a point of leeway (`FloatPlacementPdfTests.RightFloatThatDoesNotFitBesideAnInlineBlock_GoesBelowTheLine`), and set their text in the bundled font so the difference is the same on every platform.
