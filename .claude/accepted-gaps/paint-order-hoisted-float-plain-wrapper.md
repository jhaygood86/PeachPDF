# Paint order for a float hoisted past a plain, non-positioned wrapper

Paint order (`FragmentPainter.PaintBoxContent`'s stacking loop) correctly orders block → float → inline-level content per CSS2.1 Appendix E *within one stacking context's own direct participants* (including a plain block wrapper whose entire content is inline, e.g. a `<div>` around nothing but a resolved inline `<object>`/image — see `StackingOrder.ActsAsInline`). A float hoisted (`DomUtils.NeedsStackingHoist`/`StackingOrder.Flatten`) past its immediate container now preserves correct local order against its true, non-hoisted block/inline siblings whenever that immediate container is itself positioned (`position: absolute`/`relative`/`fixed`/`sticky`, regardless of whether it has an explicit `z-index` — see `StackingOrder.IsLocalOrderingScope`/`SearchForHoistableDescendants`'s `claimFloatsHere` parameter) — this is what Acid2's own `.eyes`/`#eyes-a`/`#eyes-b`/`#eyes-c` needed, since `.eyes` is `position: absolute` with no `z-index`. A genuine stacking-context descendant (real `z-index`, `opacity<1`, or a transform) nested inside such a box still correctly keeps escaping all the way to the nearest true stacking context, not trapped locally — z-index competition only has meaning there. The one remaining, narrower gap: a float whose immediate container is a *plain, non-positioned* wrapper (no `position` at all) still doesn't preserve local order against non-hoisted siblings — it hoists to the nearest true stacking-context ancestor instead, since a plain wrapper has no Appendix-E-recognized atomic-ordering role to claim it locally. Fixing that remaining case would need the hoisting mechanism to track and re-interleave against a plain wrapper's own non-hoisted siblings too, which touches the same float/clip-ancestor hoisting logic a prior round already hardened against a double-paint regression (`StackingContextPaintRegressionTests.cs`) — not attempted here. See `Acid2FeatureVerificationTests.NormalFlowBlockFloatAndInline_PaintInAppendixEOrder`'s doc comment for the historical context, and `Acid2RegressionTests.Eyes_FloatChild_OrdersLocally_NotHoistedPastNonStackingContextAncestor` for the fixed `.eyes`-shaped case.
