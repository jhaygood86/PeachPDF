# Viewport and container units do not size a replaced element

A replaced element (`<img>`, inline `<svg>`, `<object>`) whose `width`, `height`, `min-*` or `max-*` is written in `vw`, `vh`, `vmin`, `vmax`, `ch` or a container unit (`cqw`...) is sized as if the property were absent. `CssLayoutEngine.TryResolveLength` reads the value through the legacy `CssLength`, which only knows `%`, `em`, `ex`, `px`, `mm`, `cm`, `in`, `pt`, `pc` and `rem`; any other unit sets `HasError`, so the value is dropped before the shared unit conversion (`Length.ToPixels`, which does handle them) is reached. Seen with `svg { width: 10vw; height: 10vw }`: the element keeps its natural size (an svg with only a `viewBox` takes the available width). A test row for it passed for a long time only because the svg's `viewBox` extent happened to be within the test's tolerance of the expected 59.5pt. Not tracked by an issue yet.
