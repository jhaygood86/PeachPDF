# A float that fits no band under a repeated `thead`, in a table cell, makes 16 empty pages

`<table><thead>...</thead><tbody><tr><td><table><tbody><tr><td><div style="float:right;height:90pt">` on a 160pt page with 20pt margins stalls: no pass places the float, because the repeated header leaves it a hair too little room on every page. The driver's stall guard (16 passes that resume at the same place) lays the remainder out in one piece, so the document finishes, but each of the 16 stalled passes was already emitted as a page that holds only the header: 18 pages where Chrome has 2 (it places the float at the top of the second page and lets it overflow, css-break-3 section 4.4; tracking issue #2297). With these styles a float of 80pt or less fits, 85pt goes to a second page, 86 to about 95pt stalls, and 100pt or more renders normally (the float then fits no band either way, and a block that cannot fit moves on); without the `thead` it is one page. #2293 was the same document with `rowspan` cells, where the guard never fired and the render did not finish. The stall guard that makes it end covers block, inline and table tokens only: the same document inside a flex or grid container never finishes (#2298), and inside an absolutely positioned box ends only at that loop's own pass cap, as 10,001 pages (#2299).
