# A pseudo-element with `display: contents` and `position: absolute` is placed after the text

`#p::before { content: "B"; display: contents; position: absolute }` puts the "B" after the text of `#p`; a browser generates no box for it and the "B" stays inline in front of the text (x=10.7 for the text after it, here 0; plain `display: contents` is right, tracking issue #2248). The cascade blockifies an absolutely positioned box (`DomParser.BlockifyPositionedBox`, step 10) before `ResolveDisplayContents` (step 12) computes `contents` to `inline`, and the box then goes through `CorrectAbsolutelyPositionedInlineElements`, which appends its wrapper to the end of the parent's children instead of in the box's place (read from the code and a review's trace, not stepped through).
