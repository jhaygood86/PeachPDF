# `<center>` and `align` on `td`/`div`/`p` are a plain `text-align`, not `-webkit-center`

A browser maps these to the legacy `-webkit-center`/`-webkit-left`/`-webkit-right` alignment. Here they are an ordinary `text-align`, with these browser behaviors recovered: a table does not inherit it (`DomParser.StopTableInheritingLegacyTextAlign` finds the nearest ancestor the value comes from and resets the table's `text-align` to `start` when that is a `<center>` or an element with an `align` attribute; a `text-align` from a style rule is still inherited), and a block-level table that is a direct child of `<center>` or of an element with `align=center` is centered as a box (`DomParser.CenterTableInLegacyCenteredParent`).

Not covered: `-webkit-center` also centers other block-level children that have a definite width (a `div` with a `width`), not only tables, and the legacy values are not parsed from author CSS. A distinct legacy keyword in the cascade would cover both (tracking issue #2186).
