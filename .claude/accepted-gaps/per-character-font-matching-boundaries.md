# Per-character font matching: remaining coverage boundaries

Per-character font matching (`@font-face` `unicode-range` + glyph-coverage fallback across the `font-family` stack, plus a last-resort system-fallback scan of every OTHER registered font) is implemented (issues #158, #172). Astral/supplementary-plane codepoints (above U+FFFF, i.e. emoji) are supported via the cmap **format-12** subtable — glyph lookup (`OpenTypeDescriptor.CharCodeToGlyphIndexCore` → `CMap12.MapCodeToGlyph`) and coverage (`CMapCoverage.Extract(CMapTable)`) both consult it. Remaining boundaries: (1) **color** emoji via **`COLR`/`CPAL`** (v0 layers + v1 paint graphs) is now supported — color glyphs are drawn as vector content (see the Recent-fixes entry), closing the `COLR` half of #175; the remaining unsupported color formats are bitmap `CBDT`/`CBLC` + `sbix`, SVG-in-OpenType, `COLR` over CFF outlines, and COLRv1 variable paints (tracked follow-ups in the Recent-fixes entry); (2) a font with *only* a format-12 subtable (no format-4) still isn't usable (`CMapTable.Read` requires format-4 for the WinAnsi `Widths` loop). cmap **format-14** variation sequences are no longer a boundary: `CMap14` is read, a non-default UVS record swaps its dedicated glyph in during shaping (`GsubShaper.MapToGlyphs`, the selector itself still flagged hidden-ignorable and dropped last), and for U+FE0E/U+FE0F a listed sequence counts as the font supporting that presentation - see the `font-variant-emoji` recent-fix. Emoji-sequence composition does **not** depend on it: it comes from `GSUB` `ccmp`, not from the cmap. Overlap tie-break for two ranged faces covering the same codepoint is last-declared-wins (CSS cascade order); real subsets are disjoint so this is an edge case. The last-resort system-fallback step orders multiple covering candidates by which one most overlaps the codepoint's Unicode script (falling back to alphabetical family-name order for a script-less character or a tie) rather than the script/language-aware curated tables a browser's own font-matcher uses — CSS Fonts 4 leaves the system-fallback font itself entirely user-agent-defined, so this is a deliberate simplification, not a spec deviation. See [Per-character font matching](docs/html-css-support.md#per-character-font-matching-and-coverage-fallback), `UnicodeRangeLayoutIntegrationTests`, `SystemFallbackFontLayoutIntegrationTests`, `FontResolverCodepointTests`, `Format12CmapAstralTests`, `CMap14VariationSequenceTests`.
