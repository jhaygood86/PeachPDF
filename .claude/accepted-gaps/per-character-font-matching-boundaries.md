# Per-character font matching: remaining coverage boundaries

Per-character font matching (`@font-face` `unicode-range` + glyph-coverage fallback across the `font-family` stack, plus a last-resort system-fallback scan of every OTHER registered font) is implemented (issues #158, #172). Astral/supplementary-plane codepoints (above U+FFFF, i.e. emoji) are supported via the cmap **format-12** subtable — glyph lookup (`OpenTypeDescriptor.CharCodeToGlyphIndexCore` → `CMap12.MapCodeToGlyph`) and coverage (`CMapCoverage.Extract(CMapTable)`) both consult it. A font whose only Unicode subtable is format 12 (no format-4) is usable: `CMapTable.cmap4` is then null and the format-12 groups answer for the BMP too (`CMapTable.Read` only refuses a font with neither).

Colour glyphs are supported in every format: `COLR`/`CPAL` v0 layers and v1 paint graphs (over `glyf` or CFF outlines), `CBDT`/`CBLC` + `sbix` bitmaps and SVG-in-OpenType all render. What is left is approximate: the Porter-Duff `PaintComposite` modes with no vector equivalent (`SRC_OUT`, `DEST_OUT`, `XOR`, `PLUS`) degrade to source-over, and a radial gradient between circles with different centers ignores its inner radius and does not repeat/reflect (issue #287).

cmap **format-14** variation sequences are read: `CMap14`, a non-default UVS record swaps its dedicated glyph in during shaping (`GsubShaper.MapToGlyphs`, the selector itself still flagged hidden-ignorable and dropped last), and for U+FE0E/U+FE0F a listed sequence counts as the font supporting that presentation - see the `font-variant-emoji` recent-fix. Emoji-sequence composition does **not** depend on it: it comes from `GSUB` `ccmp`, not from the cmap.

Overlap tie-break for two ranged faces covering the same codepoint is last-declared-wins (CSS cascade order); real subsets are disjoint so this is an edge case. The last-resort system-fallback step orders multiple covering candidates by which one most overlaps the codepoint's Unicode script (falling back to alphabetical family-name order for a script-less character or a tie) rather than the script/language-aware curated tables a browser's own font-matcher uses — CSS Fonts 4 leaves the system-fallback font itself entirely user-agent-defined, so this is a deliberate simplification, not a spec deviation. See [Per-character font matching](docs/html-css-support.md#per-character-font-matching-and-coverage-fallback), `UnicodeRangeLayoutIntegrationTests`, `SystemFallbackFontLayoutIntegrationTests`, `FontResolverCodepointTests`, `Format12CmapAstralTests`, `CMap14VariationSequenceTests`, `Format12OnlyFontTests`.
