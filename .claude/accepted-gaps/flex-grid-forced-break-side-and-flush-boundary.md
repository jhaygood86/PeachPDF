# A forced break on a flex or grid item drops its side, and is taken again at a boundary it is already at

Two deviations in the one place a flex line or grid row is moved to the next fragmentainer, `LineRelocation.DeltaFor`. Both predate `break-after` being read at all (issue #441 only widened the set of break points the question is asked at), and both are muted enough in ordinary documents to have gone unnoticed.

**The side is dropped.** `BreakValues.IsForcedPageBreak` accepts `left`/`right`/`recto`/`verso`, and the destination is then always `PageTopOf(slot + 1)` — there is no parity walk (`BreakValues.SlotIsOn`) and no blank-slot reservation, both of which the block-flow path grew in issue #302. So a directional value forces the break but the line opens the next page whichever side that is. It is stated as a limitation under "Directional page breaks" and "Breaks in flex and grid containers" in `docs/html-css-support.md`, and filed as [issue #450](https://github.com/jhaygood86/PeachPDF/issues/450). Note that closing it needs the winning *value* rather than a boolean: `LineRelocation.ForcedBreakBetween` answers whether a forced break falls between two lines, not which value wins, which is `BreakPropagation.Combine`'s rule.

**A line already at a fragmentainer top is pushed a further page.** `SlotStartingAt(top)` resolves a flush top edge to the *later* slot, so `PageTopOf(slot + 1) - top` is a whole band even where the break has already happened. Measured on a 200pt page (160pt band, slot 1 beginning at y = 180) with one flex item carrying `break-before: page`: a filler of 159pt lands it at y = 180 (correct), 160pt at **y = 340** — one slot skipped — and 161pt at y = 340 (correct, its top was already past slot 1's). §4.4 forbids the empty fragmentainer this creates; nothing blank is printed, because the skipped slot has no content and CSS Paged Media 3 §3.2 drops it, but the content is attributed to the wrong slot for `@page :left`/`:right` and for the parity arithmetic #450 needs. Filed as [issue #451](https://github.com/jhaygood86/PeachPDF/issues/451).
