# An inline svg directly under a `display: contents` element reads the grandparent's font size

An inline `<svg>` starts from the computed font size of its HTML parent (`CssBoxSvgSourceNode.InheritedFontSizePx`, read from `CssBox.ParentBox`). A `display: contents` element generates no box, so for an svg that is its direct child `ParentBox` is the element's own parent, and the font size the element sets is skipped: `<div style="font-size:30px"><div style="font-size:10px; display:contents"><svg>` gives 30px where a browser gives 10px (`main` before the inheritance change gave the constant 11, so this case moved from wrong to differently wrong). A `<span>` inside the same element is right, because ordinary text takes its style through the cascade, not through the box tree.

The fix is to read the size from the element tree (the svg's DOM parent) instead of the box parent, which needs the engine to keep the style of an element that has no box reachable from the svg's box. Not done: the case needs a `display: contents` wrapper directly around an inline svg that also sets a font size of its own. Tracked in #2165; the units row of `docs/supported-svg-features.md` states the behaviour.
