# The table engine's whole-table pre-checks decide from an estimate

The two whole-table pre-checks in `CssLayoutEngineTable.LayoutCells` still decide from `EstimateRowHeight`, a one-line-of-text heuristic blind to tall block content inside a cell — but a misjudged estimate is no longer a gap: `CssBox.PerformLayoutEpilogue`'s §4.3 mover asks the real question once the table's own height is known (`PaginatedItsOwnContentWithoutBreaking` — a table that recorded no break between two of its rows did not fragment), and it asks it of every table rather than only of the headerless ones. That closed [issue #151](https://github.com/jhaygood86/PeachPDF/issues/151) (a table with only a repeating `<tfoot>`, which fell between both pre-checks) and [issue #152](https://github.com/jhaygood86/PeachPDF/issues/152) (a repeating-header table with no real-height fallback), whose old blocker — repositioning the header's already-created `CssProxyBox` — went away with #353: the table is laid out again at its destination, so the proxies are rebuilt rather than moved.
