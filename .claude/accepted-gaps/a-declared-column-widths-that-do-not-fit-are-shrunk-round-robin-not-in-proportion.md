# Declared column widths that do not fit are shrunk round-robin, not in proportion

When columns that all declared a width need more than the table can hold, `ShrinkColumnsToFitAvailableWidth` takes a point at a time from each column in turn, where a browser distributes the excess in proportion (and, for percentages over 100%, keeps the earlier columns' shares). A 400px table of `10%` / `30%` / `60%` columns with long text is 89.1 / 60.0 / 150.0pt here against Chrome's 92.8 / 70.0 / 137.2, and `width:60%` beside `width:80%` is 120 / 180 against 180 / 120. Columns that did not declare a width give their share back first (`TakeExcessFromUndeclaredColumns`), so this is only reached when every column declared one. Same on the release before the default cell padding, where such a table also overflowed. Tracking issue #2397.
