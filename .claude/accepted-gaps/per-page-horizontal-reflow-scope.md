# Per-page horizontal reflow is scoped to auto-width main-column blocks

**Per-page horizontal reflow (issue #143) is scoped to auto-width main-column blocks.** The width seam (`CssLayoutEngine.GetBoxWidth` → `HtmlContainerInt.PageContentRightOf`, gated by `IsMainColumnContainer` = root/`<html>`/`<body>`) reflows only auto-width block content whose containing block is the main column. Each remaining case is a genuine CSS Paged Media 3 §5 ("the edges of the page area act as a containing block for the layout that occurs between page breaks") deviation, tracked as its own issue: flex ([#196](https://github.com/jhaygood86/PeachPDF/issues/196)), tables ([#197](https://github.com/jhaygood86/PeachPDF/issues/197)), multicol ([#198](https://github.com/jhaygood86/PeachPDF/issues/198)) — the horizontal analogue of the #166 engine-independence family; percentage/fixed-`width` blocks ([#199](https://github.com/jhaygood86/PeachPDF/issues/199)); content nested below the main column, incl. a descendant that begins on a different page than its multi-page auto-width ancestor ([#200](https://github.com/jhaygood86/PeachPDF/issues/200)); the initial containing block's own WIDTH resolving against the base page area rather than the first page's `:first`-overridden area — narrowed from the ICB generally: the height dimension now correctly reads the first page's own resolved band (`PageGeometryTable.GetPage(0).BandHeight`), so only the width side of #201 remains open ([#201](https://github.com/jhaygood86/PeachPDF/issues/201)); and named-page (`page: <name>`) L/R overrides, whose width→height→page-name feedback the bounded reflow loop doesn't drive to convergence ([#202](https://github.com/jhaygood86/PeachPDF/issues/202)) — this now also covers a named/pseudo page's own `size` override: the page gets a genuinely independent physical `/MediaBox` (`PdfGenerator.AddPdfPages` reads each page's own resolved `PageBandGeometry.SheetWidthPt`/`SheetHeightPt`) and vertical pagination adapts to its own band height, but content still wraps at the document's base measure rather than that page's own (possibly different) width, same #202 gap, same tracked issue. NOT a gap (spec-correct, don't file): a box spanning a page boundary keeps its start-page measure across fragments — CSS Fragmentation 3 shares one inline size across a box's fragments.
